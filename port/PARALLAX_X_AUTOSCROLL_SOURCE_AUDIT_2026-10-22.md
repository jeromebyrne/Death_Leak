# ParallaxLayer horizontal autoscroll — source audit (2026-10-22)

**Verdict / visual priority:** Linux omits a real Windows `ParallaxLayer` X-autoscroll feature, but **no shipped active level enables it**. All 97 `ParallaxLayer` elements in `Game/XmlFiles/levels/*.xml` have `<autoscrollx value="false" />` and `<autoscrollxspeed value="0.000000" />`. Thus this is a dormant feature-parity gap, **not a current forest or waterfall visual-parity blocker**. Do not retune forest camera-X parallax or waterfall Y-flow to compensate. With the physical-GPU/build lane owned by the fog-mip worker, no implementation or capture is justified by present authored content; prioritize visible, evidenced gaps first. This finding is from source/XML inspection, not a Windows capture.

## Exact Windows behavior and missing Linux seam

- `Game/src/GameObjects/ParallaxLayer.cpp:4-20,26-35,37-111,162-175`: XML loads `autoscrollx` and `autoscrollxspeed`; `Draw` chooses X autoscroll before camera-X parallax when enabled, even when camera multiplier is positive or the camera is stationary. Per draw it computes `percentDelta = Timing::GetLastUpdateDelta() / GetTargetDelta()` and `xShift = prior vertex[0].TexCoord.x + (XSpeed * .001f) * percentDelta` (same rule for bump vertices). It writes U `(xShift+1, xShift, xShift, xShift+1)` and marks the vertex buffer dirty. Because previous vertex 0 contains `previous xShift+1`, the raw U increases by an extra integer each draw, irrelevant under wrap; the fractional phase increases by `XSpeed*.001*percentDelta`. Initial vertex-0 U is 0 (`Game/src/GameObjects/Sprite.cpp:19,219-228`). The X branch runs when either `cameraParallaxMultiplierX>0` **or** `autoScrollX`, so a zero-multiplier authored layer still animates. It overwrites the one-span U layout regardless of `repeatwidth` (the calculated repeats are immediately forced to 1 at `ParallaxLayer.cpp:45-47`). Neither follow-camera position nor X multiplier contributes while the flag is on.
- `Game/src/GameObjects/ParallaxLayer.cpp:223-231` scales **positive** X speed by `x` during level scaling. `Game/src/GameObjects/GameObjectManager.cpp:452-463` scales all objects by backbuffer width/1920. For the existing 1280-wide Linux target, source-equivalent positive-speed phase increment at steady 60 Hz is `xmlSpeed*(1280/1920)*.001` per frame. Preserve source's positive-only scaling condition if negative-speed XML is ever supported; do not silently apply 2/3 to negative speed. `Game/src/program.cpp:115-117,149-175` sets target delta 1/60, caps `delta`, renders, then records last-update delta, so source Draw sees the **preceding** completed update's delta (initially zero), including time modifier. The port can advance phase once in `UpdateVisuals` with current `dt` as its Y-path does, but that is one-frame ahead at startup/delta changes; document or reproduce this cadence explicitly if exact timing is required. Do not mutate phase in repeated diagnostic `Draw` calls.
- Linux `port/game/LevelScene.cpp:389-401` loads Y flag/speed but never reads X flag/speed. `port/game/LevelScene.h:37-40` stores only Y phase. `port/game/LevelScene.cpp:825-835` advances only Y phase; `:1245-1256` always derives X UV from camera-X multiplier. The SDL renderer already has a one-span, wrapped-UV route (`port/linux/SDLRenderer.cpp:246-261`, with fractional/legacy dispatch subject to renderer eligibility). Its presence does not fix the missing load/phase/precedence. Existing camera-X parity is independently guarded by `port/tests/parallax_speed_test.cpp:25-48`.

## Minimal source-equivalent fix **if an enabled layer is added**

1. In `SceneSprite`, add per-instance `autoScrollX`, `autoScrollXSpeed`, `autoScrollXPhase` (default false/zero); read the two existing XML fields next to Y in `LevelScene::Load`. Keep each layer's authored position, dimensions, tint, depth and camera-follow flags unchanged.
2. Advance enabled X phase exactly once per rendered visual tick, including while game objects are paused (matching the current Y clock in `UpdateVisuals`), by `speedScaled*.001f*(dt/(1/60.f))` for the port's documented current-delta approximation; `speedScaled = xmlSpeed*(1280/1920)` **only for positive speed**, else `xmlSpeed`. Reduce modulo 1 after accumulation. For stricter legacy parity, feed the prior completed, capped/time-modified update delta and retain initial zero instead; this requires a shared visual-clock choice for Y as well. Keep X and Y phases independent.
3. In parallax `Draw` handoff, choose auto-X **instead of** camera-X whenever flag is true (not additively), including `speed=0`; otherwise retain today's camera-X expression. The Windows U orientation is left=`phase+1`, right=`phase` before world horizontal flip. For an unflipped SDL source-copy, the equivalent `uvShiftX` is **negative** phase (opposite the existing positive SDL camera shift); for a horizontally flipped copy, the screen-left sample is `phase`, so use **positive** phase. Validate both with an asymmetric labeled texture through `UVWrap` and the float path rather than assuming camera-parallax's existing sign branch applies. If X auto is true, ensure the draw retains the one-span UV path even when camera-X multiplier is zero; a zero phase needs ordinary full-quad sampling and a nonzero phase needs wrapped sampling. Do not allow ordinary repeated tiles to preempt autoscroll.
