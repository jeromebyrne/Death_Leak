## Verdict

**A narrow source-proven cadence divergence exists at level entry: the Linux scene-local prior-render delta starts at zero on a newly loaded bottom scene, whereas original Windows `Timing::LastUpdateDelta` is process-owned and already contains the preceding rendered update's modified delta.** Thus, if ID25 is eligible for the first bottom draw following an ordinary 1/60-s prior render, original `ParallaxLayer::Draw` advances V by `9 × (720/1080) × .001 = .006` on that draw; the current Linux path advances by zero. This is a conditional first-draw **command-phase** divergence, not a demonstrated original-vs-Linux pixel mismatch at saved present 826. The saved `.384000212` is consistent with 64 full `.006` advances in the Linux bottom scene, but does **not** prove an original Windows phase, draw count, time-modifier history, or even the exact first eligible bottom draw. No speculative correction is justified from the packet alone.

## Evidence / recurrence

- Authored bottom ID25 has `autoscrolly=true`, speed 9 and zero camera-Y parallax (`Game/XmlFiles/levels/waterfall_bottom.xml:453-474`). Windows scales positive auto-scroll-Y speed by `y` in `ParallaxLayer::Scale` (`Game/src/GameObjects/ParallaxLayer.cpp:223-231`); `GameObjectManager::Load` scales objects with backbuffer height / 1080 (`Game/src/GameObjects/GameObjectManager.cpp:451-463`). At 1280×720, effective speed is 6.
- Original `ParallaxLayer::Draw` adds `(scaledSpeed × .001) × GetLastUpdateDelta()/GetTargetDelta()` to stored vertex V **when drawn**, then calls `Sprite::Draw` (`Game/src/GameObjects/ParallaxLayer.cpp:114-160`). Its `Update` does not advance V (`:26-35`). The main loop targets 1/60, caps current delta, calls `Update`, then `Render`, and only **after Render** writes `SetLastUpdateDelta(delta × TimeModifier)` (`Game/src/program.cpp:115-117,149-177`). `Timing` initializes that slot once to zero; it is not reset by loading a level (`Game/src/Core/Timing.cpp:6-16`, `Timing.h:18-19`). The mathematical command phase is `(Σ prior process modified-delta / target-delta × .006) mod 1` over eligible draws since ID25 was constructed. D3D may retain unbounded UV coordinates; a wrapping sampler makes the fractional phase relevant.
- Linux initializes each `SceneSprite::autoScrollYPhase=0` and each `LevelScene::previousRenderedModifiedDelta_=0` (`port/game/LevelScene.h:44,247-248`). `Load` resets `pendingModifiedDelta_` but does not import the process prior slot (`port/game/LevelScene.cpp:139-141`); the actual top-to-bottom trigger route constructs a fresh `LevelScene` and move-assigns it (`port/linux/main.cpp:1450-1474`). `UpdateVisuals` records current `dt` in `pendingModifiedDelta_` (`LevelScene.cpp:842-849`), then `Draw` adds `9 × (720/1080) × .001 × (previousRenderedModifiedDelta_ × 60)` to phase, wraps it and submits `draw.uvShiftY` **before culling** (`:1444-1456`). Only at the end of this scene draw does it commit pending to previous (`:1475-1479`). Thus the first fresh-scene draw uses zero even if the process's preceding completed render had nonzero modified delta. Thereafter a one-update/one-draw steady run advances .006 per scene draw, assuming ID25 remains eligible. A draw skipped while the scene is paused or a level replacement changes that history; `updateOrdinal` alone is not a V-draw counter.
