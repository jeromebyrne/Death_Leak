# ID46 Windows sampler source gate — 2026-10-23

## Decision

**No ID46 sampler/alpha/UV patch is justified by current evidence.** The original foliage shader declares **U/V WRAP, MIN_LINEAR / MAG_POINT / MIP_LINEAR**; Linux's measured ID46 texture is **S/T CLAMP_TO_EDGE, MIN/MAG LINEAR, with only level 0 allocated**. Those are real API-state differences, but not a demonstrated pixel mismatch at the observed R:98 boundary: Linux draws local U 0–1 per tile, the shared edge falls in zero-alpha source columns, the same-state baseline/hide comparison has no contribution at x860–899, and ID46 only begins contributing about x901 where source alpha becomes nonzero. The original's actual resource mip count and same-state Windows pixels have not been observed. Do not infer an ID46 seam from a declared WRAP or MIP_LINEAR alone.

## Source contract (original Windows)

- Forest ID46 is an unrotated, horizontally flipped 10,000×252 non-native repeat-X sprite using `leaves_shadow.png`, alpha 0.5, and `effectfoliagesway`: `Game/XmlFiles/levels/forest_exploration_1.xml:765-778`.
- `Sprite::RecalculateVertices` assigns U=0 on the left and U=1 on the right before reflection, then extends right U to `m_dimensions.X / mTextureDimensions.X` for repeat-X; the flip is implemented through negative X scale, not by rewriting UVs: `Game/src/GameObjects/Sprite.cpp:19-22, 89-98, 215-234`. `Sprite::Draw` selects the foliage effect and `Draw_effectFoliageSway` binds that texture/alpha and applies the pass: `Game/src/GameObjects/Sprite.cpp:396-400, 829-862`.
- The foliage FX sampler explicitly says `MIN_LINEAR_MAG_POINT_MIP_LINEAR`, `AddressU=WRAP`, `AddressV=WRAP`; its pixel shader samples diffuse at interpolated UV and multiplies sampled alpha by sprite alpha: `Game/ShaderFiles/FoliageSway.fx:14-20, 61-67`. The engine's enabled RGB blend is `SRC_ALPHA / INV_SRC_ALPHA`: `Game/src/Core/Graphics.cpp:392-407`.
- `TextureManager::LoadTexture` passes null load-info arguments to `D3DX10CreateShaderResourceViewFromFile`: `Game/src/Core/TextureManager.cpp:50-79`. The source does **not** specify or query that loaded resource's MipLevels, so it cannot establish whether Windows ID46 sampled a populated mip chain. This sampler declaration is not evidence that a mip level was actually selected.

## Linux path and bounded comparison

- Linux decodes the PNG as RGBA, creates an SDL texture, and enables SDL alpha blending: `port/linux/SDLRenderer.cpp:153-185`. ID46 opacity is quantized by `lround(alpha*255)` to 128/255 versus FX float 0.5 (`port/game/LevelScene.cpp:552-554`, `port/linux/SDLRenderer.cpp:211-225`). This generic 0.00196 alpha-representation difference is source-backed, but no ID46-specific visible mismatch has been measured from it; it cannot explain a large seam.
- The current scene draw selects SDL linear scale mode for minified/repeated sprites, including ID46: `port/linux/SDLRenderer.cpp:213-225`. The effect branch calls `DrawFoliageSway`; each repeated tile is mapped through a local U interval and submitted with `SDL_RenderGeometry`: `port/linux/SDLRenderer.cpp:232-234, 532-592`. The right-anchored partial tile follows the whole-quad flip in `port/linux/RepeatX.h:16-40`. Thus the SDL geometry uses repeated texture *copies*, not out-of-range U requiring GL WRAP.
- The independent physical-GPU trace `port/ID46_DRAW_STATE_TRACE_2026-10-23.md` measured both R:98 tile draws as CLAMP_TO_EDGE/LINEAR, level 0 2048×252 with levels 1–3 empty. The shared deformed edge is x≈871 at y640; no baseline-versus-hide-ID46 pixels change at x860–899, while x901 is the first change at y640, about 30 screen px / 45 source texels inward. The source PNG alpha near that interior lookup is small but nonzero. This is a post-flush SDL-bound texture query, not a Windows sampler capture or exact GL instruction trace.
- At this draw each 2048×252 source tile occupies roughly 1365×168 screen px, so **minification**, not MAG_POINT, is the relevant declared filter branch. A one-level SDL texture does not emulate an *observed* D3D mip chain; whether one exists remains unproved. CLAMP versus WRAP can differ only in the filtering footprint at tile edges under local 0–1 UVs, and the observed zero-alpha guard provides no seam signal there. The nonzero transition around x900–920 is inside a tile, not the wrap boundary.

## Smallest next executable discriminator

On a Windows run of the original forest-1 ID46 draw, query the bound `ID3D10ShaderResourceView` resource through `GetResource` / `ID3D10Texture2D::GetDesc` for **MipLevels**, and save one lossless, same-camera/time **pre-sepia ID46-isolated** frame or crop spanning x860–955, y620–680 (with the original's native backbuffer coordinates mapped to the Linux comparison). Compare its alpha/onset profile to the already captured Linux baseline/hide-ID46 pair in `port/build/id46-seam-gpu-2026-10-23/`. A populated Windows chain plus a measured interior transition difference would justify a scoped mip/filter experiment; a boundary discontinuity in that matched crop would justify investigating wrap/tile filtering. Without either observation, leave source, art, and sampler state unchanged. No build, game, GPU, source, tests, or shared status were touched for this read-only gate.
