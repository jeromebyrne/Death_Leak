# Waterfall-top splash ID49: bounded implementation audit (2026-10-22)

Scope: read-only inspection of original source, XML, and current port; no implementation or visual acceptance. This follows `port/NEXT_COMPOSITION_GAP_2026-10-22.md`. The only proposed admission is waterfall-top `ParticleSpray` ID49. Forest ID47 and waterfall IDs50/51 remain separate.

## Authored contract and source behavior

- `Game/XmlFiles/levels/waterfall_top.xml:836-856`: ID49 is updateable, not always-update; origin `(320.985352,3530.298340)`, `kGroundFront`, dimensions `1000×3000`, spawn spreads X=22/Y=150, alpha 1, `effectlighttexture`, occlusion fade disabled, 100 particles, `Media\\waterfall_splash.png`, direction `(0,-1)`, spread 1, speed 14–35, lifetime 1–1.5 seconds, size 250–450, `scaleto=false` (the authored scale-to value 4 is inert), gravity 0, loop true/loop time 0, brightness 1–1, fade-in/out both .25. The dimensions are the emitter's object bounds for update/draw culling, **not** a 1000×3000 textured rectangle. Each particle has its own textured square.
- `Game/src/GameObjects/GameObjectManager.cpp:833-923` reads those values, calls `CreateDirectedSprayLoadTime`, then `Warm(true)`. The emitter factory (`Game/src/Particles/ParticleEmitterManager.cpp:575-724`) creates 100 particles at load, not over time. Lifetime is deterministic by index: `1.5 - (0.5 / 100)*i`, i=0..99, so the final value is 1.005 rather than 1.0. X/Y offsets each use `rand() % (spread*10+1)`, independently signed by another `rand()%2`; these are unscaled source-world offsets (up to 220/1500 respectively), not merely ±22/±150. Size uses integer `rand() % (int)(450-250) + 250 + 1`, then game scale; speed uses hundredth-step random from `(35-14)*100`, plus 14.01, then game scale. Brightness is exactly 1. `randSpread` consumes a `rand()` call when spread >0 but its computed expression is discarded; direction remains `(0,-1)` (`:606-614`). Do not introduce angular scatter from the XML spread.
- `ParticleSpray::Update` (`Game/src/Particles/ParticleSpray.cpp:160-342`) constructs six vertices for each non-dead particle from its **pre-advance** position/size, then moves it by `direction*speed*(delta/targetDelta)` (target delta is the runtime value; port assumes 1/60), subtracts gravity in Y, increments age, computes per-particle alpha/brightness, and resets looping particles to original spawn position/speed/size and age zero at expiry. For ID49 gravity and scaling are inactive. With fadeOut=.25 the actual source condition is `percentTimeLeft < 1-.25`, so the fade-out formula `percentTimeLeft/.75` operates over the last **75%** of life; fade-in is first 25%. The branch is `if ... else if`, and all vertex normals begin at (1,1,1). Loop time 0 means no timed stop.
- Warm-up is **deferred**: `Warm(true)` only sets a flag; after the first ordinary update has built vertices, `Warm(false)` (`:337-363`) draws one random age per particle, `rand() % (int)(MaxLiveTime*1000) / 1000`, then places it at `StartPos + direction*currentSpeed*age` and adds that age to current time. The source's warm gravity term has a plus sign, unlike Update's subtract; gravity is zero for ID49. First drawn vertices can therefore still reflect the pre-warm state; do not pre-warm at load and claim frame-exact equivalence.
- `ParticleSpray::Draw` (`:128-157`) sends 6 vertices per particle. `Game/ShaderFiles/Particle.fx:52-59` multiplies sampled RGBA by vertex Normal.y brightness and then multiplies resulting alpha by Normal.x fade. The XML alpha is 1. Source draw culls the **whole object** via camera visibility and positive object alpha (`GameObjectManager.cpp:302-330`); update culls it via the 4000×4000 camera update zone when not always-update (`:221-257,397`; rectangle logic `Game/src/Utils/Utilities.h:45-72`). The authored bounds affect those predicates, not particle count/size. The object is inserted in the depth-ordered game-object stream, so `kGroundFront` belongs after higher-depth ground/player layers and before `kFarForeground`/`kMiddleForeground` objects; XML order matters among peers.

## Current port and minimal integration seam

- `port/game/LevelScene.cpp:271-275` explicitly admits only forest `forest_exploration_1.xml` ID47; ID49 is skipped before asset load. The existing branch (`:275-328`) already reads the ID49-compatible XML fields and creates per-particle state. `port/game/ParticleSpray.h:12-99` has independent RNG, deferred warm-up, pre-advance draw coordinates, age/alpha, brightness, looping, and textured particle quads. `LevelScene::UpdateVisuals` (`:665-670`) already gates spray updates on the authored emitter rectangle against camera ±2000; `LevelScene::Draw` (`:861-879,956`) merges admitted sprays into the painter stream using depth and XML order. `Depth()` maps `kGroundFront` to 1750 (`:31-41`). These are reusable; no new waterfall-specific renderer/effect or giant rectangle should be introduced.
- Minimal change: broaden the admission predicate to `(forest_exploration_1.xml,47) OR (waterfall_top.xml,49)` and set `spray.xmlId` from the admitted object ID rather than hard-coding `"47"`; retain the existing XML order/depth assignment. Keep IDs50/51 excluded. Preserve the existing forest stream/seed and forest behavior. A separate, emitter-specific deterministic seed for ID49 is acceptable for repeatable port captures but is **not** Windows global-`rand()` equivalence. The original global RNG is also consumed by prior objects and by the discarded spread expression. Do not silently assert particle-by-particle parity to Windows without matching RNG call order, seed, game scale, frame delta, and load history.
- Existing port update bounds approximate the source's 4000×4000 zone; source uses `IsObjectInRectangle` and current parallax offsets, while the port uses direct AABB overlap. Source draw culls by emitter bounds/camera before submitting all particles; port draw has per-particle viewport culling (`ParticleSpray.h:81-97`) and no explicit emitter-level camera cull in `drawSpraysBefore`. For ID49, verify expected camera-zone transitions and offscreen draw behavior when integrating; if exact draw-call semantics matter, add source-style emitter cull without using dimensions as a quad. The port's `Update` begins with `if (!updateable || dt<=0)`, so an always-update but non-updateable spray would differ; ID49 is updateable and this does not block this slice.
- Source factory applies `Game::GetGameScale().X` to size/speed, whereas the port currently uses XML values directly (`LevelScene.cpp:318-324`); determine the actual game scale for the target run before claiming metric parity. The port's alpha/brightness tint formula corresponds to the source shader for ID49 (brightness=1), but sample filtering, blending, UV orientation, and byte rounding still require visual comparison. Existing port comments/logic use private LCG RNG and 60 ticks/s; those are controlled approximations, not source RNG/timing identities.
