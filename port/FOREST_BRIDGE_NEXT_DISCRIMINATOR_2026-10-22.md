# Forest bridge/lower-atmosphere next discriminator — 2026-10-22

## Decision

A concrete, source-backed **motion-dependent lower-foreground discrepancy** is still present at inspected HEAD `e2c5adf1de43bf694185367b4702acb32c3e32bc`: forest-1 ParallaxLayer **ID37** (`shrubbery.png`) draws at the *previous update's* camera X in Windows but at the *current* camera X in Linux. Both use the current camera X for texture UV phase. During rightward camera motion this shifts the Windows shrubbery destination left by one camera increment relative to Linux, without changing its authored alpha or vertical extent. It is testable by source-state/within-port controlled comparisons **without an original Windows frame**. This is an already identified and GPU-quantified contract difference, not a newly discovered explanation for the broad dark/soft appearance gap. Do **not** retune haze, ID37 alpha, or bridge artwork on this basis.

## Falsifiable discriminator, already partly run

At 1280×720, for two identical simulation states with camera X stepped from `Cprev` to `Cnow`, compare an ID37-only Linux draw using current X against a **render-only** previous-X destination override, leaving current-camera U, alpha, texture, depth and all other layers unchanged. Predicted destination-center shift is `-(Cnow-Cprev) × 2/3` pixels; on the next held-camera update it is zero. A CPU draw spy can assert these destination and UV values at current HEAD without a Windows executable or GPU. This is a geometry/motion discriminator, **not** a global brightness/blur test.

Importantly, `port/FOREST_FOLLOW_LAG_GPU_DISCRIMINATOR_2026-10-22.md` already ran the corresponding controlled physical-GPU experiment at earlier HEAD `814fbd3`: camera 761.040→769.036, ID37 destination 640.000→634.669 (−5.331 px) with identical U=.530635, 49,532 changed pixels in the isolated lower crop but mean RGB delta only 0.394/255; held-camera images were byte-identical. This supports a **real, low-contrast transient**. Repeating a GPU A/B merely to rediscover it is not the next priority. If exact current-HEAD contract regression evidence is needed, run only a CPU draw-state check at `e2c5adf`, plus a held-camera negative control; preserve existing source/art. The next *material* lower-atmosphere parity judgment still needs a lossless original-Windows forest bridge frame with same-frame camera XY/history, viewport, level/effect time, player/HUD/pickup state and fog phase, followed by a registered Linux frame and isolated 37/119/122 comparison.

It does **not** prove the Steam-JPEG darkness/softness difference is a port bug, quantify its appearance at current HEAD, or justify a renderer correction.
