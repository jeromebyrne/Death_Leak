# Waterfall foliage parallax-phase CPU gate (read-only source audit, 2026-10-23)

## Verdict and correction to the 06:44 gate

`VISUAL_GAP_SOURCE_GATE_0644_2026-10-23.md` identifies a real current draw-contract mismatch: waterfall-top ordinary `Sprite` IDs 64/65 get depth-parallax **destination** positions in Linux, while the foliage sine sees their original XML centre. Windows `GameObject::Update` puts the parallax-translated centre in `World`, and `FoliageSway.fx` evaluates sine after `World`. The fix is **not yet implemented** in the inspected dirty `LevelScene.cpp`: loader lines 536-539 initialize `sway.worldX/Y` from `sprite.x/y`, and draw lines 1283-1286 change time and global multiplier but never centre. This report owns no code changes.

The prior gate's proposed single initial-camera draw spy needs one correction: ID65 is culled from a 1280×720 Linux viewport at camera `(0,3000)`; ID60 is also horizontally offscreen there. A renderer-call spy cannot demand all three IDs at that camera. Test per-ID cameras below, or spy before viewport culling and distinguish that from an actual submitted draw. Its quoted centre phase shifts (3.3 and 3.53 radians) are valid *centre* deltas, not complete per-vertex sine arguments; bottom vertices include `-677/2` world Y.

## Source chain and timing

- XML `Game/XmlFiles/levels/waterfall_top.xml:1045-1060,1118-1147`: ID60 is an ordinary `kGroundFront` `Sprite`, centre `(-2063.014648,3571)`, size `756×677`, horizontal flip true; IDs 64/65 are ordinary `kFarForeground` `Sprite`s at `(-1179.014648,3660)` and `(2059.985352,3706)`, both `2048×677`, no flips or rotation. All have foliage X intensity 20 at source bottom corners, Y intensity 0, top intensities 0, time multiplier 1. Level initial camera is `(0,3000)` at XML line 3.
- `GameObject.h:317` defaults ordinary object parallax on; `ParallaxLayer.cpp:17` disables it for that separate class. `GameObject.cpp:916-924` gives `kFarForeground` multipliers `(1.1,1.05)` and `kGroundFront` `(1,1)`. `GameObject.cpp:173-205` computes `offset=(camera-position)*(multiplier-1)` during `Update`, then translates `World` by `position-offset`. `FoliageSway.fx:40-51` transforms each vertex by `World` before X sine of world Y, then Y sine of updated world X. The ID60 X flip changes source-vertex identity/geometry but not its depth multiplier.
- Important temporal bound: original parallax is sampled when each updateable/in-zone object **updates**, not intrinsically on every render. `GameObjectManager.cpp:205-257` skips paused and out-of-update-zone objects; `GameObject::Initialise` initially builds an unshifted World. Accordingly, source-equivalent centre at a draw means the camera sampled at the object's *last successful Update*. Do not claim precise same-frame source parity for paused, never-updated, or skipped objects without a native frame trace. For the ordinary active/in-zone CPU contract below, use the camera supplied to the corresponding scene draw/update. Linux `LevelScene::Draw` currently takes one camera argument and has no per-object stored last-update parallax centre.
- Linux `LevelScene.cpp:1234-1261` assigns `(layerX,layerY)=(1.10,1.05)` for depth 1500 and `(1,1)` for 1750; its destination centre is screen `(640+(x-cx)*layerX*2/3, 360+(cy-y)*layerY*2/3)`. `EffectQuadGeometry.h:25-46` derives shader-world vertices from `draw.foliageSway.worldX/Y`; `SDLRenderer.cpp:535-559` passes that value, not the destination-inferred world centre. The renderer therefore moves the quad with parallax while leaving sway phase attached to XML centre.

For active IDs 64/65, expected translated centre is `P'=(Px-(Cx-Px)*0.10, Py-(Cy-Py)*0.05)` (equivalently `1.10*Px-.10*Cx`, `1.05*Py-.05*Cy`). At camera `(0,3000)`, ID64 `P'=(-1296.916113,3693)` and ID65 `P'=(2265.983887,3741.3)`; ID60 stays `(-2063.014648,3571)`. At any source bottom corner with zero rotation/flip for 64/65, **pre-sway** world Y is `P'y-338.5`: respectively `3354.5`, `3402.8`. Current Linux uses `3321.5`, `3367.5`, a 33/35.3-world-Y or 3.3/3.53-radian input error. With a held camera and time `T`, bottom X displacement is `20*sin(.1*(P'y-338.5)+T*local*global)`. Top-corner X intensity is zero. All Y intensities are zero, so X-centre differences are not visible through these IDs' sine, although the world-centre contract should still match both axes.

## Minimal patch seam and scope

At `LevelScene::Draw`, after `worldX/worldY` and `layerX/layerY` are determined and after `draw.foliageSway = object.foliageSway`, set `draw.foliageSway.worldX = worldX-(cameraX-worldX)*(layerX-1)` and corresponding Y **only when foliage is enabled and the object is an ordinary static depth-parallax sprite** (`!player`, `!playerShadow`, `!playerAimLine`, `!parallaxLayer`; the existing depth switch provides multipliers). This is algebraically the exact centre already implied by `draw.destination`, with no destination or renderer-wide geometry change. ID60 remains unchanged via multiplier 1. Avoid changing `sprite.foliageSway` at load, modifying `FoliageSwayWorldVertex`, globally changing sine frequency, touching `ParallaxLayer`, or mixing this with unrelated camera, clock, weather, Y-cadence, and renderer work. If a later broader parity task targets source pause/out-of-zone temporal behavior, it will need separately stored last-update camera/World state rather than this bounded active-draw correction.

This source/CPU gate does **not** establish measured image impact or Windows pixel parity; that requires a matched original-Windows camera/time/weather/viewport/object-state frame and a subsequent GPU comparison by its owner. No source, tests, shared checkpoints, builds, GPU/Xorg/captures, or commits were touched here.
