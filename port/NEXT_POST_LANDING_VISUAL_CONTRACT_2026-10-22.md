## Bounded implementation and GPU discriminator contract

**No implementation on this evidence.** For the known lag, retain current art, alpha, UV, painter order and destination until a matched original-Windows transform/frame shows the legacy one-update matrix is actually presented and preserving it is desired. If so, implement only a per-follow-layer previous-X draw-position cache (ID37/40 semantics), with **current-camera U unchanged**, and a CPU held/moving/held draw-state assertion. Do not apply a global camera offset, fog/brightness change, or XML tweak. The existing controlled ID37 GPU A/B is sufficient to bound likely visible magnitude; repeat it only if a later source change alters that path or a specific ID40 residual is isolated.

For the larger *apparent* bridge-atmosphere question, obtain **one lossless original Windows forest-1 active-gameplay frame** and sidecar containing level, viewport/backbuffer and any bars, camera XY/zoom plus preceding camera X, player XY/pose/health/orbs/pickups, level-relative time, IDs119/122 elapsed/alpha/position, shader/weather phase, and transformed bounds/UV for IDs37/40/15. Reproduce the same state on exclusive physical Xorg/NVE7 Linux GPU. Register fixed pickup/branch/raft landmarks first and preserve whole-image aspect ratio; compare lower-ground ROI and isolated ID37/119/122 contributions at the same registered coordinates before color/blur judgments. A same-frame Linux hide-ID difference proves contribution only. **Patch gate:** a repeatable, material matched-state residual attributable to one draw/update operation, with a focused regression and then a physical-GPU before/after; otherwise close without a visual correction. The existing Steam JPEG alone cannot satisfy that gate.
