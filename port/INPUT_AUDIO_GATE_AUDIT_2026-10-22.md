# Input/audio release-gate audit — 2026-10-22

Scope: read-only audit of current HEAD `50ba9e9` and existing evidence; no build, capture, device test, or code change. The only new artifact is this report.

## Current evidence and gaps

- **Input:** `port/linux/SDLRenderer.cpp` opens the first SDL game controller at startup/hotplug and polls keyboard, controller buttons/left-stick, and logical-coordinate mouse (`Initialize`, `PollQuit`, `KeyDown`, `Mouse`). Scripted routes and mouse-script fixtures exercise gameplay/UI code, but bypass real physical actuation. The 2026-10-22 XTest attempt reached Xorg's keymap yet generated no SDL scancode/event; its no-motion result cannot diagnose an actual keyboard. Host `/dev/input/js0` was an Apple sensor, and no game controller was enumerated (`CHECKPOINT_STATUS.md`, physical-input and device audit). Thus physical keyboard/controller and real mouse acceptance remain open. A connected controller and a person operating the display are prerequisites to closing that gate; a synthetic-key rerun is not a substitute.
- **Audio:** `port/linux/SDLSoundPlayer.cpp` opens an SDL 48-kHz stereo device, mixes authored SFX and streamed WAV ambience, and honors SFX mute. Audio initialization failure is nonfatal (`port/linux/main.cpp`). Existing strict-Xorg `hw:1,0` ALSA runs proved non-dummy device open, two forest ambient voices, knife cue dispatch, and a 10,000-frame combined GPU/audio route (`CHECKPOINT_STATUS.md`; `port/tools/run_physical_xorg_audio.sh`). They do **not** show an acoustic waveform at the speakers, audibility/quality to a listener, or stereo placement. The default ALSA device failed in the container; explicit `hw:1,0` was required. `port/README.md` also records no playable level score because authored `japanese2.mp3` is absent; the Music option persists but cannot control that score. MP3 ambience and full original audio parity remain open.
- **Release boundary:** Offscreen integration and scripted physical-Xorg runs establish functional paths, not human input or perceived audio. Visual acceptance and private gameplay-video delivery are separately blocked; neither is completed by this audit. Ordinary scripted in-game death is not a port defect or release gate.

## One next measurable, non-GPU test

Run a **paired SDL disk-audio mix comparison** with the existing binary under test-only offscreen/software rendering (the same opt-in environment used by `port/tests/integration.sh`), never attaching to physical Xorg or `/dev/dri`. First confirm SDL's installed audio drivers include `disk`; if unavailable, record that prerequisite and do not silently substitute dummy audio. Set `SDL_AUDIODRIVER=disk` and distinct `SDL_DISKAUDIOFILE` paths. Run the same authored forest scene for equal *measured wall-clock* duration with (A) idle input and (B) scripted knife fire (`F` or `B`), SFX on in an isolated temporary settings file. Retain the logs, PCM files, byte counts and sample format. Require successful audio initialization, two ambient voices in both logs, nonzero PCM output in both, and a reproducible extra transient/energy over the idle mix at knife times in B (e.g. short-window RMS/peak comparison after alignment). Use enough wall time for SDL callbacks; a fast fixed-dt simulation alone is not sufficient. A muted-SFX control may sharpen attribution if the first pair is ambiguous.

This measures **actual callback mix output beyond cue-dispatch logging** without physical Xorg/GPU or shared-source edits. It still cannot accept speakers, physical controls, visual parity, or the absent music score. Those require separate physical-device/human checks when the devices and reviewer are available.
