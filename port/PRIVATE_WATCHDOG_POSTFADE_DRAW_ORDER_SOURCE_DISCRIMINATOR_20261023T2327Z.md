## Source chain and narrow caveats

- **Original world before UI.** `Game/src/program.cpp:293-318` draws `Game::Draw()` to the preprocess target, composites it through `Game::PostDraw()` to the backbuffer, and only then calls `UIManager::Draw()`. `Game/src/Game.cpp:354-405,428-445` submits the camera-transformed object scene and sepia postprocess. `Game/src/GameObjects/GameObjectManager.cpp:302-330` draws visible world objects in its maintained game-object order. Consequently ordinary UI is unprocessed and cannot be behind the sepia scene at this stage.
- **Original loading retirement is deferred.** `Game/src/UI/UIGameLoading.cpp:94-136` sets splash alpha to zero at `FinishedFadeOut()` and calls `PopUIDeferred("gameloading")`; `Game/src/UI/UIManager.cpp:81-94` processes that pop at the *start of a subsequent* UI update, before updating current screens. `Game/src/Game.cpp:254` calls that update before rendering. Therefore the zero-alpha loading-screen draw and the first render with **no** loading screen are different state predicates on Windows. The latter has no `gameloading` member in `m_currentScreens`; source alone does not supply its numeric ordinal.
- **Original ordinary HUD order.** `Game/src/UI/UIManager.cpp:174-229` draws current screens in insertion order, then optional cursor, then queued interactable icons. `Game/src/UI/UIScreen.cpp:161-172` draws each screen's visible widgets in `m_widgetMap` order, and `Game/src/UI/UIScreen.cpp:42-73` inserts them by name into that map. `Game/XmlFiles/UI/game_hud.xml:3-108` names the film `26_`, frame bars `29_`/`30_`, orb `40_`, and meters `9_`/`91_`, giving film → bars → orb → meters in the screen pass; `Game/src/UI/UIGameHudScreen.cpp:226-241` calls base draw before orb-count text. The optional interactable icon pass is later than all screens, not part of the world scene. This route's authored destination has no interactable-icon source, as established in `PRIVATE_FOREST_WATERFALL_LOADING_ICON_APPLICABILITY_20261023T2225Z.md`; injected objects are outside that static conclusion.
- **Linux no-splash path.** `port/linux/main.cpp:1436-1532,1560-1609` calls `scene.Draw`, `ApplyScenePostprocess`, draws film, bars, then `Hud::Draw`, followed by optional FPS/modal/death layers and a loading sprite **only while** `loadingPhase != None`. `port/game/Hud.cpp:74-124` submits orb, count, and meters. `port/linux/main.cpp:778-784` retires FadeOut when its clock exceeds 0.20 s; saved corrected observer has ordinal 423 at alpha zero with phase FadeOut, ordinal 424 with phase None and all four active update flags (`PRIVATE_WATCHDOG_POSTFADE_ACTIVE_WATERFALL_PACKET_PLAN_20261023T2325Z.md`). Thus 424 is the Linux no-loading-UI state, independent of the separate ordinal-415 first-reveal packet. Optional port-only FPS is a known diagnostic, not a newly discovered draw-order defect.

The only general composition exception is Windows' post-screen interactable-icon pass versus Linux's lack of a corresponding generic late pass. It is **not applicable to ordinary Forest→Waterfall entry** on the authored levels (`PRIVATE_FOREST_WATERFALL_LOADING_ICON_APPLICABILITY_20261023T2225Z.md`), and was already identified by `PRIVATE_LOADING_FADE_COMPOSITION_ORDER_SOURCE_AUDIT_20261023T2222Z.md`; it is not a distinct post-fade finding. The zero-alpha Windows screen may still issue a draw before deferred removal, while Linux also has a zero-alpha pre-retirement submission; neither is the requested first no-loading-UI render.
