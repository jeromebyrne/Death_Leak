# Right-stick × fractional-parallax integration risk — 2026-10-22

**Read-only verdict: no new integration conflict found in the current uncommitted source.** The outstanding blocker for a one-owner build/GPU review is already documented: the fractional-UV command is not wired into `SDLRenderer::DrawSprite`. This note records the cross-feature boundary without repeating the binding specification.

- The right-stick path is now connected from `SDLRenderer::ControllerAxes()` (`port/linux/SDLRenderer.cpp:563-568`) through the live-loop sample (`port/linux/main.cpp:455`) to `cameraTarget.Update` after motion/combat (`:694-700`). `FollowCameraWithTarget` consumes the prior target before motion (`:654-669`); successful scene replacements reset it (`:539,629,969,1000,1033,1058`). The camera passed to `LevelScene::Draw` is this same `cameraX/Y` (`:1160`), so the camera-to-scene seam is present in source.
- `LevelScene::Draw` computes parallax destination and signed UV phase from that camera (`port/game/LevelScene.cpp:1215-1251`). Thus the new stick offset can change both parallax placement and phase after follow lag/clamping; there is no separate parallax camera value to reconcile. The pure `PrepareParallaxUVCommand` in `port/linux/ParallaxUVCommand.h:24-39` does not consume controller state and introduces no competing camera ownership.
- The live full-texture UV-scroll arm still invokes integer `ForEachUVWrapSegment`/`SDL_RenderCopyExF` (`port/linux/SDLRenderer.cpp:246-261`) and neither includes nor calls `ParallaxUVCommand.h`. The float phase therefore cannot appear on GPU yet, regardless of whether the right stick moves the camera correctly.
