## Source contract and exact gap

- Windows `Game/src/GameObjects/ParallaxLayer.cpp:37-83` computes continuous float UVs, with an unflipped camera-X term `-camX * multiplier`; `Game/ShaderFiles/BasicLightTexture.fx:11-16,37-55` passes those UVs through a `WRAP` sampler with linear minification/point magnification and alpha multiplication. Forest IDs 37/40 have multiplier `.000690`, texture width 2048, and a 2048-world-unit whole quad (see `port/FOREGROUND_PARALLAX_DIRECTION_AUDIT_2026-10-22.md`).
- Linux `port/game/LevelScene.cpp:1204-1245` already hands off the **correct SDL-facing sign**: `uvShiftX = cameraX * multiplier * (flipX ? -1 : +1)`, while suppressing ordinary repeat-X. Do not reverse this, change the authored XML, or conflate UV phase with the separately documented one-update follow-X destination lag.
- `port/linux/SDLRenderer.cpp:246-261` sends that float to `ForEachUVWrapSegment`; `port/linux/UVWrap.h:15-26` floors `fract(shift)*pixels` to an integer `cut`. The resulting `SDL_Rect` source and destination fractions cannot express a subtexel shift. At held camera X 1000 then 1000.5, the phases are `.690000` and `.690345`; `2048*phase` is `1413.12000` and `1413.82656`, both `cut=1413`. Expected continuous feature movement is `.47104` logical screen px at 2/3 projection, while the current copy layout stays identical. This is a small motion-phase issue, not evidence for a broad darkness fix.

## Narrow implementation seam

1. Add a CPU-only coordinate helper adjacent to `port/linux/UVWrap.h` (e.g. `port/linux/ParallaxUV.h`) taking `shiftX`, `shiftY`, `flipX`, `flipY` and yielding **float**, unquantized UVs for the four screen corners. Preserve the existing SDL-facing signed shift from `LevelScene.cpp:1234-1240`. For each axis, normalize only by `phase = shift - floor(shift)` (finite inputs); at the screen-leading edge use `phase`, and at the trailing edge use `phase + (flipped ? -1 : +1)`. Thus X is `left=phaseX`, `right=phaseX±1`; Y is `top=phaseY`, `bottom=phaseY±1`. Do **not** apply a second sign reversal for flips. An equivalent unnormalized `shift, shift±1` is fine; normalized phase avoids float growth in long auto-scroll. The GL texture-coordinate orientation must be checked against the existing SDL-bound custom-quad convention in `SDLRenderer.cpp:310-324,382-390`, not against top-first PNG rows directly.
2. In `port/linux/SDLRenderer.cpp:246-261`, replace the integer segment path **only** for full-texture, unrotated UV-scroll sprites when the OpenGL renderer is active, with one float-UV quad. Keep the existing branch as a test-only/non-GL fallback and for any unsupported texture binding. Follow the state transaction already established in `DrawPixelWobble` (`SDLRenderer.cpp:335-405`): `SDL_RenderFlush`, save active texture/binding/program/matrix and texture sampler parameters, bind via `SDL_GL_BindTexture`, set `GL_REPEAT` on S/T, select `GL_LINEAR` minification and `GL_NEAREST` magnification (or the existing exact-size mip-chain choice after the fog-mip owner finishes), enable alpha blending, set 1280×720 orthographic projection, draw a quad using the helper's float UVs and `destination`, then restore all touched state and unbind. Reproduce the current texture tint/alpha semantics; where `Sprite::opacity` is the authored float alpha (`Renderer.h:41-54`, `LevelScene.cpp:1246-1249`), multiply it once rather than silently discarding it or double-applying the SDL alpha mod. Preserve per-pixel texture alpha and `GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA` blending. Do not route repeat-X ordinary sprites, rotated/source-rect sprites, pixel-wobble, foliage-sway, or damage-burst through the new path; dispatch precedence at `SDLRenderer.cpp:226-266` already separates them.
3. **Texture-span gate:** `SDL_GL_BindTexture` can return a physical span smaller than 1 for padded/atlased allocations. Blind `GL_REPEAT` would then wrap across padding, not the authored image. Require both spans to be 1 (within a deliberately small tolerance) for the direct one-quad path. If an affected texture has a subunit span, supply an exact-size private GL texture (the PNG upload/mip approach in `SDLRenderer.cpp:587-681` demonstrates a pattern) before claiming full equivalence; otherwise retain the integer fallback and log the remaining fractional-gap case once. Do not merely multiply a wrapped coordinate by `textureSpan`: that samples padding and creates an incorrect edge seam. This gate is especially relevant to non-power-of-two ID40 height 677. No GL capability/texture-span claim was made in this CPU-only audit.
4. Keep `UVWrap.h` and its integer-copy behavior available for fallback and existing waterfall regression coverage. Avoid changing `LevelScene.cpp` or shared scene timing; the fix belongs at the float-to-integer renderer boundary.

## Focused CPU gate (no GPU required)

Add `port/tests/fractional_parallax_uv_test.cpp` as a header-only geometry/phase test and a small explicit target analogous to `port/Makefile:20-24`; compiling just that test is sufficient for this gate. Do not build/run it concurrently with the GPU/fog owner. Assertions should cover:

- Unflipped 2048-width forest case: C=1000 and 1000.5, multiplier `.000690`; `leftU` advances `.000345` and mapped source position `leftU*2048` advances `.70656` texel, despite both old integer cuts being 1413. This guards against accidental use of `cut / width` in the new helper.
- Rightward camera movement maps a fixed unflipped feature left: `destination.width * deltaU = (2048*2/3)*.000345 = .47104` logical pixel in magnitude. Separate this UV assertion from the scene handoff already checked by `port/tests/parallax_speed_test.cpp:25-48`.
- `shift=0`, `.999`, `1`, `1.001`, and negative shift (e.g. `-.25`) keep exactly a one-UV-span edge-to-edge mapping and continuous modulo-1 phase; no degenerate zero-length seam or sign flip. For flipped X/Y compare corner mapping to `UVWrap.h:20-26` at integer-aligned cuts, then assert fractional phases still differ inside one cut bin. A pure helper test can validate geometry and phase, **not** GPU sampler filtering, SDL texture-span behavior, or resulting RGB pixels.
