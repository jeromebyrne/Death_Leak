## Source-backed mechanism

- Authored `Game/XmlFiles/levels/forest_exploration_2.xml:9-32` makes ID1 a 1985×1090, alpha-.90 `tree_strip_bg.png` ParallaxLayer with `followcamx=true`, X/Y UV multipliers `.000059/.000024`. IDs28 and 36 at `:442-465` and `:571-594` are 2048×677 `trees_top.png` and 2048×512 `shrubbery.png`, alpha .95, `followcamx=true`, `repeatX=true`, X multiplier `.000690`. All three are `always_update=true`. Thus placement affects broad authored quads, even if a moving-frame difference proves visually small.
- Original `Game/src/GameObjects/ParallaxLayer.cpp:26-35` calls `Sprite::Update(delta)` **before** assigning `m_position.X = camX`; `Sprite.cpp:358-365` passes through `DrawableObject::Update`, whose `DrawableObject.cpp:41-43` calls `GameObject::Update`. In `GameObject.cpp:160-212`, that update builds `m_world` translation from the **previous stored position**. `Sprite.cpp:626-637` then gives this matrix to `effectlighttexture` draw. `GameObjectManager.cpp:234-237,320-329` updates always-update objects and later draws them; it does not rebuild the world matrix between the parallax follow assignment and draw. Meanwhile `ParallaxLayer.cpp:37-40,65-89` uses the **current** camera X to set the authored X UV phase. At any nonzero camera step, original draw therefore combines prior-follow quad translation with current-camera UV phase. This is a timing fact, not an assertion that the original design is desirable.
- Port `port/game/LevelScene.cpp:1364-1372,1392-1401` submits **current** `cameraX` as both followed quad center and UV-phase input for every `followCameraX` ParallaxLayer except ID59. Its special previous-X retention at `:883-892,1368-1369` applies only to XML ID59, not Forest-2 IDs1/28/36. Forest-2 therefore lacks the original update-before-follow placement lag on moving-camera draws. The established UV sign/span translation (`:1395-1406`) is not disputed here.

A deterministic command example, **not a measured frame**: after a prior eligible update stores camera X=100, an eligible update/draw at camera X=108 leaves the Windows world translation at X=100 and followed position at 108 for the next update; Linux centers all three quads at 108 immediately. With the 2/3 world-to-1280×720 scale used in the port, this is a 5⅓-screen-pixel geometry offset across broad layer heights (ID1 ~727 px, ID28 ~451 px, ID36 ~341 px before viewport clipping). The current-camera UV phase should remain unchanged in both arms. The exact direction/size on the saved `L:150/240` route depends on its camera history; no packet here records those original-Windows matrices or registered pixel residuals.
