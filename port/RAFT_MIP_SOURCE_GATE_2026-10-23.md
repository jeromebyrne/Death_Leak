# Raft mip source gate — 2026-10-23

**Verdict: source/API-contract mismatch is concrete; pixel impact is unmeasured.** Forest-1 sprite IDs 11/57/58 all use the nonanimated `Media/objects/raft.png`, 458.298584×125.316017 world units, `effectlighttexture`, and no repeat (`Game/XmlFiles/levels/forest_exploration_1.xml:191-203,928-955`). The PNG is 1024×280 RGBA (`Game/Media/objects/raft.png`; file header), so at the port's 2/3 projection its full quad is ~305.5×83.5 output pixels (~3.35× minification per axis).

**Original Windows path.** `Sprite::LoadContent` sends every nonanimated sprite filename to `TextureManager::LoadTexture` (`Game/src/GameObjects/Sprite.cpp:162-170`); that function calls `D3DX10CreateShaderResourceViewFromFile` with **null load info** (`Game/src/Core/TextureManager.cpp:50-79`, especially :66). Microsoft's [API reference](https://learn.microsoft.com/en-us/windows/win32/direct3d10/d3dx10createshaderresourceviewfromfile) says null load info uses texture characteristics; its [D3DX10_IMAGE_LOAD_INFO reference](https://learn.microsoft.com/en-us/windows/win32/direct3d10/d3dx10-image-load-info) explicitly says `MipLevels=0` or `D3DX10_DEFAULT` creates a **full mip chain**. No source override requests one level for these sprites. XML `effectlighttexture` maps to `EFFECT_LIGHT_TEXTURE` (`Game/src/GameObjects/DrawableObject.cpp:168-179,133-141`); `Sprite::Draw` selects that path and binds the loaded SRV (`Game/src/GameObjects/Sprite.cpp:369-379,626-635`; `Game/src/Effects/EffectLightTexture.cpp:51-57`). `BasicLightTexture.fx:10-16,53-56` samples it with `MIN_LINEAR_MAG_POINT_MIP_LINEAR`. Thus the normal Windows source/API path generates and selects mip levels for minified raft; this is stronger than the prior conditional inference, though no live Windows `GetDesc`/SRV capture was made.

**Current Linux path.** `port/linux/SDLRenderer.cpp:153-188` decodes the PNG and creates one `SDL_Texture` from one surface. The ordinary sprite draw selects `SDL_ScaleModeLinear` when minified (`:197-225`) and uses SDL copy/ex-copy (`:263-267`); it has no ordinary mip chain or LOD selection. IDs 11/57/58 reach the ordinary draw path from `port/game/LevelScene.cpp:1254-1263,1275-1307`. Private GL effect handling elsewhere does not alter this path. Therefore Linux base-level bilinear filtering does **not** match Windows mip-filtered minification for these pieces. This establishes a sampling-contract mismatch, **not** that any particular Steam screenshot softness, haze, or pixel difference is caused by it.
