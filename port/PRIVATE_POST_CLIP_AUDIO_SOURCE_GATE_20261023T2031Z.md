## One source-backed active-Forest discrepancy

**Accepted player jumps and rolls have no authored player jump vocal SFX in the Linux port.** This is an event-coverage gap, not a failed SDL callback or speaker claim. The original Windows `Character::Jump` calls `PlayJumpSFX()` only after `CanJump()` and water checks pass (`Game/src/GameObjects/Character.cpp:1239-1258`); a successful `Roll` also calls it (`:1460-1494`). `PlayJumpSFX()` returns for non-players, then uses `rand()%20`: values 0–4 each select one of `character/jump_1.wav` through `jump_5.wav`, and values 5–19 play no vocal (`:1497-1525`). All five authored WAVs exist in `Game/Media/Audio/character/` (51,244–96,300 bytes at inspection). Thus the source calls the picker for each qualifying player jump/roll, with a 25% vocal-selection chance per call, not a vocal on every action.

The port accepts normal jump input and advances `PlayerMotion` (`port/linux/main.cpp:787,812-814`); the motion layer recognizes a new valid jump and updates velocity/visual takeoff (`port/game/PlayerMotion.cpp:76-93`). Successful rolls are recognized by `PlayerMotion::TryRoll` (`:32-43`) and called in `main.cpp:795-797`. Neither path sends a sound cue. The complete port `Cue` enum has only KnifeThrow, OrbCollect, FinalTitle, StoneSmash, PaperPickup, HealthUpgrade (`port/audio/SoundPlayer.h:12`), and the SDL sample manifest/mapping has no jump WAV (`port/linux/SDLSoundPlayer.cpp:27-33,53-59`). The main loop's current cue calls cover those six events, not jump/roll (`port/linux/main.cpp:660,823,837,884,1083,1099`). So active Forest traversal and rolls remain audibly sparser even with SFX enabled and a working output device.
