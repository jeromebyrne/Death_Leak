# Forest knife versus solid-line material spray — CPU slice (2026-10-22)

Implemented one dry player-knife solid-line contact emitter in `Combat`, using the winning ground segment's material texture already loaded by `LevelScene`. Forest-1 SolidLineStrip ID3 has `grassground`, whose sole active material particle texture is `Game/Media/rock_particle.png`. The event creates ten nonlooping particles at projectile depth 2500 before the existing immediate shot removal. The spray is drawn through the existing combat painter stream and updated/retired through the existing combat material-spray path. Enemy-presence pass-through, non-player shots, boxes, contact removal, and other emitters remain unchanged.

Source mapping: `SolidLineStrip::GetProjectileCollisionData` writes `collisionPosition = line.Position() - projectile.GetCollisionRayEnd()`. `Projectile::HandleSolidLineStripCollision` then sets `particlePos = line.Position() - collisionPosition`, so its actual origin is the **collision ray end**, not the line intersection. In the port, ground strips retain only world endpoints and swept contact checks a projectile center. This patch maps the source ray end to the untruncated candidate center at the end of the tick plus half the 84.5-unit knife width along its fixed horizontal launch direction. The source collision geometry/timing and global RNG stream are not reproduced; event, asset, depth and dry parameter envelope are the bounded claims.

CPU fixture `port/tests/knife_line_material_spray_test.cpp` loads the authored forest level and crosses ID3. It checks exactly one 10-particle spray, texture, depth, origin mapping, draw bounds, direction/spread, per-particle lifetime, speed, size, gravity, brightness, spawn offsets, fades and scale; later ticks do not duplicate the event. Negative cases cover noncontact, box-only contact, a living-enemy blade pass-through and an enemy projectile's line contact. The existing knife visual lifecycle fixture also passes. Both were compiled directly from `Combat.cpp`, `LevelScene.cpp` and TinyXML with `g++ -std=c++17` and run without the game binary or GPU. TinyXML emitted preexisting compiler warnings only.

**Remaining gate:** GPU owner should capture the same-camera impact instant and ages .1–.75 seconds to establish onscreen visibility. Matched Windows comparison additionally requires matching projectile/line/camera state, effect age, and RNG. No visual acceptance or pixel parity is claimed.
