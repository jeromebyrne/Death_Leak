# Current renderer-diff visual QA — 2026-10-22

Scope: read-only review of the uncommitted diff in `port/linux/SDLRenderer.cpp`, `port/linux/main.cpp`, `port/render/Renderer.h`, and `port/tests/integration.sh`, against original Windows behavior and current port scene code. Only this handoff was written. No source edits, build, game/GPU run, or shared checkpoint/status change. This is static evidence, not a pixel-parity verdict.

## Findings

1. **Medium — active forest strafe omits the source's persistent aim line and can point its brief line opposite the body.** The new `SDLRenderer::ControllerAxes` plus `main.cpp:691-693,1092-1093` activates `PlayerStrafeVisual` for a real opposed-stick controller input. Windows `Player.cpp:345-365` refreshes the 0.05 s aim-line hold on *every* `mIsStrafing` update; `InputManager.cpp:379-395` also steers its rotation/attachment from right-stick aim. Port `LevelScene.cpp:1077-1085` refreshes only on `eligibleFireAttempt`, sets `playerAimLineFacing_ = facing` (movement-facing from `main.cpp:608-611`), while `:1099-1106` flips the strafe body to `strafe.aimFacing`; `:1213,1217,1272` hides the line at zero alpha and positions/flips any visible line by movement-facing. Thus ordinary opposed-stick strafe without firing shows no line, and an active firing line can disagree with the body/right-stick side. This was latent in the committed scene slice but becomes user-visible through this diff's live controller binding. The existing CPU fixture's aim-line case at `port/tests/strafe_body_cpu_test.cpp:181-201` forces a fire attempt and explicitly expects the old combat-facing line; it does not cover the source's no-fire strafe hold. **Next test:** render-spy two consecutive grounded forest frames with LX<−8689/RX>8689 and no fire, then with fire; assert source-expected nonzero line alpha, side/attachment, and body/line relation before matched Windows/GPU comparison.

2. **Medium — right-stick aim produces a source camera/parallax offset that this binding does not carry.** Windows `InputManager.cpp:449-458,499-503` resets the target offset when the right stick is neutral, otherwise applies `originalTargetOffset.X + 450 * rightThumbstickRangeX`; `:379-395` also sets Y offset from right-stick Y. The new port snapshot is consumed only by `ResolvePlayerStrafeVisual` (`main.cpp:454,691-693`); camera follow still uses fixed `scene.CameraOffsetX/Y()` at `main.cpp:675-683`. Port parallax draw depends directly on camera X/Y (`LevelScene.cpp:1215-1251`), as the Windows `ParallaxLayer.cpp:37-72,114-140` does. Consequently an active right-stick aim/strafe shot can retain the wrong camera center and parallax phase despite correct body flip. No changed code directly alters UV sign, sprite rotation, or parallax rendering; this is missing input-to-camera coupling, not proof of a shader regression. The earlier `FOREST_VISUAL_BEHAVIOR_GAP_2026-10-22.md` already flags camera aim offset as outside the body slice; this review confirms the current live input diff has not closed it. **Next test:** trace right-stick ±X/Y at a fixed forest player XY for original target-offset/camera state versus Linux camera and one parallax ID's UV/position; then capture matched frames.

3. **Low — current integration diff does not gate these active visuals.** `port/tests/integration.sh` changes only long-route orb/health/death expectations (around lines 164-330); its existing CPU strafe fixture (`:8-17`) constructs stick values and checks a scene spy, not `SDLRenderer::ControllerAxes` or the live `main.cpp` frame path. A passing integration run therefore cannot establish no-fire aim-line, controller disconnect, camera offset/parallax, or physical-GPU forest flip/rotation fidelity. No new source-level flip/rotation regression is visible in the reviewed diff: the rotation/UV/flip branches in `LevelScene.cpp:1245-1276` and SDL draw paths are unchanged. **Next test:** one live/controller-injection forest acceptance sequence covering opposed left/right strafe, release, roll, and landing, with camera/line/body draw state and a matched Windows capture. Keep the reserved fog-mip GPU lane exclusive.

## Verdict

The uncommitted renderer-facing changes are a narrow controller-state plumbing patch, not a general renderer rewrite. The strongest concrete forest-visible gaps are the missing persistent/aim-oriented strafe line and source right-stick camera offset (hence parallax composition). Static diff review finds no direct regression to the previously implemented ordinary flip/rotation or fractional parallax UV code, but runtime and Windows visual parity remain unverified.
