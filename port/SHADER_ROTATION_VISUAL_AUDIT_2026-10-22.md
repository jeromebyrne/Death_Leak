# Shader-specific sprite rotation visual-parity audit — 2026-10-22

## Verdict (CPU/source contract only)

Two live shader branches inherit an ordinary-copy angle decision but implement their own geometry. **Forest-1 pixel-wobble fog ID122 is rotated with authored Y flip and receives the wrong rotation sign** under the current X-only helper; ID119 is the no-flip control and currently receives the right sign. **Rotated foliage with no authored Y flip is also wrong**, but for a different reason: `DrawFoliageSway` negates the already ordinary-converted angle and applies authored flips to geometry *before* that rotation. Waterfall-top leaf-shadow IDs 66/67 are live, large, rotated examples. The prior unflipped-ordinary audit explicitly excluded custom shader paths; extending its ordinary fix alone would not fix foliage. No Windows image comparison, GPU capture, or magnitude-of-visible-opacity assertion was performed.

## Transform contract and branch accounting

`Game/src/GameObjects/Sprite.cpp:19-22,89-96,215-223` binds source UVs to centered world vertices and encodes authored flips as negative scale. `Game/src/GameObjects/GameObject.cpp:202-210` forms row-vector `R*S*T`; `Game/ShaderFiles/FoliageSway.fx:41-54` applies World before world-space sway, and `Game/ShaderFiles/BasicLightTexture_PixelWobble.fx:40-49` applies World before pixel-stage UV distortion. With screen Y down, let `F=diag(sx,sy)`, where each sign is -1 for the corresponding authored flip, and `A(a)` be clockwise screen rotation by `a`. The Windows *pre-effect, UV-labeled* point is `F A(-theta) q`. The source UV labels stay attached to the four vertices; pixel wobble changes sample coordinates afterward, while foliage displaces the transformed vertices afterward.

`port/game/LevelScene.cpp:997-1012` passes authored Y directly to custom shader branches, but gives **all** sprites `phi=OrdinarySpriteRotationDegrees(theta, flipX) = -sx*theta` (`port/render/OrdinarySpriteRotation.h:4-10`). It does not consider flipY. The ordinary light-texture copy (`port/linux/SDLRenderer.cpp:207-249`) maps UV-labeled points as `A(phi) F q`; equality needs `phi=-sx*sy*theta`, as the prior `UNFLIPPED_ROTATION_VISUAL_CONTRACT_AUDIT_2026-10-22.md` established. Thus its authored-Y counterexamples remain; no new ordinary-copy mismatch is claimed here.

**Pixel wobble:** `port/linux/SDLRenderer.cpp:353-369` rotates its screen quad by `+phi` and `port/linux/WobbleUV.h:8-14` assigns authored-flipped D3D UVs, so its labeled-point map is also `A(phi) F q`. The GLSL retains source UV order and converts V only when sampling (`SDLRenderer.cpp:608-620`); this does not cure geometry. Forest-1 `Game/XmlFiles/levels/forest_exploration_1.xml:1631-1659` authors both 1988x1290 fog quads at `theta=+0.11`: ID119 X=false/Y=false wants `phi=-0.11` (current correct), ID122 X=false/Y=true wants **`phi=+0.11`** (current `-0.11`). Their centers, scrolling, and alpha need no adjustment for this discrepancy. For a corner at the quad half-extents, the two angular outcomes differ by up to roughly `2*sin(.11)*sqrt(994^2+645^2) ~= 260` world units (about 174 logical output pixels); that is only a corner-coordinate bound, **not** a predicted opaque-pixel delta. Pixel UV wobble itself is separately implemented and does not justify shifting fog by that amount.

**Foliage sway:** `port/linux/SDLRenderer.cpp:383-413` explicitly reflects each source vertex using authored X/Y then rotates it by **`-phi`** before applying the world-space sine; its map is `A(-phi) F q`. To match Windows, this branch needs `phi=+sx*sy*theta` *with its present minus sign*, or equivalently it can consume the ordinary-corrected `phi=-sx*sy*theta` and rotate by `+phi`. Today `phi=-sx*theta`, so all **non-Y-flipped** rotated foliage has opposite geometric rotation (for Y-flipped foliage the current signs happen to agree). `Game/XmlFiles/levels/waterfall_top.xml:1148-1176` authors large 2000x252 leaf-shadow sprites 66/67, X=true/Y=false, theta -0.099903/+0.080501 with `effectfoliagesway`; these are concrete examples. `FoliageSway.fx:44-52` uses the post-World position in both sway phases, so wrong base rotation also changes phase inputs. `port/linux/SDLRenderer.cpp:414-449` assigns UVs after finding flipped corners; `port/linux/FoliageSway.h:7-12` handles source V orientation. This audit does **not** overturn the earlier foliage-V correction or assert that its wrap tiling is otherwise exact.
