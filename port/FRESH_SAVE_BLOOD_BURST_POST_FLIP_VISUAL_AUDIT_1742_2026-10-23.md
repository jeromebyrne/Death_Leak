# Fresh-save sword-pull blood burst: post-flip visual audit (17:42, 2026-10-23)

## Highest-impact remaining source-backed pixel mismatch

**The Linux intro burst uses `fadeIn = 5` and `fadeOut = 1` where the original directed ParticleSpray receives `fadeIn = 0.1` and `fadeOut = 0.8`.** This is a draw-alpha contract error across both burst emitters (70 particles), independent of the now-applied horizontal U flip. It makes the visible burst almost transparent through its entire short life and omits the source's late fade-out. This is source/implementation evidence, not a matched Windows screenshot or GPU measurement.

- The original sword-pull transition calls generic `CreateDirectedSpray` twice, for 20 `bloodparticle2.png` and 50 `bloodparticle3.png` particles. After `scaleTo` (3 and 1.75), the final four call arguments are `5.0f, 1.0f, 0.1f, 0.8f` in each call (`Game/src/GameObjects/Player.cpp:1035-1083`). The function signature orders these as `spawnSpreadX`, `spawnSpreadY`, `fadeInPercentTime`, `fadeOutPercentTime` (`Game/src/Particles/ParticleEmitterManager.cpp:390-397`); it passes them to the spray setters at `:540-541`. The original generic constructor has `isBloodSpray=false` (`:515-526`), so `Particle.fx`, **not** `BloodParticle.fx`, is selected (`Game/src/Particles/ParticleSpray.cpp:436-450`).
- Windows `ParticleSpray::Update` computes `percentTimeLeft = (MaxLiveTime-CurrentTime)/MaxLiveTime`, sets alpha to `percentTimeLeft/(1-fadeOut)` only when `percentTimeLeft < 1-fadeOut`, otherwise sets it to `(1-percentTimeLeft)/fadeIn` only during the early fade-in (`Game/src/Particles/ParticleSpray.cpp:233-258`). This alpha is carried in vertex Normal.x; brightness is Normal.y (`:260-267`). `Game/ShaderFiles/Particle.fx:52-59` multiplies sampled RGBA by brightness and sampled alpha by Normal.x. The source quad's U reversal is already represented by Linux `leaf.flipX=true` (`Game/src/Particles/ParticleSpray.cpp:8-11,191-219`; `port/game/ParticleSpray.h:83-101`).
- Linux makes the corresponding two emitters in `port/game/LevelScene.cpp:1072-1116`, but sets **`spray.fadeIn = 5.f; spray.fadeOut = 1.f` at `:1093-1095`**, apparently transposing the source spawn-spread arguments into fade settings. Its `ParticleSpray::Update` follows the source formula (`port/game/ParticleSpray.h:40-60`) and `Draw` maps fade and brightness into SDL sprite tint (`:83-101`); `SDLRenderer::DrawSprite` applies the alpha tint to the texture (`port/linux/SDLRenderer.cpp:205-236`) and submits via SDL copy (`:275-280`). Consequently the wrong fade values reach actual pixels. The Linux burst draw is reached through `port/game/LevelScene.cpp:1438-1439`.

## Concrete isolated discriminator

Use a single opaque-texel, brightness-1 particle in a recording `Renderer` or deterministic 1-particle SDL capture (no art/XML change). Give it lifetime `0.75 s`, initial elapsed `0`, and invoke `Update(0.15 s)` once, then `Draw`; keep its fixed position/size, camera, texture, and flipped U identical. The source fade parameters yield **alpha 1.0 / tint 255** at 20% lifetime, whereas current Linux parameters yield **alpha 0.04 / tint 10** (`0.2/5`, rounded), an approximately 25× opacity difference at the same pixel. At 90% lifetime, source alpha is 0.5 while Linux remains 0.18, also separating late fade-out. A source-parity fix should assign `.fadeIn=.1f`, `.fadeOut=.8f` to both intro burst recipes without changing spawn spread, art, U/V, or generic renderer behavior. A fixed-frame fresh-save held-pull capture can then test the visible 70-particle effect once the exclusive GPU owner releases that lane; this audit does not claim final visual acceptance.
