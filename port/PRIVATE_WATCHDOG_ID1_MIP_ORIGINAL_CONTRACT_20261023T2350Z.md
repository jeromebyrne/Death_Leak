# ID1 original D3DX mip/entry-frame LOD contract — 2026-10-23 23:50Z

## Decision

**A successful original-source D3DX10 load is expected to create a full mip chain, but the authored original 1920×1080 camera/render target predicts level-0 sampling for Waterfall ID1 at the nominal entry frame.** The previous post-snap gate correctly identifies a general sampler-capability difference with the 1280×720 Linux ordinary-copy path; its ~1323×727 destination and ~0.585 nominal LOD are *Linux presentation* calculations, not evidence that the original D3D10 scene uses lower mips. Neither an actual original ID1 SRV descriptor nor per-pixel LOD has been read back. Consequently, ID1 is not yet a proven original-Windows-versus-Linux pixel error, and adding mips to this scene draw solely on source expectation is premature.

## Exact evidence and calculation

- `Game/Media/objects/tree_strip_bg.png` SHA-256 `6ffd55b67049473570eea3c9964cf03e23367ea6a814c2b19219a0e191847046` is **1985×1090 RGB**, not RGBA (PNG metadata also records gamma 0.45455). It contains a single source image; any lower levels would be generated by the loader, not embedded PNG frames. The authored opacity is a separate `0.900000` field (`Game/XmlFiles/levels/waterfall_top.xml:9-18`). Its `native=true`, 1985×1090 world quad, no flip/rotation/repeat, `effectlighttexture`, `followcamx=true`, `followcamy=false`, X/Y parallax UV multipliers 0.000059/0.000024, and camera zoom `1.000000` are at `waterfall_top.xml:3,9-31`.
- The nonanimated `Sprite::LoadContent` calls `TextureManager::LoadTexture` (`Game/src/GameObjects/Sprite.cpp:162-170`); the native-dimension initialization reads its texture resource dimensions (`:73-98,107-149`). `TextureManager.cpp:50-79` calls `D3DX10CreateShaderResourceViewFromFile(device, path, nullptr, nullptr, &texture, nullptr)` with **null load info and no explicit one-level override**. Microsoft's D3DX10 API/load-info contract, already documented with links in `port/RAFT_MIP_SOURCE_GATE_2026-10-23.md`, predicts `MipLevels=D3DX10_DEFAULT/0`, i.e. a full chain. For a 1985×1090 2D resource, that means **11 levels, 0–10** (`floor(log2(1985))+1`), *if* the default load succeeds and the resource/view exposes the expected levels. The call does not assign its HRESULT to local `hr`; the source's `FAILED(hr)` is therefore not evidence of success, while the non-null pointer check is (`TextureManager.cpp:62-76`). No D3D10 descriptor or actual mip texels for ID1 exist in this checkout.
- Original source initializes the backbuffer and viewport to **1920×1080** (`Game/src/program.cpp:15-18,261-280`; `Game/src/Core/Graphics.cpp:49-60,262-281`), creates the camera from backbuffer dimensions (`Game/src/Game.cpp:92`), sets an orthographic projection to those dimensions (`Game/src/Core/Camera2D.cpp:10-30`), and applies Waterfall zoom 1.0 from XML (`Game/src/LevelProperties.cpp:24-27,43-53`; `Camera2D.cpp:262-280`). The Steam Deck branch changes **window** dimensions to 1280×720, not `gBackBufferWidth/Height` (`program.cpp:103-109`). Original `ParallaxLayer::Update` follows camera X, and `Draw` shifts UVs by camera/parallax without changing UV span 1 or quad size (`Game/src/GameObjects/ParallaxLayer.cpp:26-35,37-111,114-159`). Thus the nominal ID1 source footprint is 1985×1090 texels over 1985×1090 *1920×1080 render-target* pixels, even though part of the quad is clipped. Translating the camera and shifting UV origin do not change derivatives. With one UV span across the unrotated native quad, `rho=max(1985/1985,1090/1090)=1`, so implicit `lambda=log2(rho)=0`: **level 0 is the likely sampled level**, notwithstanding a full resident chain. The shader requests `MIN_LINEAR_MAG_POINT_MIP_LINEAR`, WRAP U/V and texture sampling with authored alpha multiplication (`Game/ShaderFiles/BasicLightTexture.fx:10-16,53-59`; `Sprite.cpp:626-669`). At exact LOD 0, mip-linear cannot blend in level 1; min-vs-mag boundary and fractional raster effects remain runtime details.
- Linux `port/linux/SDLRenderer.cpp:153-185,205-245` loads one SDL texture and picks linear for the ordinary minified scene copy, with no per-copy mip selection. At Linux's 1280×720 projection the same authored 1985×1090 quad is about 1323.33×726.67 pixels, giving `rho≈1.5`, `lambda≈0.585` **for that renderer**, provided the draw reaches the ordinary branch. This is not the original D3D10 target footprint. An eventual 1920→1280 output/window reduction is a separate image resample after original scene shading, not proof of ID1 mip LOD during the D3D10 draw (`program.cpp:293-322`).

## Limits and next exclusive-GPU discriminator

The nominal LOD calculation assumes the source-built original's declared backbuffer/viewport, native quad dimensions, 1.0 zoom, unit UV span, no dynamic geometry scale, and an actual ID1 draw at the active post-snap frame. It does **not** prove the shipped binary uses this exact source, that D3DX created all 11 levels, that the effective bound SRV exposes them, or that every fragment selects exactly LOD 0. The camera-following source makes visibility plausible but does not replace the fresh post-snap ordered packet. Previous `port/PRIVATE_WATCHDOG_WATERFALL_POSTSNAP_NONPLAYER_VISUAL_SOURCE_GATE_20261023T2349Z.md` and `port/WATERFALL_LIGHT_LAYER_AUDIT_2026-10-22.md` cover priority and generic filter differences; `port/RAFT_MIP_WINDOWS_BINDING_GATE_2026-10-23.md` covers the reusable D3D descriptor route. This report's distinct finding is the **original-target 1:1 LOD-zero prediction**, which weakens a mip-level explanation for entry-frame ID1.

After the current GPU packet owner releases its fresh post-camera-snap capture, check actual ID1 presence, destination, UV span, zoom/viewport and painter slot.
