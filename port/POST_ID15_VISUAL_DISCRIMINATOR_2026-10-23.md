# Post-ID15 forest visual discriminator — 2026-10-23

## Decision

**Next bounded, source-backed visual discriminator: ordinary-sprite minification on the forest-1 raft (XML IDs 11/57/58).** This is a *conditional sampling-parity question*, not an established visible defect or a proposed blanket renderer change. The original requests mip-linear minification for these textured sprites; the current Linux ordinary SDL copy has base-level linear scaling but no mip selection. The raft appears repeatedly in the only identifiable original forest-1 Steam composition, screenshot 14. Its 1024×280 RGBA art is rendered at approximately 306×84 pixels at the port's 2/3 projection, about 3.35:1 minification, so this is a high-leverage, spatially narrow test. Earlier reports `NEXT_FOREST_VISUAL_GAP_0247_2026-10-22.md`, `RAFT_MIP_SOURCE_GATE_2026-10-23.md`, and `RAFT_MIP_WINDOWS_MATCH_FEASIBILITY_2026-10-23.md` already identify the candidate; this report selects its **next decision gate after the now-completed ID15 test**, not a newly found issue.

The 540-frame baseline/hide-ID15 physical-GPU pair in `ID15_GPU_CAUSAL_CAPTURE_2026-10-23.md` changes 79,175 RGB pixels only in the right-side shaft bbox `[1011,316,1280,649)` with identical printed gameplay state. It is a qualified attribution because `elapsed=` is nondeterministic wall time and violates that protocol's full-line equality gate. No further Linux ID15 hide capture is the highest-value next step. It cannot decide original Windows parity: Steam screenshot 14 shows the earlier ID117/raft region and geometrically excludes ID15 (`FOREST_ID15_MATCHED_REFERENCE_2026-10-22.md`). A lossless original Windows frame near the right exit remains the separate prerequisite for *ID15* edge/color parity. Do not interpret the attribution as an instruction to remove or recolor the authored shaft.

## Executable decision protocol

**A. Non-GPU preflight now (source/assets only).** Verify the three XML IDs still share the same hashed raft PNG and ordinary draw branch in the integration tree; record their projected texture-to-screen ratios from their authored dimensions and actual current view scale. A CPU image analysis may estimate whether single-level point-sampled bilinear versus a *labeled approximate* mip pyramid changes high-frequency/alpha-edge regions, but must not be used as a Windows-renderer or SDL pixel reference: mip generation, filtering, alpha treatment and rasterization are implementation-dependent. The preflight ends at a *test-worthiness* decision, not a parity verdict. If the branch or asset changed, re-evaluate rather than applying this older diagnosis blindly.

**B. First decisive external fact, when an authorized Windows renderer is available.** At an actual ID11/57/58 `Draw_effectLightTexture` call, record the bound SRV's `GetDesc` (dimension, most-detailed mip, view mip count), its `GetResource`/`ID3D10Texture2D::GetDesc` (width, height, resource mip count, format), and the bound `BasicLightTexture` sampler. Associate object ID/texture path, EXE/build and asset hashes, and a rendered frame. A source-built Windows run must be labeled source-built, not shipped-binary proof. **If the bound view exposes only mip 0, close the mip candidate for that runtime without a Linux mip edit.** Multiple viewable mips make the candidate live but do not yet prove a visible parity error.

**C. Only later, on an exclusive GPU/capture lane, test pixels.** Acquire one native-size, lossless original Windows forest bridge frame plus atomic same-frame sidecar, then a Linux frame with the same effective view/projection, viewport, player/raft transforms, object visibility, shader/postprocess time and weather state. Capture matching stages (prefer scene pre-sepia/pre-HUD and final composite separately); use a raft-local ROI, not a whole-screen/JPEG score. On the Linux side compare the same frozen executable or controlled render-only branch with raft mip sampling off/on, scoped *only* to IDs 11/57/58, preserving flips, rotation, painter slot, UV wrap, tint/alpha, blend, and sepia; restore GL state before the next SDL draw if a private-GL path is used. Record both the isolated raft contribution and final crop. A Linux off/on delta proves local effect only. Promote a raft-specific implementation solely if the on-crop reduces a reproducible, registered error to the matched Windows crop without introducing alpha seams or collateral changes. If the effect is negligible or worsens the match, close or defer it; do not generalize mips to all ordinary sprites on this evidence.

## Ranking and handoff

This ranks ahead of another Linux-only ID15 attribution because that causal identity is now established, and ahead of guessing at broad haze/lower-band color because the raft has an explicit source-path fork and a narrow object-scoped experiment. **The current blocker is original Windows runtime/frame access, not another Linux replay.** Windows ID15 right-exit acquisition remains an independent, higher-level parity dependency; the raft test must not be represented as resolving it. Physical GPU capture and combat integration are owned elsewhere. This lane made no source/test/shared-checkpoint edit, build, game/GPU run, commit, or parity claim; this report is its only write.
