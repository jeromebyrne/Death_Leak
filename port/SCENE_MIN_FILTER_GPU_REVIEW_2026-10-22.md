# Scene minification GPU review — 2026-10-22

## Verdict

**Accept the scoped SDLRenderer software correction for commit/push.** The Docker build, SDL rotated-flip primitive test and physical-GPU waterfall smoke passed. Lossless, deterministic pre/post captures at authored shaft IDs 46/47 show a bounded change to the translucent shaft edge; no disappearance, hard cutoff, compositing-order change, or obvious broader scene break was found. ## Change and source basis

Only `port/linux/SDLRenderer.cpp` was changed. Before each ordinary SDL texture copy it selects linear for pre-sepia minification and nearest otherwise, resetting the per-texture state per draw so HUD reuse does not inherit scene filtering. `BeginFrame` opens that phase; `ApplyScenePostprocess` closes it. Source rectangles and repeat-X's 2/3 tile scale are considered. Alpha, tint, blend, source UV, rotation, flip and painter order are unchanged. The two ordinary `sun_shaft_2.png` sprites are ID46 (X-flipped, -1.52 degrees) and ID47 (-1.47 degrees), 512x512 displayed near 341.3x341.3 at 2/3 scale. `Game/ShaderFiles/BasicLightTexture.fx` specifies `MIN_LINEAR_MAG_POINT_MIP_LINEAR` and source-alpha compositing. SDL exposes one scale mode, not independent min/mag/mip selection: this corrects the ordinary minified case but does not emulate D3D mip selection, mixed-axis sampling, or exact sampler arithmetic. Dedicated GL effects remain separately filtered. The renderer lacks a scene-begin marker, so pre-sepia menu/preview sprites may also receive this rule.

## Acceptance limits

This review cannot claim exact original D3D filtering, mip level, color-space or Windows visual parity; no original Windows matched reference was available. Broad pre-sepia scene sprites beyond the two shafts do change, so a future original-renderer matched capture should review them too. No user/Jerome visual acceptance is claimed.
