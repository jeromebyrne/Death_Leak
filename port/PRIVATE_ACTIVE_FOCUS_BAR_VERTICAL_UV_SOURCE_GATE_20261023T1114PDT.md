# Private active-gameplay focus-bar vertical-UV gate — 2026-10-23

## One unowned source-backed mismatch

The ordinary Forest-1/waterfall-top **focus (XP) meter's colored fill** is authored with `vflip="true"`, but Linux emits its `xp_meter_bar_middle.png` draw with `flipY=false`. This is a persistent active-gameplay texture-orientation mismatch whenever focus fill is visible, separate from burst, HUD film, forest painter, meter length, and meter progress cadence. It is a smaller top-left HUD visual slice, not evidence that it outranks the broad unregistered forest-reference concern in pixel area. No Windows screenshot/pixel severity is claimed.

Original `Game/XmlFiles/UI/game_hud.xml:88-97` sets `91_xp_meter` `vflip=true` and the colored bar texture. `UISprite::XmlRead` retains the vertical flag (`Game/src/UI/UISprite.cpp:27-40`), and both `UISprite::Reset` and `RebuildBuffers` choose vertically inverted texture coordinates from that flag (`:60-95, :145-180`). `UIMeter::Draw` changes `m_horizontalFlip` for each piece but never changes `m_verticalFlip` (`Game/src/UI/UIMeter.cpp:76-126`), so the colored fill remains vertically flipped in the source draw. Linux `port/game/Hud.cpp:87-94` submits the focus fill at line 89 without a `flipY` field, whose default is false (`port/render/Renderer.h:65-81`). The focus bar is loaded at `Hud.cpp:46`. The normal active-play branch calls `Hud::Draw`; no source or GPU run was needed to identify the command mismatch.

This is visually non-vacuous art: `Game/Media/UI/xp_meter_bar_middle.png` is 1×19 RGBA, with opaque rows 3–13. A read-only Pillow comparison to its vertical reverse has nonempty difference bbox `(0,3,1,16)`; e.g. source row 3 is `(0,134,178,255)` versus reversed row 3 `(255,255,255,0)`. The shared `meter_overlay.png` and `meter_edge_2.png` are vertically symmetric by the same exact RGBA comparison; hence this narrow gate targets the colored fill, not generic HUD flipping. Overlay transparency through its central rows leaves the colored fill's orientation potentially visible. Existing health-length and progress-state reports/fixtures cover width, timing, and backing but do not claim focus vertical-UV parity; a targeted report-title/content search found no owner for this flip.
