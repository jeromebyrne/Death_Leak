# Forest composition isolation diagnostic (2026-10-22)

This is a temporary, **off-by-default**, render-only diagnostic. `LevelScene` retains each rendered XML object's source `id` through depth sorting. At draw time, set either environment variable **before starting the process**:

- `DEATHLEAK_RENDER_ONLY_XML_IDS=19` draws only XML sprite ID 19 (comma-separated lists accepted, e.g. `17,19`). The dynamically spawned orbs, which have no XML ID, are also suppressed. Non-level UI/HUD and the renderer clear/postprocess are outside this filter.
- `DEATHLEAK_RENDER_HIDE_XML_IDS=19` draws every level sprite except ID 19. Both lists apply if supplied together; unset both for unmodified rendering. Whitespace around comma-separated IDs is ignored. IDs match the current loaded level's XML `id` attribute exactly.

Only `LevelScene::Draw` applies the filter. `Load`, sorting, textures, collisions, pickups, simulation, and saves are unchanged. The filter is cached on first draw; restart the process between variants. Source XML and textures are unmodified.

## Same-frame comparison procedure (physical-GPU operator)

```sh

DEATHLEAK_RENDER_HIDE_XML_IDS=19 port/build/deathleak-linux --play Game/XmlFiles/levels/forest_exploration_1.xml --script R:180 --fixed-dt 0.0166667 --frames 180 --capture port/build/forest-hide-19.bmp
```

Keep `SDL_RENDER_DRIVER`, Xorg display, sepia switch (if added by the other lane), settings, script, fixed dt, and frame count identical. Compare the *same pixel coordinates* in baseline vs hide-ID; only-ID shows the isolated shape, but alpha compositing means only-ID colors need not equal its contribution against the full scene. Repeat for groups `17,4`, `18,20,46`, `38,39`, and `40`. Do not run simultaneous physical-GPU captures. The commands above are a recipe, **not** an assertion that these captures have been run.

## Source-versus-port render audit: concrete foreground mismatch (2026-10-22)

No additional original Windows forest-1 frame, executable, or save with a reproducible camera/time pair was found. The searched `.exe` files are absent; the save-like files under `port/build` are port artifacts. The Steam still/trailer limitation above remains. Do not treat screenshot 19 as a forest-1 target.

**Confirmed code-path mismatch, conditional on player overlap:** Forest-1 XML sprites IDs **5 and 6** (`Game/XmlFiles/levels/forest_exploration_1.xml` lines 101–124) are large `Media/objects/tree2.png` `kGroundFront` foreground trees with `<fade_when_player_occluded value="true" alphawhenoccluding="0.400000" alphawhennotoccluding="1.000000" />`. The Windows loader reads those properties in `Game/src/GameObjects/DrawableObject.cpp` lines 175–182. Its `DrawableObject::Update` (lines 48–113) tests whether player XY lies within the sprite's authored bounds, then lowers alpha by `1.5 * delta` per update toward 0.4 while inside and restores it toward 1 while outside. `Sprite::Draw_effectLightTexture` (lines 626–672) sends the current alpha to the shader, and the blend state in `Game/src/Core/Graphics.cpp` (lines 392–407) uses source-alpha-over. By contrast, `port/game/LevelScene.cpp` lines 375–377 parse only the static `<alpha>` value and lines 588–590 draw it unchanged; `UpdateVisuals` around lines 491–503 does not update occlusion alpha.

At the existing Linux `R:180` anchor, `run.log` reports player `(1368.99,3107.3)`. ID 6's authored center `(1339.985,3895)` and size `(1112.317,2743.384)` give unrotated bounds X `[783.827,1896.144]`, Y `[2523.308,5266.692]`; the player is inside. That establishes the branch condition for equivalent Windows world state (the source uses unrotated `Left/Right/Top/Bottom` in this check), not the precise Windows alpha at this instant because entry time/update history is not recorded. Once continuously inside for at least 0.4 seconds of normal updates, the source reaches 0.4; the port stays at 1.0. This can materially change the dark foreground/character visibility, but **cannot alone explain the upper green band** or prove a particular pixel without an ID-6 same-frame isolation capture.

**Other audited paths:** Source `GameObjectManager.cpp` lines 58–65 and 1022–1025 sorts descending by depth; port `LevelScene.cpp` line 385 also stable-sorts descending. Source `GameObject.cpp` lines 879–929 defines the same static depth-parallax factors used in port `LevelScene.cpp` lines 562–575. Source `BasicLightTexture.fx` samples texture times a normally white lightColor and alpha, so ordinary forest sprites are not subject to an additional scene-wide lighting treatment beyond the separately implemented sepia pass. However forest-1 also uses six `effectfoliagesway` sprites (IDs 41–46) and two `effectpixelwobble` fog sprites (IDs 119/122) in XML; port `LevelScene::Draw` currently ignores those per-sprite shader effects. They are confirmed animated-effect parity gaps, but do not establish the fixed horizontal band cause. Source's `GameObjectManager::ScaleObjects` scales object positions and dimensions for non-1920 backbuffers (`GameObject::Scale` defaults `scalePosition=true`), whereas the port's 2/3 projection maps authored 1920×1080 units into 1280×720. For a **matched 1920-original versus 1280-port normalized image** those are compatible; do not infer a geometry bug solely from different output sizes.

**Ranked next work:** (1) Implement the source's per-sprite occlusion fade for XML opt-in IDs 5/6 in the port scene state, with the same bounds test and `1.5*dt` alpha progression and same source update ordering; then compare a deterministic player-inside and player-outside route. This is a code-proven mismatch and high-impact foreground treatment. (2) Use the already-added off-by-default XML-ID filter for same-frame baseline/hide pairs for IDs 6, 17/4, 18/20/46, 38/39, and 40; ID 19 has already been found to affect only y405–466 in the current sepia capture, so attribution of the *upper* band must continue with other IDs. (3) Reproduce foliage sway/fog pixel wobble after foreground/band attribution if visual parity remains materially off. No XML or texture replacement is justified by the available original references.
