# Forest-1 oak leaf ParticleSpray slice (2026-10-22)

Source: `Game/XmlFiles/levels/forest_exploration_1.xml` ID 47 and `Game/src/Particles/{ParticleEmitterManager.cpp,ParticleSpray.cpp}`, plus `Game/ShaderFiles/Particle.fx`. The XML specifies four `oak_leaf.png` particles at `kGroundFront`, emitter center `(201.685,4334.996)`, spawn spreads `(370,40)` multiplied by ten in the original loader, downward direction, 3.5–4 speed, 6–40 second lifetimes, 64–92 size, 0.85–1 brightness, looping, 0.05 fade-in and 0.98 fade-out. Its 50,000×2,000 dimensions are the emitter culling region, **not** a drawable quad. The source's `randSpread` expression is discarded without assigning direction, so the authored `(0,-1)` direction remains.

The Linux port now loads this one authored emitter as four independently animated textured quads, with source-derived spawn, stepped motion, deferred warm-up, alpha/brightness, lifetime/recycle, and painter depth/order. Other particle effect types remain outside this slice. A private deterministic RNG replaces the Windows process-global `rand()` stream; individual leaf positions cannot be expected to match a Windows run. SDL sprite sampling/blending is also not a byte-exact emulation of `Particle.fx`'s sampler/filter and vertex shader. No matched Windows frame was available.

Verification: `port/tests/leaf_particle_test.cpp` compiled with `g++ -std=c++17 -Wall -Wextra -Werror` and passed. The port built successfully with the existing `deathleak-linux-build:bookworm` toolchain image. `port/build/leaf-particles-2026-10-22/` contains ignored same-frame BMP/log evidence. `baseline.bmp` and `baseline.log` are copies of the immediately preceding foliage-sway commit's physical-Xorg `R:180`/fixed-dt frame, frozen before this particle build. New `particles.bmp` and `hide-47.bmp` ran the same forest-1 route on Xorg `:0`; their logs report accelerated OpenGL, `software=0`, nouveau `NVE7`, 1280×720, and identical endpoint player `(1368.99,3107.3)` with five orbs. Hiding ID47 in the new binary yields **zero** RGB pixel differences against that baseline. Enabling the leaf emitter changes **689** RGB pixels in bounding box `(276,326,303,370)`—a small leaf-sized region, not the former giant emitter rectangle.

This is a bounded Linux implementation and same-frame attribution result, **not** a Windows visual-parity or release-acceptance verdict. The container did not expose an ALSA device, so the capture logs note audio unavailable; rendering remained accelerated on the physical GPU.
