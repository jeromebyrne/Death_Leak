# Forest-1 ID37 lower-band source/composition discriminator — 2026-10-22

## Finding

The near-black bottom band is **predicted by the original Windows source**, not presently evidence of a Linux-only dark overlay. Forest-1 XML ID37 is the 2048×512 `shrubbery.png` foreground parallax layer at world Y=2800, `kMiddleForeground`, alpha 0.95. Its source texture is black wherever covered, with opaque upper image rows and a transparent bottom image edge. The original quad's V orientation places that transparent image edge at the **screen top** of the projected quad, then increasingly opaque black toward the screen bottom. At the documented camera Y=3400 and 1280×720, 2/3-scale port projection, the quad starts near screen y=589.3. Thus a soft onset around y≈597 and an almost-black span near y≈700 are expected. A black texel at 0.95 source-over leaves roughly 5% of the prior scene RGB before postprocess; it does not require another occluder.

This is source-semantic attribution, **not** exact Windows/Linux pixel parity or approval of the full forest composition. The available Steam screenshot 14 is a different camera/state/time, and its JPEG/letterbox presentation is not a matched lossless renderer frame. The broad brighter/softer ground haze above the ID37 onset is a separate fog/state question; ID37 cannot explain all of it.

## Traceable contract

- **Authorship:** `Game/XmlFiles/levels/forest_exploration_1.xml:612-635` declares ID37 `ParallaxLayer`, `(1316.985352,2800)`, 2048×512, `repeatX=true`, `effectlighttexture`, alpha `.950000`, no sine/foliage/wobble, no flip, no occlusion fade, `followcamx=true`, `followcamy=false`, camera-X UV coefficient `.000690`, no auto-scroll. This is foreground art, not a Linux-added rectangle.
- **Texture coverage:** The existing direct RGBA asset audit in `port/LOWER_FOREGROUND_PARITY_2026-10-22.md` found black RGB with alpha 255 at x512 rows 64/128/256, alpha 219 at row 384, 56 at row 448, and 0 at row 511 of `Game/Media/levels/forest_exploration_1/shrubbery.png`. `port/ID37_PARITY_FOLLOWUP.md` also records all 2048 pixels on rows 64 and 128 as opaque black. The texture is therefore capable of an almost full-width dark lower band on its own.
- **Windows transform/effect:** `Game/src/GameObjects/ParallaxLayer.cpp:26-35` calls `Sprite::Update` then assigns followed camera X; `:37-100` replaces repeat-X with one UV span shifted by `-cameraX*.000690` and sets bottom/top vertex V=0/1 because Y parallax is off. Authored Y is retained. `Game/src/GameObjects/Sprite.cpp:626-637` supplies `m_world`, texture and `m_alpha` to `effectlighttexture`; `Game/ShaderFiles/BasicLightTexture.fx` multiplies sampled alpha by that value. `Game/src/Core/Graphics.cpp:392-405` uses source-alpha / inverse-source-alpha RGB blending; its depth function is always-pass (`:83`), so ordered draws determine overlap. `Game/src/GameObjects/GameObjectManager.cpp:58-64,1024` sorts descending depth.
- **Linux current path:** `port/game/LevelScene.cpp:1198-1269` draws authored sprites in depth order, follows current camera X for ID37, retains authored Y, applies the corresponding camera-X U shift as a single span, disables ordinary repeat tiling for X-parallax, and reverses ordinary SDL Y sampling. XML alpha is placed into `tint.a` when loaded (`:548-549`); `port/linux/SDLRenderer.cpp:209-210,247-265` applies that alpha modulation on the UV-wrap SDL copy with `SDL_BLENDMODE_BLEND` set at texture load (`:182`). `draw.opacity` is also populated but the ordinary SDL-copy branch uses `tint.a`, not `opacity`; this is not a missing-alpha defect for ID37 because `tint.a` already encodes `.95`.
- **Bounded timing caveat:** Windows `ParallaxLayer::Update` caches the world matrix before assigning followed X, whereas Linux draws at current camera X. Existing `port/ID37_CURRENT_HEAD_DRAW_STATE_2026-10-22.md` and controlled earlier GPU work predict/measured a transient ≈5.33-screen-pixel horizontal shift for the recorded 761.040→769.036 camera step, with unchanged UV phase and zero held-camera shift. It cannot create or remove a broad horizontal lower band. This is a narrow motion-parity issue, not a rationale to alter art, alpha, Y placement, or blend.

## Existing visual isolation and its limit

The saved same-frame physical-GPU forest-1 baseline/hide/only-ID37 set at `port/build/id37-parity-followup-2026-10-22/` uses deterministic `R:180`, 1280×720, accelerated OpenGL/nouveau GPU sepia and identical player state. `port/LOWER_FOREGROUND_PARITY_2026-10-22.md` independently measured 92,285 changed RGB pixels, bounded to `[0,597,1280,720)`, when ID37 is hidden. At `(640,700)`, baseline RGB is `(5,4,3)` versus hidden `(94,82,59)`; y590 is unchanged. The isolated-ID image darkens gradually downward. These controls prove ID37's contribution **within Linux** and agree with the original texture/geometry prediction. They do not provide a matched original Windows pixel sample.

Record the actual viewport/backbuffer, camera XY/zoom, ID37 world matrix and UV endpoints, plus post-shader RGBA or composited RGB; capture the same held state on Linux with only ID37 using the existing diagnostic ID filter. Compare (1) projected quad top/edges and UV orientation/phase, (2) the alpha ramp in fixed x=640 rows around 590–720, and (3) source-over RGB against an identical background after matching postprocess. **Falsifier:** if the Windows isolated layer is materially brighter, starts at another Y, reverses the alpha ramp, or differs in blend at matched state, trace that measured transform/sampling/blend residual to one operation before a scoped fix. If it agrees, close ID37 lower-band rendering as authored and investigate any remaining broader haze separately. Steam 14 or unmatched gameplay video cannot substitute for this test.
