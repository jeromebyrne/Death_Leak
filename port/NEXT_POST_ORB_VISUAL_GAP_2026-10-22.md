# Next post-orb active-gameplay visual gap — common ninja death spray (2026-10-22)

## Decision

At inspected HEAD `197ca04`, the highest-priority **distinct unrepresented visual event** I can substantiate after the forest orb trail is the **20-particle material/blood spray on an ordinary lethal arena-ninja hit**. The Linux port now renders ninja-specific ten-piece debris and five `explosion_lines.png` particles, but it never creates the *separate* `Character::OnDamage` material spray which Windows creates before `NPC::DoNinjaExplosion`. This is a missing player-visible event at a known combat kill route, not a claim that the current forest video has a blood-spray pixel mismatch. Priority is based on a definite omission, 20 image quads around the focal kill, and an existing deterministic arena stimulus; actual screen coverage is not measured.

This is **not** a second proposal for the already-audited ninja explosion-line growth/trajectory/fade errors (`NINJA_DEATH_EFFECT_SOURCE_QA_2026-10-22.md`, `NINJA_EXPLOSION_LINE_EXACT_CONTRACT_2026-10-22.md`), the ten debris pieces, combat painter order, modal/fog clocks, or orb trails. `NEXT_VISUAL_CONTRACT_POST_FOLLOWLAG_2026-10-22.md` mentioned common death particles as outside its ninja-specific implementation scope; this report isolates that still-absent layer and its gate.

## Source and port evidence

- The first arena authors a two-ninja `NPCTrigger` ID63 (`Game/XmlFiles/levels/first_ninja_arena.xml:1116-1124`). `NinjaSpawner::SpawnNPC` selects material `demon1` (`Game/src/GameObjects/NinjaSpawner.cpp:30-44`), whose sole active particle texture is `Media\\bloodparticle.png` (`Game/XmlFiles/materials.xml:492-496`); the PNG exists at `Game/Media/bloodparticle.png`. The spawn uses the ninja animation (`NinjaSpawner.cpp:90-101`). This is an authored arena event, not a hypothetical null-material branch.
- On a lethal `Character::OnDamage`, the ordinary `shouldExplode && mExplodesGruesomely` path calls `CreateDirectedSpray(20, ...)` **at `(character.X, character.Bottom()+30)`**, at `kPlayer` depth, using the material particle texture, direction `(0.2,0.8)`, spread `0.3`, 3200×2000 emitter bounds, speed 7–12, lifetime 0.8–1.5 s, particle size 10–40, gravity 1.4, non-looping, brightness 0.75–1, lifetime scaling toward 8, spawn spread 5×10, fade-in .15 and fade-out .8 (`Game/src/GameObjects/Character.cpp:1640-1690`). The factory and `ParticleSpray` paths turn that request into individually updated/drawn textured quads; the bounds are not one enormous visible quad. `NPC::OnDamage` calls `Character::OnDamage` first and only afterwards invokes `DoNinjaExplosion` when `mHasExploded && mExplodesGruesomely` (`Game/src/GameObjects/NPC.cpp:228-246`). Thus both particle groups accompany the same ordinary lethal ninja event. `GameObject::OnDamage` defaults `shouldExplode=true`; the projectile route does not override it (`Game/src/GameObjects/GameObject.h:159`, `Projectile.cpp:112,303`).
- Linux `Combat::DamageEnemy` increments kills and calls only `SpawnNinjaDeath` for a lethal `kNinja` (`port/game/Combat.cpp:184-205`). That method appends exactly ten debris entries and five explosion-line entries to `deathEffects_` (`:161-183`); `AppendPainterItems` draws those entries (`:571-582`). `Combat.h` has no material/blood spray collection, and the targeted `port/game/Combat.cpp` search found no `bloodparticle` load or common lethal emitter. The scene `ParticleSpray` collection admits authored XML/selected runtime-orb sprays, not combat's material spray (`port/game/LevelScene.cpp:272-323,705-830`). The omission is therefore not repaired by the existing generic spray renderer or the new ninja-specific effects.
- The existing arena integration trace for `--play Game/XmlFiles/levels/first_ninja_arena.xml --start-encounter 0 --script F:300 --fixed-dt 0.0166667` records two spawns and one kill (`ARENA_EXPECTATION_BASELINE_AUDIT_2026-10-22.md`). That is a deterministic **event-reachability** trace only; it does not prove the kill is on screen or quantify image coverage. The latest post-orb physical-GPU evidence is a 10 s active **forest-1** clip on accelerated Xorg/nouveau NVE7 with a faint orb breakup plume (`POST_ORB_TRAIL_GPU_REVIEW_2026-10-22.md`). It contains no arena kill and cannot accept/reject this death-spray gap. No matched original-Windows arena frame is available.

## Bounded next implementation and verification

Implement **only the common material spray for the first ordinary lethal arena `kNinja` hit**, once at the health crossing, alongside (not replacing) the existing debris/line queue. Resolve `demon1` to the shipped `bloodparticle.png` in this bounded route. Reuse the current per-particle textured draw/blend contract and unified depth painter, but create a separate 20-particle non-looping emitter at source `kPlayer=3000`, with source speed/lifetime/size/gravity/brightness/spread/fade/life-scale parameters above. Compute the spawn origin from the source character bottom/collision pose rather than substituting the debris origin `(enemy.x, enemy.y+50)`; verify source `Bottom()` semantics before choosing the exact port coordinate. Keep existing ninja debris and explosion-line behavior unchanged in this slice. Do not add player/ghost/skeleton death variants, audio, random slow motion, spawned orbs, or change XML/art.

Focused CPU gate: with a fixed deterministic *Linux-only* seed, cause one lethal and one nonlethal ninja hit; assert zero new material particles on nonlethal, exactly one 20-particle `bloodparticle.png` emitter on lethal, painter depth 3000, source parameter ranges, one-shot behavior on repeated/dead-target damage, and natural drain. Then, when the separate GPU owner is free, use the known arena kill route on physical accelerated display, log kill frame and enemy/camera position, and inspect pre-hit and immediate/0.5 s post-hit crops **only if the enemy is onscreen**. An isolated material-spray draw mask can establish Linux contribution. Exact Windows particle positions, alpha curves, and pixel parity require matched Windows camera, kill frame, renderer scale, material/RNG history, and effect age; the existing forest post-orb clip is not that comparator.

## Scope and uncertainty

This is source-backed event omission, not measured Windows/Linux visual parity or human acceptance. Source `Bottom()` placement, game-scale conversion, random sample sequence, and the practical occlusion of the blood texture remain verification points. No source, tests, build, game, GPU/display, shared checkpoint, or other audit file was changed in this lane; only this report was written. Unrelated worktree changes were preserved.
