# Damage-burst visual feasibility, bounded slice (2026-10-22)

## Verdict

No software edit was made. The source-equivalent per-actor RGB burst is feasible in the SDL/OpenGL backend, but **not cleanly implementable within this worker's permitted files** (`Combat.*`, `LevelScene.*`, `SDLRenderer.*`). The missing pieces cross two unowned interfaces: the backend-neutral sprite draw contract in `port/render/Renderer.h`, and the gameplay-to-scene player-hit integration in `port/linux/main.cpp`. Encoding gain into an unrelated `Sprite` field or introducing process-global Combat/scene state would make the result fragile rather than source-equivalent. Existing byte tint cannot encode gain above 1.

## Source contract and port evidence

- `Game/src/GameObjects/SolidMovingSprite.cpp:464-477` resets the burst start time only inside `mCanBeDamaged` on `OnDamage`.
- `Game/src/GameObjects/Sprite.cpp:626-672` uses elapsed time below `kBurstTintMaxTime` (0.25 s) to set `val = 5 - 16*elapsed`, then restores shared effect light color to white after this sprite. `Game/ShaderFiles/BasicLightTexture.fx:53-59` multiplies sampled RGBA by light color before blending and independently multiplies alpha by sprite alpha. The intended port gain is RGB-only with original texture/sprite alpha, saturating at the render target; it is not a whole-scene overlay.
- Accepted enemy hits are centralized in `Combat::DamageEnemy` (`port/game/Combat.cpp:146-166`); that method can reset an `Enemy` hit age. Enemy painter items are built in `Combat::AppendPainterItems` (`:490-510`). Player projectile damage is accepted in `Combat::Update` (`:422-433`), and solid-contact damage enters `Combat::ApplySolidContactDamage` (`port/game/Combat.h:68`) from `port/linux/main.cpp:697-698`. Both could reset a `Combat` player hit age.
- The player is rendered independently by `LevelScene::Draw` (`port/game/LevelScene.cpp:892-941`). Its signature takes only renderer/camera/player coordinates/painter items (`port/game/LevelScene.h:86-87`), not `Combat` or a player-hit gain. The caller in `main.cpp` must pass that state, or an equivalent explicit scene setter must be called there. Neither can be wired from the owned files alone without a global/sentinel workaround. Player body and its copied arm draw should share the same accepted-hit gain, while shadow and aim-line should not.
- `render::Sprite` has only byte `Color tint`, float `opacity`, and unrelated shader states (`port/render/Renderer.h:31-52`), and `Renderer::DrawSprite` has no gain argument (`:56-66`). `SDLRenderer::DrawSprite` applies `SDL_SetTextureColorMod` (`port/linux/SDLRenderer.cpp:173-190`), whose white byte value is already the ceiling. The existing `DrawPixelWobble` OpenGL path proves a per-sprite shader and SDL queue flush are technically available, but a dedicated gain parameter on the neutral draw contract is needed to convey RGB >1 without overloading opacity/tint/effect flags. The current renderer shader paths are conditional on SDL OpenGL; a software-only test cannot validate their pixels.

## Smallest clean ownership expansion and implementation

1. Permit `port/render/Renderer.h` to add `Sprite::rgbGain = 1.f`. At draw, only a value above 1 selects a dedicated per-sprite OpenGL fragment path: `sampled.rgb * rgbGain` with original sample alpha times `tint.a/255` (and authored opacity as applicable). Flush SDL before direct GL, preserve/restore GL program, texture, blend, projection, and viewport state as existing custom paths do. The white default keeps all neighbors unchanged. No global postprocess, art, or XML changes.
2. Permit `port/linux/main.cpp` to pass `Combat::PlayerDamageBurstGain()` to `LevelScene::Draw` (or explicitly set it on the scene immediately before drawing). Advance per-actor hit ages by gameplay `dt`, reset only on accepted positive damage, clear on level/reset, and assign gain `5 - 16*age` for `0 <= age < .25`, else 1. The player body/arm and each living/visible enemy receive only their own gain.
3. Add a focused deterministic test using a mock renderer to inspect actor gain at ages 0, .125, and .25, including reset on a second hit and unchanged neighboring sprite/alpha. Then build with the established Docker image. Physical-GPU acceptance remains a separate step: capture matched hit-age player/enemy crops on strict OpenGL GPU at 0, .125, >=.25 and a no-hit neighbor; compare to Windows, checking alpha edge and post-hit white reset. Do not infer visual parity from a software build.
