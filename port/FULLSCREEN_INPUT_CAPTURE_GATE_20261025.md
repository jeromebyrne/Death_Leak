## Real X pointer/click blocker

An authenticated XTest client successfully moved the X server root pointer to `(450,620)` and issued button-1 down/up (`XTestFake*` returned success; `XQueryPointer` confirmed the root movement). That coordinate should map to logical `(400,511)` in the centered 1280×720 content and land inside menu Options widget 1. During a live 1440×900 fullscreen menu probe, `renderer->Mouse()` instead stayed at logical `(0,-40)` with `leftDown=0` for all 176 logged frames; no `Menu mouse press/release` event occurred. The root window child under the pointer was `cinnamon-screensaver-main.py` (`0x422f439`) while the game's focus eventually became `Death Leak - Linux renderer slice` (`0x4c0000a`). The locked screensaver overlay intercepted the synthetic physical-root input; the game did not receive movement or clicks. The first 360-frame menu run also logged only `(0,-40)` and no click. This is an **environment/focus blocker**, not evidence that the game's coordinate conversion or click activation is defective or correct. We did not bypass the lock screen or modify the desktop session.
