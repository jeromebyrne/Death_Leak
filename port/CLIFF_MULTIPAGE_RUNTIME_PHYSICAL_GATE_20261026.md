# Cliff large-sprite multi-page runtime physical gate — rejected (2026-10-26)

Base: clean detached exact pushed feature ref `a0cd892f00c38c0cfa99219b64b50bc841087e11`. Primary dirty tracked/untracked work was not built, staged or edited except the separate append-only performance checkpoint. This slice built and physically tested an actual six-source, two-page ordinary virtual-texture mapping, then reverted it after exact-pixel failure. Default atlas coverage remains 15/896 PNGs.

## Eligibility and measured scene reuse

Authored `cliff.xml` has 25 unique non-repeat, non-pixel-wobble/non-foliage ordinary Sprite PNGs totaling 24,090,671 source-rectangle pixels, the only current level above one 4096² page in that broad static census. That total alone was not used as proof. A clean exact-ref Docker production build passed. An authenticated, hardware-accelerated physical X11/OpenGL Mesa nouveau NVE7 `--load-save` at cliff player `(0,-500)`, fixed dt 0.0166667 and 1280×720 output was traced for three presents. Warm frame GL texture uploads/draws confirm co-resident 3000×1000 sand textures, 4096×1434 cave underlay, 2097×736 cave overlay, 1230×1632 mill and 2048×2048 windmill blades. These are ordinary SDL draws at the site, but minification/rotation/source cropping still have exact-sampling obligations. Repeated warm full-frame trace: control 37 `glDrawArrays` / 114 `glBindTexture`, opt-in atlas 36 / 113. Two atlas page uploads appear in B. The one-call reduction per frame is measured, not a multi-draw batch or frame-time gain.

## Dense pages, virtual mapping and memory proxy

`port/tools/atlas_pack.py` packed bottom_sand, bottom_sand_cave, cave_underlay, cave_overlay, mill and windmill_blades with 2-pixel extruded edges and transparent guard, and verified reconstructed visible RGBA/source hashes. Page 0: 3895×3960, 12,954,125 visible-source pixels / 15,424,200 page pixels = 83.99% occupancy. Page 1: 3001×1248, 3,072,483 / 3,745,248 = 82.04%. Both are trimmed and below the 4096 ceiling. Two pages require 76,677,792 raw RGBA allocation bytes, compared with 78,474,880 source-rectangle bytes for six dedicated textures: theoretical -1,797,088 bytes if all dedicated copies disappear. This is an allocation proxy, not live VRAM. The 4096-wide underlay cannot fit with mandatory padding untrimmed; alpha-transparent cropping was necessary. A local opt-in `DEATHLEAK_ATLAS_CLIFF_LARGE=on` runtime branch used the new multi-page TSV lookup, selecting pages on demand; dedicated repeat/UV/private-shader fallback, source rect, tint, painter, blend and sampler logic were unchanged. Candidate Docker production build passed.

## Serial physical rejection

Strict serial NVE7 A/B/A at deterministic three-present `--level-preview Game/XmlFiles/levels/cliff.xml --fixed-dt 0.0166667` used the same candidate binary with the opt-in off/on/off. Controls were byte-identical full 1280×720 BMP RGB, SHA-256 `93fd976561629b9cb1e1cbf6aa290b7afe1fdf473b28bddfa31d6a5bd481c706`; B SHA-256 `40a50ef334f9014a8934936a01ae579073a8b6b7a3fe5db88dbcae68dcc8e29a`, differing at 15,676 pixels, bbox x=2..1279/y=0..719. All three runs reported x11/OpenGL, accelerated=1/software=0/vsync=1, NVE7, actual/logical 1280×720. Preview deliberately removes live gameplay/film-clock differences; it is a pixel oracle, not active-play acceptance.

Page isolation found all 15,676 changed preview pixels on page 0; page 1 alone matched at that camera, which does **not** prove page-1 visual parity. Individual page-0 mappings yielded bottom_sand 0, cave_underlay 240, mill 4,137, windmill_blades 11,318 changed pixels against the same control. The direct cause is not yet proven; changed normalized UV, trimming/guard and linear minification/rotation are plausible, and no arbitrary UV bias or filter downgrade is accepted. The separate active gameplay three-present A/B traces had unsynchronized endpoint `(0,-511.591)` versus `(0,-523.182)` due live timing and are used only for GL attribution, not full-frame parity. Query-off serial 300-present cliff-preview A/B/A present-interval p50/p95/p99 ms: A1 20.0397/22.4323/23.291, B 19.5068/22.6945/22.7856, A2 20.0831/23.2334/23.312. B p95 is worse than A1, and invalid pixels bar acceptance regardless of timing. These intervals include display pacing and do not establish GPU-time or sustained active-gameplay gain.

## Disposition and next distinct gate

**Reject the runtime B mapping and keep all six dedicated by default.** The isolated opt-in source/assets were removed before the report commit. The multi-page lookup format remains functional, but this candidate fails exact output and no new coverage, VRAM saving, FPS or release acceptance is claimed. To progress this measured family, isolate the exact SDL GL texture coordinates and bilinear sample footprints for cave_underlay, mill and blades in the matched physical preview frame; derive a source-coordinate-preserving mapping (or retain each failing source dedicated), then retest *both visibly sampled pages* at multiple camera positions before any default integration. If no exact sampling correction exists, select another physically co-resident family rather than packing unrelated fillers. Multi-page benefit cannot be inferred from density alone.

Evidence retained in `/tmp/deathleak-multipage-evidence/`: A/B GL traces and dumps, authenticated logs, BMPs, per-page/per-source isolation BMPs, serial timing logs, deterministic pack/manifest/TSV and rejected runtime assets. No test-only source or generated atlas is committed.
