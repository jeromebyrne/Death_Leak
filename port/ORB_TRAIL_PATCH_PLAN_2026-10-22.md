# Small CurrencyOrb tracking trail — minimal patch plan (2026-10-22)

Read-only plan; no implementation, build, or display changes. Scope is the small *authored* orb's looping tracking trail, not the large-orb collection burst or smash-spawned orbs.

## Patch sequence and exact seams

1. **Asset and ownership — `port/game/LevelScene.h`, `LevelScene.cpp::Load`.** Add a scene-owned `orbShatterTexture_` and a separate runtime-trail collection, e.g. `vector<{string orbId; ParticleSpray spray; bool attached}>`. Clear both at the existing reset around line 131. Load/cache `Game/Media/orb_shatter.png` through the local `textures` map and `renderer.LoadTexture` after that map is created, only when the scene contains eligible small orbs; report a deliberate load error if absent. The source material `flame_orb` has exactly this particle texture (`Game/XmlFiles/materials.xml:657-661`). Do not admit new XML `ParticleSpray`s or load inside a tick. Use `persistentId` as the stable attachment key; no pointer/index into vectors that may move.
2. **Trigger and factory — `LevelScene.cpp::UpdateAuthoredOrbs`, false→true branch around lines 695-698.** Immediately after hover and strict `dx²+dy² < 130²` test, set `orbTracking=true` and create exactly one trail at the *current hovered* orb XY. Keep the existing `continue` so no tracking motion occurs until the next tick. Guard creation by orb key even if the branch is re-entered. A focused factory beside this function can initialize `ParticleSpray` without modifying the XML parser: 15 particles, texture above, `depth=3250` (`kOrb`), 3200×1200 update bounds, speed 1.5–3.4, lifetime `0.35 - (0.25/15)*i` for i=0..14 (last ≈0.1167), size 40–80, gravity .5, brightness .8–1, looping true, `loopTime=-1`, `scalesByLifetime=true`, `scaleTo=.1`, fade-in .15, fade-out .8, initial independent signed X/Y direction samples, and initial 3×3 spawn spread. Initialize `drawX/Y` to spawn XY. Use a stable per-orb seed/private `ParticleSpray::Random`, not Windows global-rand claims. Source: `Game/src/GameObjects/CurrencyOrb.cpp:149-178,326-390`, `Game/src/Particles/ParticleEmitterManager.cpp:212-371`.
3. **Attachment/recycling — narrow seam in `port/game/ParticleSpray.h::Update`.** Permit an optional *current parent XY* only for runtime attached trails. At lifetime expiry, if looping and attached, reset `p.x/y` to that current XY; otherwise preserve existing `startX/Y` restart for XML sprays. Keep already-live particles on their independent trajectories. Critically, Windows `UpdateParticleToParent` at `Game/src/Particles/ParticleSpray.cpp:479-514` **does not reapply per-particle spawn offsets on recycle** (it even has a TODO), so spread applies at initial construction, not each attached restart. Offset is zero, making orientation tracking inert for this effect. Do not rewrite all particle positions each frame. Leave authored spray warm-up/update semantics intact.
4. **Tick and lifetime — `LevelScene.cpp::UpdateVisuals` around line 732.** After `main.cpp:690-694` has run orb motion and collection, resolve each attached trail's key to the post-motion orb XY, update its emitter position for zone gating, then call `Update(dt, parentXY)` once. A detached trail updates without a parent every tick until every particle is `dead`, even outside the camera update zone; then erase it. The original `ParticleSpray::Update` marks expired non-looping particles dead and removes an empty spray (`Game/src/Particles/ParticleSpray.cpp:287-335`). A source `-1` loop-time sentinel means no finite auto-stop; collection is the stop edge. Decide runtime warm-up intentionally: source defers `Warm` until first update; port currently draws pre-update `drawX/Y` and warms after its first update. Keep that timing for the new trail and cover first draw in a test.
5. **Detach — `LevelScene.cpp::CollectCurrencyOrbs` around lines 581-593 and `ApplyCollected` around 594-597.** On first collection mark the matching attached trail detached and `looping=false`, without clearing its live particles. Do the same if `ApplyCollected` runs on a live tracking scene. Save-restored collected orbs should never enter the spawn branch. `Load` and `main.cpp`'s `nextScene` replacement are hard boundaries: clear residual trails there. Do not let `SceneSprite::collected` suppress residual particle draws.
6. **Painter merge — `LevelScene.cpp::Draw` around lines 914-945, 1023-1026.** Do not append runtime trails unsorted to `particleSprays_`: `nextSpray` assumes depth/order sorting. Merge a second runtime stream at `kOrb=3250` or insert via a sorted keyed layer. Explicit tie rule: draw new trails **after pre-existing authored kOrb objects** (source appends the new GameObject then stable-sorts by depth in `Game/src/GameObjects/GameObjectManager.cpp:943-985,1022-1025`); preserve existing XML-spray order and dynamic-item depth behavior. Call existing `ParticleSpray::Draw`; a capture assertion should lock down the exact same-depth policy chosen for dynamic items.

Thus this minimal hook lights waterfall only unless the integration owner deliberately broadens the existing hover/tracking path to forest. Adding trails alone must **not** mark forest orbs tracking without its motion behavior; decide whether forest tracking parity is in this slice. No asset blocker: `Game/Media/orb_shatter.png` exists. Runtime texture handle, container, attachment restart, and painter merge are the implementation gaps. Same-depth tie against independently supplied dynamic painter items is not fully represented by the current port API; choose and capture-test a deterministic rule rather than claiming exact Windows insertion chronology.
