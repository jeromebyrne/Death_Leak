# Foliage-sway / pixel-wobble orientation audit — 2026-10-22

## Source contract and finding

`Game/src/GameObjects/Sprite.cpp` (`RecalculateVertices`, source vertices 0–3) places `(u,v)=(0,0)` on the bottom-left world vertex and `(0,1)` on top-left; the D3D camera projects world Y upward. `Game/ShaderFiles/FoliageSway.fx` passes that UV through unchanged while displacing each vertex in world XY, first X then Y, with the authored per-corner `NORMAL.xy` values. An authored vertical flip belongs to the World transform, so it swaps which vertex/UV reaches the screen top. D3D/PNG V=0 samples the first image row, making ordinary unflipped source sprites display that row at the **screen bottom**.

Linux `port/linux/SDLRenderer.cpp::DrawFoliageSway` already selected the right geometric top/bottom corners after authored flips and reproduced the shader's ordered world-space displacement (`FoliageSwayWorldVertex`). Its `SDL_RenderGeometry` UVs were inverted relative to those corners: unflipped screen-top received V=0 rather than the source's V=1, and flipped screen-top received V=1 rather than V=0. This is a concrete shader-path image-orientation defect, independent of the earlier plain-sprite/parallax UV fix at `60faa5e`.

The bounded correction sets foliage screen-top/bottom UVs to `(1,0)` unflipped and `(0,1)` vertically flipped via `FoliageScreenV`, without changing XML, texture assets, ID37, geometry, sway phase/intensity, repeat-X, draw order, or other render paths. The focused host test covers all four screen-edge/flip combinations and the existing ordered sine displacement.

Pixel wobble is different: `Game/ShaderFiles/BasicLightTexture_PixelWobble.fx` perturbs the source UV in order (V first; then U using the modified V), with wrapped sampling. Linux `DrawPixelWobble` supplies source V=1 at unflipped screen-top, V=0 at flipped screen-top; its GLSL applies the same ordered equations before converting source V to GL `1.0-uv.y`. With SDL's uploaded PNG first row at texture T=0, that conversion keeps the source image orientation and flips the *sampled* result as authored. No additional pixel-wobble orientation defect was proven, so none was changed.
