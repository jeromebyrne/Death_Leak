## Original Windows contract, including phase

- `Game/src/GameObjects/Player.cpp:39,998-1028,1103-1127`: only `IntroCutscene1` and raw held Interact accumulate `mCurrentTimePullingSword += delta`. Once that *post-increment* value is **strictly greater** than 2.75 s, the code zeros it, switches to `IntroCutscene2`, resets zoom to `mCameraZoomOnLoad`, emits the separately owned burst and returns **before** the shake request. Every still-held update at or below the threshold calls `DoShake(5.0f * (heldSeconds/2.75f), 0.1f)`, then applies the zoom decrement `delta*0.05` with floor `0.75*loadZoom`. An unheld update zeros pull progress, recovers zoom at `delta*0.10`, and makes no shake request (`:1129-1148`). Phase 2 makes no new request. Release/threshold does **not** cancel an already active 0.10-s shake; it simply permits its natural expiry.
- `Game/src/Core/Camera2D.cpp:120-167,297-307`: `DoShake` refuses requests while active. Accepted amplitude is therefore latched from the first eligible held update after the previous shake expires; it does **not** ramp continuously within a shake. `Update` first constructs the view from the current stored camera position, then checks expiry (`start + duration - currentTime <= 0`) or adds `± intensity * (remaining/duration) * timeModifier` to stored X/Y, independently, only for followed axes. It consumes one `rand()%2` for X before Y, only if that axis follows. The displacement becomes visible via a later view sample after follow/lag, not by offsetting the current already-snapshotted view or the HUD.
- `Game/src/Game.cpp:153-162,175-184,257-259` places camera follow/bounds before object/Player update and camera `Update` after it. `Game/src/program.cpp:163-175` increments total clock after `Game::Update` and before rendering. Thus the same update's accepted start uses the pre-increment clock; camera `Update` may perturb stored position immediately, but the current rendered view is the pre-perturbation snapshot. At a fixed 60 Hz, the first accepted update has intensity about `5*(1/60)/2.75 = 0.0303` world units; the next accepted start is after the prior 0.10-s expiry, subject to float/strict-boundary behavior. Do not impose a hard-coded six-frame cadence.
- `Game/XmlFiles/levels/forest_exploration_1.xml:3` authors zoom 1, follow-X true, follow-Y false, X lag 15, Y lag 7. In that level the source shake perturbs stored X only. At zoom `z`, a world-space horizontal displacement appears at approximately `(2/3)/z` logical screen pixels per world unit at the 1280×720 port viewport, before follow/rounding/parallax. Zoom changes projected amplitude but **must not** multiply the stored world-unit shake. Original `Camera2D::SetZoomLevel` changes orthographic extents, not `DoShake` intensity (`Camera2D.cpp:262-280`).
