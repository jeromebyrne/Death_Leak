# Ninja lethal debris/spray source QA — 2026-10-22

Scope: read-only comparison of committed `bbc113b` against original Windows C++ and authored PNG metadata. No build, display/GPU, or integration tests. The authored ten debris texture selections, duplicate counts, speed multipliers, native PNG dimensions (74×35, 58×75, 59×30, 32×32, 64×64, 32×32, 64×64), and five `explosion_lines.png` entries match `Game/src/GameObjects/NPC.cpp:524-578` and `port/game/Combat.cpp:116-123,162-181`. The following are **source-level visual mismatches**, not pixel-capture findings.

1. **Explosion-line quads do not grow and have a different opacity curve.** Original call enables `scalesByLiveTime=true`, `scaleTo=16`, fade-in fraction `.05`, fade-out fraction `.1` (`Game/src/GameObjects/NPC.cpp:541-565`). The original particle update enlarges `Size` from `StartSize` toward `StartSize * m_scaleTo` throughout life (`Game/src/Particles/ParticleSpray.cpp:269-283`), and computes fade over lifetime fractions (`:235-258`). The port fixes each quad at 40–120 world units until its last `.1s`, then shrinks and fades it (`port/game/Combat.cpp:177-181,573-580`). At the Windows reference 1920×1080 game scale of 1 (`Game/src/Game.cpp:142-143`), this materially changes the characteristic expanding flash. The source lifetime values are also deterministic `.7,.62,.54,.46,.38s` (`Game/src/Particles/ParticleEmitterManager.cpp:435-440`), versus port `.3,.4,.5,.6,.7s` (`port/game/Combat.cpp:181`).
2. **Explosion-line trajectory is too slow and includes impossible directions.** Original direction is `(0,0)` with nonnegative random spread `<.1`; speed is `3.5–5` per target tick (`Game/src/GameObjects/NPC.cpp:544-550`; `Game/src/Particles/ParticleEmitterManager.cpp:430-433,490-500`), so all five travel right/down in source world coordinates. Port's fixed spread runs negative through positive and produces left/up as well as right/down, at only a fraction of the source speed (`port/game/Combat.cpp:179-181`). This is a geometry/motion mismatch independent of rendering.
3. **Debris persist/fade on a timer instead of terrain contact.** Original `Debris` enters fade-out when it collides with a solid line (`Game/src/GameObjects/Debris.cpp:155-163`), then shrinks over the last `.2s` of the collision-triggered fade (`:80-103`). Port unconditionally expires at 4.2s and shrinks/fades during its final `.2s`, without terrain collision (`port/game/Combat.cpp:172-173,219-231,573-580`). Pieces can visibly disappear in midair or remain after landing, depending on terrain.
4. **Emission gate is broader than the original.** Original `DoNinjaExplosion` only creates these visuals for an animated NPC whose animation file is `ninjaAnimation.xml` (`Game/src/GameObjects/NPC.cpp:524-529`); it is called after `mHasExploded && mExplodesGruesomely` (`:228-243`). The port emits for every lethal `enemy.type == "kNinja"` (`port/game/Combat.cpp:201-204`). This only matters if a `kNinja` uses different/no animation or an otherwise non-exploding kill route; it is not evidence of a mismatch in the currently authored arena.
