# First-rain lightning / rain overlap — physical GPU, 2026-10-22

## Scope and setup

This is a bounded visual verification of committed `50ba9e9` (`port/linux/main.cpp`, `WeatherLightning.h`, `WeatherRain.h`), not a Windows comparison. I read the current status tail and `port/RAIN_GPU_PARITY_FOLLOWUP_2026-10-22.md`. Before each capture, process inspection found physical Xorg `:0` and no competing game, build or FFmpeg. Each run was sequential in `deathleak-linux-build:bookworm`, with host `/dev/dri`, X11 socket and LightDM Xauthority, `DISPLAY=:0`, SDL `x11`/`opengl`, and dummy audio. Logs all report strict SDL accelerated OpenGL (`accelerated=1 software=0`), nouveau/NVE7, GPU Sepia postprocess, 71 authored sprites / zero missing assets, and the identical grounded forest-1 endpoint `(-43.0146,3206.9)`, one orb. The logged `elapsed` values (~75–76 s) are wall-clock durations, **not** simulated weather time.

Each fresh process used `--play Game/XmlFiles/levels/forest_exploration_1.xml --script .:3604 --frames 3604 --fixed-dt 0.05 --capture <BMP>`. Float32 repeated-step calculation gives weather elapsed ~180.1564 s *after* frame 3603 and ~180.2064 s after frame 3604. The source/port order is rain begins on the first update with pre-update elapsed strictly greater than 180 s (frame 3601), schedules the first flash on the next rain update (frame 3602), and begins nonzero flash alpha on frame 3603. At captured frame 3604, port alpha is approximately 0.749985, quantized to 191/255; `WeatherLightning.h` uses the source's 0.4 s fade. This is the **first** authored rain-session lightning flash, not a later randomized flash.

## Painter/source interpretation and limits

The Windows source `WeatherManager.cpp` creates the `lightning_layer.png` parallax object before the rain directed spray, both at weather-foreground depth 20; `UpdateRaining` begins the 0.4 s alpha fade on the update after flash scheduling. Port `main.cpp` appends the flash painter item before the rain item; `LevelScene.cpp` uses stable same-depth dynamic ordering. At initial rain creation, `WeatherRain.h` places particles at the authored offscreen placeholder `(99999,9999)` and they enter the camera on first expiry (lifetimes 0.7–0.85 s). The first flash ends before that initial particle expiry, which explains the byte-identical no-rain discriminator. **The desired visible rain/lightning overlap does not occur on the source-authored first flash**, so no source-proven painter-order defect was found or fixed. A later flash during established rainfall would be the appropriate visible overlap discriminator, but is outside this first-flash bounded run.

The flash is a physical-GPU port result, not matched Windows pixel parity or Jerome visual acceptance. The original uses a process-global `rand()` stream and D3D `effectlighttexture`; this port has independent deterministic RNG and its current OpenGL sprite/postprocess approximation. Audio is outside scope. No source files, shared status/checkpoints, or commits/pushes were changed.
