# Next current-tree visual gate — right-stick aim-line orientation (2026-10-22)

**Finding at HEAD `19c28af`:** the player aim-line remains horizontal and attached according to movement-facing in Linux even when live right-stick input fires a diagonal or opposite-side shot. This is a recurrent focal active-play composition error for controller aiming, not a broad forest-atmosphere mismatch. The latest verified forest-1 footstep video (`port/build/footstep-qa-gpu-2026-10-22/forest-1-footstep-current-head-10s.mp4`, capture HEAD `e2c5adf`; `FOOTSTEP_QA_GPU_REVIEW_2026-10-22.md`) shows active player/aim-line gameplay, but uses scripted `B:300,F:99700`, **not right-stick input**; it cannot measure this defect. The later commits through `19c28af` add controller shot aim and footstep effects, without changing the aim-line transform below. No Windows/Linux pixel delta is claimed.

**Exact contract:** Windows `Game/src/InputManager.cpp:374-395,400-420` normalizes right-stick `(RX,RY)`, calls `Player::SetAimLineDirection`, and attempts a shot while either component exceeds the 8689 deadzone. `Game/src/GameObjects/Player.cpp:661-697` sets the line's angle, vertical flip and X attachment sign from that vector; `:345-365` holds its alpha during strafe and fades it afterward. Linux `port/linux/main.cpp:691-706` already supplies the right-stick vector to `Combat::Update`, so knives can launch diagonally. But `port/game/LevelScene.cpp:1077-1085` refreshes the line only for `eligibleFireAttempt` and stores `facing`; `:1224-1227,1279-1283` attaches/flips from that stored movement-facing sign and uses the XML rotation, never the right-stick angle. `port/game/LevelScene.h:162-165` exposes no aim vector to `UpdatePlayerVisual`. Consequently a diagonal shot and its visible aim mark can disagree in the same frame; opposed-stick aim can attach the mark on the wrong side. `STRAFE_AIM_LINE_SOURCE_CONTRACT_2026-10-22.md` previously identified this contract; this gate confirms it remains open at current HEAD, rather than nominating a new fog/particle/parallax change.

**Bounded next implementation:** after the scene-file owner is clear, pass the already computed right-stick aim vector/active flag from `main.cpp` to `UpdatePlayerVisual`; derive line rotation, vertical flip and ±5 X attachment from the four `Player::SetAimLineDirection` quadrants, retaining existing 400×400 art, depth, alpha/fade timing, painter order, body-facing, projectile physics and camera behavior. Check D3D-to-SDL angle/UV convention in a draw spy before selecting the final sign; no speculative global rotation fix.
