# Rotated ordinary repeat-X renderer design — read-only handoff (2026-10-23 23:53Z)

## Scope and source proof

This is an implementation design, **not an implementation or a measured parity result**. No source, tests, build, Docker, GPU, shared status, or checkpoint changed. The preceding source gate is `PRIVATE_WATCHDOG_WATERFALL_POSTSNAP_DISTINCT_EFFECT_SOURCE_GATE_20261023T2352Z.md`.

Waterfall XML ID17 (`Game/XmlFiles/levels/waterfall_top.xml:357-370`) is a non-native ordinary ground sprite: 2377.010986×1024 world units, `ground.png` 734×1024, `repeatX=true`, authored X flip, 0.089953-rad rotation. ID18 is similar but unflipped. Windows `Sprite::RecalculateVertices` (`Game/src/GameObjects/Sprite.cpp:215-234`) assigns U=0 to the left and U=dimensions.X/textureDimensions.X to the right **before its world transform**, even when rotated. `BasicLightTexture.fx` uses wrap in both axes, MIN_LINEAR/MAG_POINT/MIP_LINEAR, source alpha. Thus ID17 U span is about 3.2384, with its *whole-quad* X reflection reversing the U direction and placing the fractional repeat at the reflected edge.

Linux `LevelScene.cpp:1388-1448` passes projected destination, repeat flag, X flip and corrected rotation; `OrdinarySpriteRotationDegrees` encodes the authored reflection/rotation sign convention. `SDLRenderer.cpp:246-280` only tiles ordinary repeat-X when `rotationDegrees == 0 && !sourcePtr`, so ID17 falls through to one whole-texture `SDL_RenderCopyExF`. The existing `RepeatX.h` zero-rotation tiler is intentionally viewport-culling and phase-aware but its screen-X-only cull cannot be reused for rotated quads. The old pre-snap frame424 packet documented in the source gate is Linux admission evidence only. **There is no matched source-built Windows frame or post-snap same-state pixel comparator**, so this is source-contract discrepancy, not an observed Windows/Linux residual.

## Minimal implementation seam once assigned

Add one narrowly dispatched branch to `SDLRenderer::DrawSprite`, in the existing ordinary-copy chain after higher-priority effect arms and before the zero-rotation repeat tiler:

- Eligible only for `sceneSamplingPhase_ && sprite.repeatX && sprite.rotationDegrees != 0 && !sourcePtr`, with valid finite positive authored/projected dimensions, valid texture size, desktop SDL `opengl` context, and no conflicting custom effect arm. Keep existing dispatch for all other sprites, including parallax, wobble, foliage, damage and zero-rotation tiler. Do not special-case texture path or XML ID; ID17/ID18 are fixtures.
- Use one **private full-image GL texture** with repeat-capable sampler, at this painter slot. The existing cached `WobbleMipTexture(sprite.texture)` PNG upload already provides exact NPOT dimensions, bottom-first rows, complete mips and GL repeat; either reuse it with state-safe parameter override or factor a neutral private repeat texture helper. Do **not** set `GL_REPEAT` on an SDL-bound atlas/padded texture: `SDL_GL_BindTexture` can expose a sub-unit UV span/implementation-owned allocation and repeating it can sample neighbors or padding. Verify desktop GL NPOT repeat+mipmap support and successful upload before drawing. If unavailable, report non-parity/legacy fallback explicitly; never mark a stretched copy as a successful repeated draw.
- `SDL_RenderFlush(renderer_)` before private GL, preserving draw order. Set logical 1280×720 orthographic projection, standard source-over alpha blend, color modulation = sprite tint RGB and `(tint.a/255) * sprite.opacity` (the private texture is unmodified), depth off, texture env modulate; sampler U=`GL_REPEAT`, V=`GL_REPEAT`, min=`GL_LINEAR_MIPMAP_LINEAR`, mag=`GL_NEAREST` to match the ordinary D3D sampler as closely as available. Unlike SDL's one-mode `SDL_SetTextureScaleMode`, this keeps min/mag distinct. Check/create context only on SDL desktop `opengl`, not `opengles2` fixed-function assumptions.
- Form **one rotated quad**, not independent rotated copies. Let `destination = ProjectWorld(authoredDestination)`, `R = authoredDestination.w / (textureWidth * 2/3)` (equivalently projected width divided by projected one-source-width; do not divide projected width by an unzoomed tile width). Its local corners are `(-w/2,-h/2), (+w/2,-h/2), (+w/2,+h/2), (-w/2,+h/2)` around the projected destination center, rotated by the already-corrected `sprite.rotationDegrees` via the same `x cos - y sin, x sin + y cos` screen-space equations used by `DrawRaftMipExperiment` / `DrawDamageBurst`. No second flip of positions: flip is represented by UV labels, and the angle has already been corrected by `OrdinarySpriteRotationDegrees`.
- UV X labels: unflipped `uLeft=0,uRight=R`; flipped `uLeft=R,uRight=0`. **Do not** use `1,0` for a flipped quad, restart U at the viewport edge, or flip each unit tile independently: those all move the ~0.2384 fractional repeat to the wrong edge. UV Y labels on the private bottom-first PNG use `vTop = sprite.flipY ? 0 : 1`, `vBottom = 1-vTop`, consistent with `DrawRaftMipExperiment`; `sprite.flipY` here is the SDL-space flag already inverted for ordinary XML sprites in `LevelScene`. For ID17 authored verticalflip=false, draw.flipY=true, hence top V=0; ID18 has the same V convention. Confirm the actual existing ordinary SDL copy orientation with an asymmetric test image rather than assuming raw XML flipY directly maps to GL V.
- Restore GL program, matrix mode/stacks, active texture and binding, sampler state (or private-object settings as appropriate), blend/scissor/viewport and all modified fixed-function state before returning to SDL. Follow the nearby parallax/raft patterns but check `SDL_RenderFlush` and GL texture allocation failures before claiming a draw. Keep instrumentation of backend mode, U endpoints, texture dimensions and painter slot optional/diagnostic, not a per-frame log.

### Clipping and phase

The GPU viewport clips the rotated quad; no per-tile scissor or axis-aligned screen-X trim is needed. If optimization is later warranted, cull using the **four transformed corners** or inverse-transform the viewport into local quad space, retaining global local-X/U phase. Never call current `ForEachRepeatXTile` with the rotated sprite's screen X: it assumes unrotated rectangular tiles and can drop visible corners, particularly when flipped. A standalone sprite-level cull already runs in `LevelScene` (`SpriteMayIntersectViewport`). Leave source alpha and painter order intact; do not add an opaque fill or clip to the unrotated destination rectangle. Ensure rendering to resized physical output still uses SDL's logical viewport/scissor state after a flush; a GL viewport reset or incorrect scissor could clip the rotated extremities or leak into letterbox bars. An implementation should inspect SDL's current viewport/scissor or explicitly restore it, and verify with a non-1280×720 window.
