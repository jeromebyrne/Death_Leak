# Y-autoscroll exact draw eligibility — read-only source design (2026-10-24 03:37Z)

## Decision

Moving `autoScrollYPhase` mutation after the present `SpriteMayIntersectViewport` call repairs the definite **pre-cull drift** but is **not sufficient for exact Windows draw/phase parity**. The port's inclusive rotated rendered-quad AABB is a different predicate from `GameObjectManager::Draw` plus `Camera2D::IsObjectInView`: Windows checks positive alpha, a strict origin test, then strict bounds overlap, with a special *pre-scale square* for every nonzero rotation. The exact Windows-style predicate should gate both autoscroll phase mutation and sprite submission when faithful admission is the objective. Keep diagnostic filters, collected-object state, and other port-only omissions as separate conditions; do not mistake them for Windows camera eligibility. This design composes with the process-wide preceding-render clock correction in `PRIVATE_WATCHDOG_AUTOSCROLL_CROSS_SCENE_CLOCK_DESIGN_20261024T0332Z.md`.

## Source-backed predicate

`GameObjectManager::Draw` skips null/non-drawable objects; then calls `ApplyChange` if required and `Draw` **only if** `Alpha()>0 && (Camera2D::IsObjectInView(obj) || IsPlayer())` (`Game/src/GameObjects/GameObjectManager.cpp:302-330`). A `ParallaxLayer` is not the player. `Camera2D::IsObjectInView` returns true unconditionally in debug level-edit mode; normal play uses camera center `(cx,cy)`, dimensions `(cw,ch)`, object current position `(x,y)`, current object-parallax offsets `(ox,oy)`, current dimensions `(w,h)`, and current rotation angle `r` (`Game/src/Core/Camera2D.cpp:39-81`; `Game/src/GameObjects/GameObject.h:108-151,221-222`). Let `L=cx-cw/2`, `R=cx+cw/2`, `B=cy-ch/2`, `T=cy+ch/2`. The **exact branch structure** is:

```
origin = (x-ox > L && x-ox < R && y-oy > B && y-oy < T)
if (origin) inView = true
else {
    halfX = (r == 0 ? w : largestPossibleWidth) / 2
    halfY = (r == 0 ? h : largestPossibleHeight) / 2
    right  = x + halfX - ox
    left   = x - halfX - ox
    top    = y + halfY + oy  // intentional Windows + sign
    bottom = y - halfY - oy
    inView = (right > L && left < R && top > B && bottom < T)
}
eligible = drawable && alpha > 0 && (inView || isPlayer)
```

Do **not** silently normalize the `top + oy` asymmetry to `-oy`, replace `r==0` with an epsilon, or make edge comparisons inclusive. For ordinary `ParallaxLayer`, `mObjectParallaxEnabled=false` and offsets initialize to zero (`Game/src/GameObjects/ParallaxLayer.cpp:6-24`; `Game/src/GameObjects/GameObject.cpp:21-34,173-185`), so the offset asymmetry is latent for these authored layers but is part of the original predicate. `GameObject::Initialise` sets **both** largest-possible dimensions to `max(w,h)` before level-wide `ScaleObjects`; `GameObject::Scale` scales current position and dimensions but does not update that stored square (`Game/src/GameObjects/GameObject.cpp:80-119,454-469`; `Game/src/GameObjects/GameObjectManager.cpp:183-201,438-465`). Hence at a 1280x720/1920x1080 scale the rotated square remains in pre-scale authored units while `x,y,w,h` become scaled; this is not `abs(cos r)*w+abs(sin r)*h`. Read actual runtime values if the Windows loading/scale sequence changes. `ParallaxLayer::Update` may replace current x/y when following camera (`ParallaxLayer.cpp:27-36`), so use current cull position, not a stale XML position or the port's `followWorldX` render-transform cache.

The port currently builds a render sprite from `worldX/worldY`, screen destination, alpha and effective rotation, then increments Y phase, then invokes `SpriteMayIntersectViewport` (`port/game/LevelScene.cpp:1372-1456`). That cull admits a screen-space quad whose **edges may equal** 0/1280 or 0/720 and whose half-extents are trigonometric (`port/render/ViewportCull.h:10-24`). The port's `draw.opacity=object.alpha` is not a pre-draw alpha gate (`LevelScene.cpp:1418-1455`). Preserve phase as each object's own stored state; `ParallaxLayer::Draw` changes stored vertex V only once the manager has admitted the object (`Game/src/GameObjects/ParallaxLayer.cpp:108-161`). Neither actual raster survival nor occlusion is a mutation prerequisite.

## Boundary/rotation/alpha countercases

* **Boundary:** An unrotated object's right edge exactly equals camera left, with origin outside, fails Windows `right > L`; the port's `centerX+halfX >= 0` admits the touching quad. With alpha positive and nonzero prior delta, post-cull mutation still adds a spurious phase step and submits a command. Identical strict logic applies to other edges. An origin exactly on an edge fails the origin branch, but bounds may still overlap and admit it; do not equate `origin=false` with `inView=false`.
* **Rotation:** For `r!=0`, Windows uses the stored max-dimension square regardless of angle, not the rotated quad AABB. A long thin sprite can be admitted by that square when its actual rotated screen quad is fully outside. At the current uniform 2/3 scale with matching centers and zero offsets, that pre-scale square conservatively contains the rendered rotated quad; do not invent a reverse disagreement without a differing position/offset or scale state. At `r=0` Windows switches to current rectangular dimensions abruptly, whereas the port's trig AABB varies continuously. Flips affect the port's effective rotation but not Windows' branch choice (`port/render/OrdinarySpriteRotation.h:5-11`). Evaluate Windows cull with the authored/current **Windows angle**, not SDL degrees.
* **Alpha:** `alpha==0` (and negative alpha if ever present) suppresses Windows `Draw` and V mutation even when spatially in view. Port presently mutates and may submit; its loader clamps XML alpha to `[0,1]`, but runtime alpha can change (`port/game/LevelScene.cpp:563-565,1418-1455`). Use `object.alpha > 0.f` before increment. A tiny positive alpha still passes the manager even if later quantization/transparency yields no visible pixel. For the currently enabled waterfall Y layers, saved XML alpha is positive per the prior source-gate inventory, so zero-alpha is a regression edge, not a claimed recorded mismatch.

## Correction layout for implementation owner

1. Materialize an original-style, CPU-only `WindowsCameraAdmission` helper for Y-autoscroll sprites (or drawable sprites if broadening deliberately) taking a snapshot of *current Windows-equivalent* position, dimensions, rotation, largest-possible pre-scale dimensions, offsets, alpha, and camera center/dimensions. Use the exact branch/predicate above. At the current uniform 2/3 port scale, convert authored-world camera/object position and current dimensions into Windows backbuffer coordinates consistently, but retain the pre-scale square in its original units; do not simply feed the 1280x720 port destination into the helper. Validate this mapping against a Windows same-state command trace before declaring equivalence. If runtime scale/follow transforms make those inputs unavailable, store/reconstruct them explicitly instead of approximating with `SpriteMayIntersectViewport`.
2. In `LevelScene::Draw`, apply existing port-specific object/diagnostic skips first. For an authored Y layer, compute exact admission **before** phase mutation; on rejection, continue with phase unchanged and no sprite command. On acceptance, increment once with that sprite's scaled authored speed and the **process preceding-render modified delta** (not the scene-local slot), wrap/assign `draw.uvShiftY`, then submit. Keep sprite order, texture and color construction unchanged. For non-Y sprites, changing global culling is a separate visual-policy decision. If the implementation retains `SpriteMayIntersectViewport` for accepted Y sprites as a second rejection, it can suppress a Windows-admitted command and must not be treated as exact parity; use it only as a diagnostic comparison or where proven equivalent.
3. `ApplyChange` is manager-side before `ParallaxLayer::Draw`; its effect does not justify mutating V on rejected sprites. Diagnostic object filters must be off in parity traces. Treat debug level-edit force-in-view and player bypass explicitly if the helper is ever generalized beyond normal-gameplay layers.

## CPU-only oracle and external gate

Use a pure predicate table (no renderer/GPU): origin strictly inside; origin on each edge with (a) bounds overlapping and (b) bounds only touching; unrotated right/left/top/bottom equality; just-inside/just-outside epsilon around each boundary; nonzero angle with a long thin rectangle and its pre-scale max square; `r=0` versus tiny nonzero `r`; nonzero X/Y offsets including the `top + oy` quirk; alpha `0`, small positive, and positive with diagnostic filter disabled. Compare the helper to a literal independent translation of `Camera2D.cpp`, not to port `ViewportCull.h`. Include at least one case where `SpriteMayIntersectViewport` disagrees, proving simple post-cull mutation insufficient.

Then command-capture a Y layer (e.g. top ID15) through N offscreen renders and its first admitted render. Log scene/object ID, camera and Windows-equivalent current object inputs, alpha, origin/bounds branch results, original-style and port viewport results, process prior delta, eligible draw count, phase before/after, and submitted command UV. Assert no phase mutation/no command on Windows-ineligible draws and one increment `speed * (720/1080) * .001 * (priorDelta*60)` on each eligible draw, modulo one within float tolerance. Add the touching-boundary, rotation-square and zero-alpha sequences; explicitly test a Windows-admitted/port-culled case so the second cull does not erase the accepted command. Verify a cross-scene first eligible draw with nonzero process prior delta using the separate clock design. A matched-state **original Windows command** capture is still required to validate coordinate/state mapping and residual parity; only matched original pixels could support a visible-fidelity claim.
