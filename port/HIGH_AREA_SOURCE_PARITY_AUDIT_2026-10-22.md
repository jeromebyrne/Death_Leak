# High-area source parity audit — 2026-10-22

## Boundary and verdict

Source/read-only comparison of the CPU draw-spy states in `HIGH_AREA_DRAW_SPY_2026-10-22.md`; no build, capture, raster test, code edit, or shared-status edit. The spy proves the selected IDs are submitted in painter order, not that their pixels match Windows. I found **one narrow source-backed sampling omission** for the minified scrolling fog (waterfall IDs 117/118/119/121): the original pixel-wobble shader requests mip-linear minification, while the Linux pixel-wobble path forces base-level `GL_LINEAR` sampling. This is a render-path contract gap, **not** proof that any specific unmatched frame or visible high-area landmark is caused by it. The waterfall curtain IDs 13/14 are slightly magnified in the spy state, so this omission is not evidence for their current appearance.

IDs 13/14 use the pixel-wobble route (`port/game/LevelScene.cpp:538-540,1258-1261`), whose shader preserves the original Y-then-X sine order (`Game/ShaderFiles/BasicLightTexture_PixelWobble.fx:56-64`; `port/linux/SDLRenderer.cpp:597-609`). ## One concrete missing visual behavior: mip-linear filtering of minified fog

`Game/ShaderFiles/BasicLightTexture_PixelWobble.fx:13-19` declares `MIN_LINEAR_MAG_POINT_MIP_LINEAR` with wrap on both axes. Original `Sprite::Draw_effectPixelWobble` binds that shader for the selected fog (`Game/src/GameObjects/Sprite.cpp:675-709`), and original texture loading uses `D3DX10CreateShaderResourceViewFromFile` with default load information (`Game/src/Core/TextureManager.cpp:50-66`). Linux loads one PNG surface into an SDL texture (`port/linux/SDLRenderer.cpp:143-171`), then the pixel-wobble GL path explicitly sets `GL_TEXTURE_MIN_FILTER` to `GL_LINEAR`, not a mip-capable filter (`:332-341`), before evaluating the wobble UV shader (`:597-609`). There is no mip generation in that load/path. The spy records the fog draw size as 1325×860 logical pixels; `Game/Media/fog.png` is 1988×1290, so these rows are minified at about 2/3 in each axis. The omission applies to 117/118/119/121 and forest fog 119/122 at comparable scale. The 512×1024 `waterfall_4.png` curtains 13/14 draw at ~540×1081 in this state, so their magnification selects point sampling and this specific gap does not implicate them. Ordinary sprite minification also has a broader sampler difference (`SDLRenderer.cpp:195-207`), but is outside this isolated pixel-wobble candidate.

**Minimal isolated fix plan, not implemented:** In the custom pixel-wobble path only, create/cache mip levels for SDL-owned scene textures after binding (or own a dedicated GL texture with mip chain), then use `GL_LINEAR_MIPMAP_LINEAR` for minification while retaining `GL_NEAREST` magnification, wrap, current shader math, float alpha, flip, and state restoration. Check SDL texture ownership/format and GL extension support before selecting the mechanism; avoid changing ordinary SDL copies in this slice. Verify with an ID-only same-camera fog crop and a matched Windows frame/clock before attributing a visible difference. The precise Windows-resident mip chain and per-pixel impact are not observable in this source-only audit; the source-level mismatch is the filter/LOD behavior, not a quantified image delta.
