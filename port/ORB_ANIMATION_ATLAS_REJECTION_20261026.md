This is a distinct family from previously rejected menu, tree blur, branch, cart, arena and cave candidates.

This is an allocation proxy, not measured VRAM. The family is animation-local rather than mixed into always-resident icon/HUD pages.

A bounded runtime candidate routed only `Game/Media/orb/` manifest entries through existing virtual subtexture mapping by default, with `DEATHLEAK_ATLAS_ORB_ANIMATION=off` as a dedicated-texture control. Painter order, texture-specific source rectangles, flip, tint, rotation, and existing repeat/UV-shift/private-shader dedicated fallback were unchanged. Isolated Docker production `make -C port -j2` passed; candidate binary SHA-256 `435d2eb7aed1b0a012361ca50920f8ef6b4e2f19c74a2bd08dc284f7402b79af`.

## Physical pixel gate

Strict serial same-binary A(off)/B(on)/A(off), real Xorg `:0`/SDL x11 OpenGL, `accelerated=1 software=0 vsync=1`, Mesa nouveau NVE7, 1280×720, three fixed-1/60 Forest-1 frames with identical player/vital endpoints. Both full BMP controls matched SHA-256 `ee5b2b4b79574c32022bc321e5fd332901711c6989675fee24e4ea797291d60d`; B was `6a15bd23a5441a37d0f5706a7400a2d1608ee3ed0ff502530d57bfa7d48ca6b7`. Pillow RGB difference: 22 pixels, maximum channel delta 1, bbox x=27..1146/y=283..542, distributed over visible orb screen sites. This is a positive active ordinary-orb route, not an offscreen-only parity pass. The sole arm change was atlas routing; exact source reconstruction therefore does not establish exact minified/vertically flipped bilinear raster sampling. The precise GL arithmetic producing the 1-LSB differences was not isolated.

**Rejected:** strict exact-pixel parity fails. Candidate source and runtime assets were removed from the feature checkout; only this evidence report is retained. Default runtime atlas coverage remains 15/896, with 881 unatlased. No accepted atlas page, binding/submission reduction, p50/p95/p99, calibrated VRAM, 8K/high-Hz, 60-FPS or release claim follows. The three-frame pixel gate was deliberately run before longer GL/timing gates; those metrics were not gathered for a rejected B arm. Shared virtual texture identity alone does not batch painter calls and the existing `DrawSprite` still issues one SDL copy per orb.

Smallest distinct next gate: build a source-pixel-addressed/filter oracle for **one** actually visible minified vertically flipped orb frame, comparing exact dedicated versus atlas UV/GL samples across several animation ordinals and camera positions. Only if exact should the ten-frame family be re-integrated and subjected to serial A/B/A full-frame pixels, steady GL submissions/binds/flushes, query-off p50/p95/p99 and allocation/VRAM accounting. Keep repeat/UV/private-shader fallbacks dedicated.
