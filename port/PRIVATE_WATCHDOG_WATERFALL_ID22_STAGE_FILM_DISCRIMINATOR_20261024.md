# Waterfall ID22 stage/film discriminator — 2026-10-24

## Verdict

The previously reported Forest-ID22-hide “upper-field response” at active Waterfall ordinal 638 was a **wall-clock HUD film-frame phase confound**, not retained Forest pixels, a Waterfall scene draw, sepia, or demonstrated GL state leak. With the same process capturing first active Waterfall render (ordinal 424) and ordinal 638, all six initial visible/Forest-hide controls have identical **full-frame** post-clear, pre-sepia and post-sepia pixels at both ordinals. Four further controls with film-index traces preserve this identity. The first new-frame divergence is **after sepia, during HUD film composition**. A matched film-phase visible/Forest-hide pair (`visible2`/`forest2`) has zero changed RGB pixels in the entire final 1280×720 image at ordinal 638. The prior stable visible (`6a191adf…382`) and Forest-hide (`ebc280c3…d16`) final BMP hashes recur here unchanged, proving the stage readbacks did not alter those outcomes.

The old level-scoped A/B report's claim of a Forest-history/transition upper-route divergence is superseded. The scoped hide still selects different rendering in Forest, but that difference is cleared before the first active Waterfall scene and has no observed same-phase Waterfall output effect. This is a Linux-port counterfactual, **not original-versus-port parity**. No matched original D3D10 frame/command packet exists and no visual correction is justified.

## Reproduction and evidence

- Built a temporary, opt-in probe with the repository Docker `deathleak-linux-build:bookworm` toolchain. Probe source captured pre-clear, post-clear, pre-sepia, post-sepia, final, shader clock, gameplay-film index, camera/player, SDL viewport/clip/logical size/render target/blend/draw color and GL program/active texture/framebuffer/binding/viewport/scissor/blend/depth. Build logs: ignored `port/build/private-waterfall-id22-levelscope-20261024/stage-build*.log`. Probe source was removed after the captures; no production source change was retained.
- Ten serial fresh-process runs (`visible1–5`, `forest1–5`) used the same read-only source mount, strict accelerated physical Xorg `:0`/NVE7 `nouveau`, dummy audio, route `--play Game/XmlFiles/levels/forest_exploration_1.xml --script B:1800 --frames 639 --fixed-dt 0.016666667`, with Forest-only hide `DEATHLEAK_RENDER_HIDE_XML_IDS=22` and `DEATHLEAK_RENDER_HIDE_XML_IDS_LEVEL=Game/XmlFiles/levels/forest_exploration_1.xml`. Ignored scripts, lossless BMPs, logs and state traces live in `port/build/private-waterfall-id22-levelscope-20261024/` (`capture-stages.sh`, `capture-stages-film.sh`, `*.first.*.bmp`, `*.638.*.bmp`, `*.state.txt`). All reached identical first-active ordinal 424 and terminal player/camera at ordinal 638.
- All ten controls have identical full-frame post-clear pixels at ordinals 424 and 638. At each ordinal, all ten also have identical full-frame pre-sepia and post-sepia pixels across both hide modes and independent processes. Pre-clear shows different prior-frame film images, but the clear removes them. Shader clocks are identical: ordinal 424 `total=7.08337, wobble=7.0667, reversing=0`; ordinal 638 `total=10.65, wobble=9.3667, reversing=1`. Relevant SDL/GL state values matched across modes at equivalent stages (viewport 1280×720, no clip, render target/default framebuffer 0, same program and phase-specific texture binding). Raw GL enable values in the traces were emitted as chars, not integers; they are therefore not used for numeric inference. SDL commands can be queued, so the GL snapshot is corroborating, not a complete command trace.
- Final pixels diverge **only after post-sepia**. At ordinal 638, `visible4` film index 2 vs `forest4` index 3 changes 256,803 upper `[0,0,1280,320)` and 330,732 lower pixels. `visible5` index 1 vs `forest5` index 3 changes 251,651 upper and 320,216 lower pixels. Yet `forest4`/`forest5` (both index 3) have byte-identical final images, and earlier `visible2`/`forest2` have zero full-frame final changes. At first active ordinal 424, the pre/post-sepia scenes are identical while different film phases again produce 252k–255k upper changes. The `visible4.638.final.bmp` SHA-256 is `6a191adf3f12538b7f16a1909e1e0769b5c077a6d4a7fd89d79f01dae41dd382`; `forest4.638.final.bmp` is `ebc280c30fa4400c97d6b0fb6f089a0d4015850c1d295dfaf496f24a6d383d16`.
- Current `port/linux/main.cpp` calls `AdvanceGameplayFilmFrame` with `steady_clock::now().time_since_epoch()` milliseconds in the ordinary gameplay HUD path and draws one of four authored `film_frame*.png` textures full-screen at alpha 51 after sepia and before the opaque HUD bars/meters. That clock is deliberately independent of `--fixed-dt`. The apparent first-run/outlier variation is explained by each process reaching ordinal 638 with a different film index under real elapsed time; the A/B modes were not film-phase matched. The original authored UI XML lists the four film frames, but this test does not establish original Windows phase timing.

## Disposition

No source-backed visual defect or production fix was established. Temporary probe edits to `main.cpp`, `Renderer.h`, and the already-dirty `SDLRenderer.cpp` were removed, preserving the pre-existing raft experiment diff and all other unrelated dirty files. No commit/push: this gate produced documentation and ignored evidence only, not verified software to publish. `PORT_WORK_STATUS.md` and Sea-2 AmbientBird files were untouched. **Exclusive source/build/physical Xorg :0 GPU lane released; no stage capture container/process remains.** Next parity gate requires matched original D3D10 gameplay-film phase and pre/post-HUD image/command packet; any future A/B final-image comparison must control or record film index.
