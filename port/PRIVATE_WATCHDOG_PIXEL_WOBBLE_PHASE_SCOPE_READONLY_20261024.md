## Original phase precision and reset boundary

Windows `Game/src/GameObjects/ParallaxLayer.cpp:110-155` reads `m_vertices[0].TexCoord.y`, adds `(m_autoScrollYSpeed * .001f) * (LastUpdateDelta / TargetDelta)`, then stores that float into the vertex array before `Sprite::Draw`. It contains **no floor/modulo, no periodic phase reset, and no precision clamp**. `Sprite::RecalculateVertices` seeds its UVs from default vertices at object initialization (`Game/src/GameObjects/Sprite.cpp:195-228`); a recreated/reloaded level object therefore starts its vertex phase anew. The process-owned wobble **Time** is separate: `Game/src/Game.cpp:379-401` reverses direction above 10 seconds and below 5 seconds; that 5–10-second oscillation bounds shader Time, **not** the ParallaxLayer V phase, and is not reset by a level load in this code. Both source vertex V and port `autoScrollYPhase` are single-precision floats; eventual rounding/quantization at large phase is an implicit numeric limit, not a designed wrap/reset contract. Do not invent a periodic phase reduction as a fidelity fix.

Current Linux `port/game/LevelScene.cpp:1443-1456` accumulates float phase and now conditionally preserves it for pixel wobble. `port/game/LevelScene.h:44` initializes phase to zero on object construction; `LevelScene::Load` clears `sprites_` (`LevelScene.cpp:143-145`), re-seeding loaded objects. `port/linux/WobbleUV.h:7-15` and `SDLRenderer.cpp:672-701` forward the resulting V to GLSL. Exact bitwise D3D/Linux phase is still not guaranteed: the Linux increment has `720/1080` scale and `previousRenderedModifiedDelta * 60` arithmetic, whereas original uses its `LastUpdateDelta / TargetDelta`; their frame histories and float operation order must be compared before claiming matched pre-shader V. The integrated conditional removes the **floor-specific** first divergence only.
