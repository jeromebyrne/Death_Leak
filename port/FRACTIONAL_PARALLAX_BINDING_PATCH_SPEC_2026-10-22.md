# Fractional parallax renderer binding patch spec — 2026-10-22

Scope: static CPU/read-only review of `9154048` and current source; this file is the only edit. No renderer patch, build, display, or GPU parity result.

## Exact insertion/dispatch

- Add `#include "ParallaxUVCommand.h"` to `port/linux/SDLRenderer.cpp:1-6`. In `DrawSprite` retain its current priority at `:226-246`: damage burst, pixel wobble, foliage, repeat-X, then only the existing nonzero-shift/full-texture/unrotated UV-scroll arm. Do not route source-rect, rotated, zero-shift, or higher-priority effects through the direct path. `ParallaxUV.h:40-62` describes the priority; it is not currently wired into `DrawSprite`.

Attempt the direct transaction once; if its returned `ParallaxUVCommand::kind` is not `FloatQuad`, execute that body exactly once. `NotApplicable` should be impossible under the arm guard, but should fall through to the existing ordinary path if dispatch is ever refactored.

It is pure preparation, not renderer integration. In particular, do not call `MakeParallaxUVCorners` separately or re-floor its coordinates (`ParallaxUV.h:11-20`).

## Direct binding gate and one balanced GL transaction

1. Before GL calls, require selected SDL renderer name **`opengl`** and non-null `SDL_GL_GetCurrentContext()`; `opengles2`, software, unknown backend and nonfinite shifts use integer fallback. `Initialize` permits `opengl` or `opengles2` in test mode (`SDLRenderer.cpp:79-143`), so acceleration alone is not this gate. Use a cached renderer-driver flag set from that inspected name, or inspect `SDL_GetRendererInfo` here; do not infer from SDL flags.
2. `SDL_RenderFlush(renderer_)` before state inspection/binding, following `DrawPixelWobble` (`:335-345`). Save `GL_CURRENT_PROGRAM`, `GL_MATRIX_MODE`, `GL_ACTIVE_TEXTURE`; `glPushAttrib(GL_ALL_ATTRIB_BITS)`; select `GL_TEXTURE0` and save its `GL_TEXTURE_BINDING_2D` **before** `SDL_GL_BindTexture`. Keep a `bound` flag set only after a successful bind. The existing pixel-wobble path demonstrates binding restoration (`:338-355,396-405`); the damage-burst path (`:270-280,325-333`) does not restore the old binding explicitly and is not a complete cleanup template.
3. Call `SDL_GL_BindTexture(texture, &spanX, &spanY)` once. On failure, do not unbind; restore saved unit-0 binding, attribs, active unit, program and matrix mode, then use fallback. On success, query the bound 2D object's level-0 width/height (or otherwise positively establish its allocation) and compare to the logical dimensions from `SDL_QueryTexture`; set `npotTexture` from the actual bound allocation, not a presumed PNG size. Determine desktop full-NPOT-repeat support conservatively: GL version >= 2.0, or a positively verified equivalent; unknown version/extensions => false. `SDLRenderer.cpp:595-600` already parses desktop GL version for wobble, but does not establish this parallax gate. ID40's 2048×677 logical dimensions make this material; logical dimensions do not prove allocation/span. Also require queried width/height > 0.
4. Build `ParallaxUVBinding{true,true,spanX,spanY,npotTexture,npotRepeatSupported}` and call `PrepareParallaxUVCommand` (`ParallaxUVCommand.h:24-39`). It rejects nonfinite shift, failed/non-GL binding, nonfinite or nonunit spans (absolute difference from 1 <= 1e-6), and unsupported NPOT (`ParallaxUV.h:25-38`). If command is `LegacyInteger`, unbind the successfully bound texture, restore state, and run fallback. Do **not** compensate a subunit span by multiplying UVs: `GL_REPEAT` would expose allocation padding/seam sampling.
5. Only for `FloatQuad`, while SDL texture remains bound, snapshot `GL_TEXTURE_WRAP_S/T` and `GL_TEXTURE_MIN_FILTER/MAG_FILTER`. Set both wraps `GL_REPEAT`, min `GL_LINEAR` (complete base-level, no mip requirement), mag `GL_NEAREST`. This parallels the SDL-owned texture transaction in `DrawPixelWobble` (`:349-365,396-401`). `glPushAttrib` cannot restore mutated sampler parameters on the texture object; restore all four explicitly before `SDL_GL_UnbindTexture`. Do not alter base/max level or PixelWobble's private mip cache (`:583-590`).
6. Draw one immediate-mode quad at command destination corners `(x,y)`, `(x+w,y)`, `(x+w,y+h)`, `(x,y+h)` paired one-to-one with `command.uv[0..3]` via `glTexCoord2f`/`glVertex2f`. Explicitly select program 0, `GL_TEXTURE_2D`, texture environment `GL_MODULATE`, white-relative `glColor4f(tint.r/255, tint.g/255, tint.b/255, tint.a/255 * sprite.opacity)`, source-over blending, and disabled depth test. Set the same logical projection `glOrtho(0,1280,720,0,-1,1)` with pushed projection/modelview matrices (`SDLRenderer.cpp:367-391`); retain SDL's current viewport/scissor after the flush so clipping/logical output matches adjacent copies. `SDL_SetTextureColorMod/AlphaMod` at `:209-210` controls SDL copies, not this fixed-function quad. `Sprite::opacity` is separate (`port/render/Renderer.h:45-51`); apply it once, not via both SDL alpha mod and GL color. If inherited multi-texture/texture-env state cannot be made deterministic, use a dedicated trivial sampler shader with identical sampled-RGBA multiplication instead of silently relying on inherited fixed-function state.
7. Use one cleanup route for every post-snapshot exit: pop modelview/projection if pushed; restore prior matrix mode and program; restore four sampler parameters **while the SDL object is bound** if they were changed; call `SDL_GL_UnbindTexture` iff bound; rebind previous unit-0 2D name; pop attribs; restore previous active unit. Ensure failed bind and ineligible bind do not leave the old program/matrix mode or unit-0 binding changed. Only then let SDL fallback copy or later draw execute. `SDLRenderer.cpp:335-405` is the nearest interop ordering example, but this path needs its own all-exits bookkeeping.

## Specific risks

- SDL-owned texture sampler changes survive `glPopAttrib`; missing restoration can contaminate later SDL copies. Unit-0 binding, program, active unit, projection/modelview and texture-env/blend state can likewise leak if any exit is asymmetric (`SDLRenderer.cpp:335-405`).
- `SDL_SetTextureScaleMode` (`:219-223`) may change SDL texture filtering before binding; direct code must restore exactly the filter state it observes, while using linear-min/nearest-mag only for its quad. NPOT/version probes must use the live desktop context; `SDLRenderer.cpp:99-132` accepts test-only software/unidentified GL but is not a capability proof.
- Fixed-function modulation may differ from SDL's texture color/alpha convention, and `sprite.opacity` must not be omitted or doubled. A GPU visual comparison is still required for seams, PNG orientation, clipping, blending, and subsequent SDL draws.
