## Best attainable source-backed conclusion

Both forest-1 objects are always-updated, follow-camera-X-only, unflipped `ParallaxLayer`s with X UV coefficient `.000690`, width 2048 and alpha `.95` (`Game/XmlFiles/levels/forest_exploration_1.xml:612-635,666-689`). ID37 is `shrubbery.png`; ID40 is `trees_top.png`. During ordinary unpaused gameplay, `Game::Update` advances camera follow before the object update (`Game/src/Game.cpp:154-180`). `ParallaxLayer::Update` calls `Sprite::Update` **before** copying current camera X into `m_position.X` (`Game/src/GameObjects/ParallaxLayer.cpp:26-35`). The base update builds `m_world` from the entering position (`Game/src/GameObjects/GameObject.cpp:160-212`, via `Sprite.cpp:358-366` and `DrawableObject.cpp:41-44`). The manager then performs a separate draw pass (`Game/src/GameObjects/GameObjectManager.cpp:221-257,302-330`); `ParallaxLayer::Draw` obtains current camera X for U and calls `Sprite::Draw`, whose light-texture path uploads the cached `m_world` (`ParallaxLayer.cpp:37-83,159`; `Sprite.cpp:369-385,626-637`). No intervening rebuild was found. Thus, **conditional on a visible draw after one ordinary object update**, the source predicts world X from the *previous followed object-update position*, while U responds to the current draw camera X. At a held camera it converges after the next object update; a +8-world-X step predicts approximately `-5.333` backbuffer pixels of destination-center displacement from the current-camera Linux placement at the documented 2/3 scale (`port/game/LevelScene.cpp:1215-1250`). This is a deterministic source-path inference, **not an observed original-Windows runtime matrix or frame**.

The qualification matters: first draw after load can use authored initial X `1316.985352`; skipped object updates (pause/damage pause) can retain a matrix longer; draw culling uses post-follow object position (`GameObjectManager.cpp:320-329`); and camera shake can make camera position differ from the view matrix constructed earlier in `Camera2D::Update` (`Game/src/Core/Camera2D.cpp:120-160`). An accepted trace must record update/draw indices, actual view matrix, and culling/draw presence, rather than label every draw a one-*frame* lag. The effect is X-only and cannot explain the broad dark band's Y extent or authored darkness.
