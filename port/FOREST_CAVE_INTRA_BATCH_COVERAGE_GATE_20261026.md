Each earlier quad's covered pixel center is counted only if a *later* quad's modeled four-tap sample is fully alpha255 there. - Diagnostic camera (-43.0146,3250), **not** the fixed-Y active Forest route: 868,058 sites; 352,816 modeled candidates (40.64%). It is sensitivity information only, not active-route acceptance.

These results establish a substantial *modeled* intra-batch overlap, unlike the rejected later-painter mask. They do **not** certify a lossless geometry B: the retained apitrace fakes SDL client-memory vertex/UV blobs (`blob(588) // fake`), so the actual per-quad transformed GL vertices, SDL raster edge inclusion, and subpixel UVs have not been recovered and tied to IDs. The oracle models pixel centers and four-tap alpha, but does not prove a coverage polygon whose every rasterized fragment is overwritten at all active camera coordinates/zoom/shake phases. The changing clipped counts show a fixed screen scissor is invalid. A per-ID dynamic mask would also split the existing single 30-vertex submission and might increase CPU/GL work, so the 26% is **not** an expected frame-time gain. No exact-safe geometry patch follows from this evidence.

**Decision:** reject runtime B for this bounded gate. No B build, new physical serial A/B/A, exact-pixel B proof, GPU fragment reduction, p50/p95/p99 benefit, or memory improvement is claimed; default atlas coverage remains 23/896. Next distinct candidate: classify the cave-blur source's large alpha-zero regions for *source-space transparent-cell geometry trimming* with bilinear-neighbor guard, independent of later painter overwrite. First recover actual emitted SDL vertices/UVs from an in-process draw spy and require a source-coordinate mask that survives camera/rotation/clipping; only then consider an isolated B and physical A/B/A. This is a different optimization mechanism from intra-batch later-alpha occlusion. No 60-FPS, 8K/high-Hz, sustained/thermal or release acceptance.
