# Fractional parallax nonfinite fallback safety audit — 2026-10-22

Scope: CPU-only, read-only source audit at `99ab5a6`. This document is the sole output; no production/test source, build, renderer, GPU, capture, Docker, or fog-mip work was performed. The edge gate and binding patch spec are proposals/evidence for the pure command seam, not proof that `SDLRenderer.cpp` uses it.

## Finding: reachable undefined conversion for invalid input

- `LevelScene.cpp:1238-1239` computes `Sprite::uvShiftX/Y` from camera/parallax state without a finiteness guard. This audit does **not** establish that normal gameplay produces a nonfinite camera or phase; the finding is conditional on such a value arriving at `DrawSprite`.
- The current full-texture, unrotated UV-scroll arm in `SDLRenderer.cpp:246-261` is active when either shift compares unequal to zero. `NaN != 0` and `+/-infinity != 0` are true. Provided no higher-priority effect/repeat-X arm wins and a positive texture height is returned, line 252 invokes `ForEachUVWrapSegment` with Y; if Y is finite it then invokes the X helper at line 253. Thus a nonfinite Y or X can reach the helper directly today; the command seam is not wired into the renderer.
- `UVWrap.h:15-18` checks `pixels <= 0`, then evaluates `phase = shift - floor(shift)` and converts `phase * pixels` with `static_cast<int>` **before** `std::clamp`. For NaN, phase remains NaN; for either infinity, `infinity - infinity` yields NaN. Conversion of that nonfinite float to `int` has undefined behavior. The later clamp cannot protect the conversion.
- `ParallaxUVCommand.h:31-38` correctly refuses a float quad for nonfinite shifts, but returns `LegacyInteger` while preserving the original nonfinite shift. A future renderer integration that sends that fallback unchanged into `UVWrap` will still reach the same undefined conversion. The edge-gate test (`fractional_parallax_command_test.cpp:131-137`) intentionally tests only command preparation and does not submit those vectors to its fallback sink. The binding patch spec's instruction to keep the fallback body unchanged is therefore unsafe for this edge case until the helper/dispatch is hardened.

## Narrow safe fix for the implementation owner

Add the finiteness policy at the shared integer helper boundary, before `floor` or any float-to-int conversion: keep `pixels <= 0` as the first return and use phase zero for a nonfinite shift on that axis, e.g. `const float phase = std::isfinite(shift) ? shift - std::floor(shift) : 0.f;`. Leave the existing cut, flip ordering, and segment logic otherwise untouched. A nonfinite axis then contributes one full-source segment at offset zero; a finite other axis retains its ordinary scrolling segments. This is a deterministic neutral-shift fallback for invalid input, not a claim of visual parity for invalid input. It protects both the currently live renderer path and any later `LegacyInteger` command consumer without adding GL work or changing the direct eligibility gate. Do not merely clamp the computed cut, sanitize only the command's UVs, or rely on the renderer branch predicate; none protects the shared conversion.

## Acceptance criteria (CPU only)

1. A focused helper test feeds `+infinity`, `-infinity`, and quiet NaN separately to X and Y through the same nested `ForEachUVWrapSegment` shape used by the renderer, with positive dimensions and both flip settings. No undefined float-to-int conversion occurs (a float-cast sanitizer where available is useful); the invalid axis yields exactly `{source=0,length=pixels,offset=0}` and the finite axis retains its expected segments. Test both axes invalid as one full-texture copy.
2. Repeat the existing finite edge/cut and flip vectors to prove segment count, source intervals, offsets, and cut behavior unchanged. `pixels <= 0` still invokes no visitor.
3. Through `PrepareParallaxUVCommand`, nonfinite X/Y still cannot become `FloatQuad`; when a test sink submits its `LegacyInteger` result to the hardened helper, it completes deterministically with the original destination/flip data and no invalid conversion. This closes the gap deliberately left by the current edge-gate test. A renderer-wiring gate, if added later by its owner, should also demonstrate exactly one safe fallback for nonfinite input; pure seam tests alone do not prove wiring.
4. Keep GL binding, texture spans, GPU parity, and fog mip behavior outside this fix. The binding spec's finite eligible direct path remains a separate renderer implementation/review.

Evidence was static inspection of `port/linux/SDLRenderer.cpp`, `UVWrap.h`, `ParallaxUVCommand.h`, `ParallaxUV.h`, `port/game/LevelScene.cpp`, the named edge-gate/spec documents, and the command seam test. No runtime safety result is claimed.
