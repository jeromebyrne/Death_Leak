# Death Leak low-end renderer architecture (2026-10-26)

## Baseline that constrains the design

Death Leak simulation is not the current bottleneck. Prior strict NVE7 measurements of active Forest show ~0.5 ms/update, ~20 ms/frame median, and a scene-GPU query interval around 19 ms at swap interval zero. Empty-frame presentation had a ~16 ms host/display floor. The authored scene includes large repeated/parallax/fog sheets and substantial overdraw, so reducing texture count or CPU calls alone cannot guarantee 60 Hz. SDL already coalesced a tested same-texture particle run into the same real GL draw count; a tested Waterfall branch group saved only one driver draw during a short route. The accepted HUD batch saved seven driver draws per frame but did not establish a material FPS gain. Physical display, NVE7 GPU, pixel and frame-time evidence remain the acceptance gates.

## Target design

1. **Keep the existing game rules and authored data.** A deterministic fixed-step simulation produces an immutable render snapshot. Rendering must not advance animations, particles, effects, audio or save state. Presentation can occur at the selected display cadence without changing gameplay time.
2. **Replace immediate scene calls with an ordered render-command buffer.** Commands carry texture/virtual-frame ID, source rect, destination transform, tint/alpha, sampler, blend, shader/effect parameters, scissor, target and painter sequence. World objects, combat effects, particles and UI append commands; backend owns submission. Retain exact source order. Only consecutive commands with identical target, shader, sampler, blend, scissor and texture page may merge. Any state change or overlapping order-sensitive layer flushes. Do not globally sort transparent sprites by texture.
3. **Scene-local atlas residency.** Deterministically pack eligible animation and prop families, with frame-local UVs and an auditable manifest; stream/load only pages needed by the current and imminent scene. Dedicated textures remain for wrap/repeat, mips/filter exceptions and special effects until their virtual-texture semantics are proved. Reuse page allocations across transitions and cap VRAM from measured budgets. Atlas occupancy is a memory/layout metric, not an FPS claim.
4. **One proven ordinary-sprite GPU path.** Submit vertex/index data in bounded persistent/reused buffers, with per-vertex color and frame rectangle; use integer texel-center sampling where normalized UVs change pixels on NVE7. Merge only repeated *real driver submission boundaries*. Specialized fog, parallax, foliage and damage shaders stay explicit commands, not magic variations on ordinary sprites. Shader changes need exact scene captures and pass-level timing.
5. **Attack overdraw and passes before chasing tiny calls.** Instrument effective screen coverage and pass GPU time for Forest and Waterfall. Prefer static background caching only when it avoids per-frame target copies, tracks all camera/animation/weather dependencies, and matches every pixel; the previous copied backplane cache was slower and visually wrong. Keep scene target + sepia + HUD order unless a fused pass proves identical output. A lower internal-resolution quality tier is acceptable as a *separately labeled optional setting*, not an exact-parity replacement.
6. **Bound work and allocations.** Preload/decode transition-critical art asynchronously, avoid frame-time allocations in draw construction, reuse command/vertex storage, cull before emission, and limit costly full-screen effects using measured coverage. Preserve the 1280×720 authored space while mapping output/input/capture through a verified display mode.

## Migration and gates

- Slice A (active): ten-frame orb page and frame-local corrected sampler; consecutive-orb ordered draw seam; segmented HUD batch. All opt-in until matched exact pixels, actual GL submission/bind counts and serial GPU timing pass. Do not enable the atlas merely because pack verification succeeds.
- Slice B: introduce a backend-neutral `RenderCommand`/`RenderList` and route one existing painter interval into it without reordering. Compare every emitted command and fixed simulation state with the old path; then exact post-HUD A/B/A on Forest, Waterfall, cave and combat frames.
- Slice C: move producer families one at a time: ordinary animated actors, particles, HUD, then eligible background props. For each, prove atlas sampling/filtering/source-rect/flips/tint, count real GL submissions and page binds, and retain a runtime control arm. Reject a family that changes pixels or costs more.
- Slice D: identify the costly scene coverage/pass from GPU measurement and prototype one same-pixel overdraw/pass reduction; reject if full-frame parity or p50/p95 regresses. Measure transition upload stalls and residency separately.
- Release: repeated real-display/GPU A/B/A at representative resolutions and scenes, p50/p95/p99 under target budgets, VRAM/thermal, real controller/display/audio playtests. Headless or offscreen tests are functional gates only.

## Initial budgets to validate, not promises

At 60 Hz the end-to-end budget is 16.67 ms, with simulation, render construction, scene GPU, postprocess/HUD and presentation all counted. On this specific NVE7/Xorg display the measured empty-frame floor already approaches 16 ms, so 60 Hz may require a different presentation path/display mode even after scene optimization. Do not infer that a modern low-end GPU shares this host's compositor floor. Track actual pixel cost, not the visual genre label “basic 2D.”
