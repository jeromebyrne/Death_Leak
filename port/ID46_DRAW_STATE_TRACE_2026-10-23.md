# ID46 draw-state physical-GPU trace — 2026-10-23

## Verdict

The forest-1 fixed `R:98` ID46 draw was traced on physical X11/OpenGL (`nouveau / NVE7`) with an isolated diagnostic binary. The measured deformed tile boundary is x869.209 at its top and x872.906 at its bottom (x≈870.95 at y640), confirming the CPU prediction. At that draw, the SDL-owned texture is **GL_CLAMP_TO_EDGE in S/T**, **GL_LINEAR min/mag**, base 0, max 1000, level 0 2048×252 and levels 1–3 unallocated. The tile UVs are local 0–1, so this is not evidence of an out-of-range wrapping error; no mip level is available or selected by `GL_LINEAR`. The trace also identifies a measurable *nonzero-alpha transition* on the right of the boundary: at y640, x901 is the first baseline-vs-hide-ID46 changed pixel, with the difference growing into the interior. No renderer change is warranted from this state. This is Linux draw-state evidence, not Windows parity.

## R:98 draw geometry and state

`LevelScene.cpp` constructs destination X as `640 + ((worldX-cameraX)*layerX - width/2)*2/3`; ID46 is an ordinary kGround sprite (layerX=1), worldX 2086.573242 and width 10000. The diagnostic R:98 draw logs `destination=(-1697.76,558.667,6666.67,168)`, world `(2086.57,2976)`, shader time `1.63334`, opacity `0.5`, `leaves_shadow.png`, texture ID 214. Inverting the draw destination puts **actual draw-time camera X≈593.21** (the printed destination is rounded; the prior CPU predictor 593.214240 is within that precision). This is an inversion of a logged draw-time value, not a direct camera-variable print. The instrumented tile corners, in SDL order TL/TR/BR/BL, are:

- Right tile: `(869.209,562.518):UV(1,1)`, `(2234.64,561.523):(0,1)`, `(2238.24,726.667):(0,0)`, `(872.906,726.667):(1,0)`.
- Left tile: `(-496.224,563.512):(1,1)`, `(869.209,562.518):(0,1)`, `(872.906,726.667):(0,0)`, `(-492.428,726.667):(1,0)`.

Both share the x869.209–872.906 edge, with U=0 on the left tile and U=1 on the right tile. At y640, linear interpolation along the edge gives x≈870.95. `RepeatX.h` chooses these right-anchored tile fractions, and `SDLRenderer.cpp::DrawFoliageSway` supplies these per-tile local UVs. Consequently this draw never requires out-of-range U to repeat.

For **both** tiles in the captured final frame, the post-flush GL query returned bound texture name 215, SDL span `(1,1)`, S/T wrap `(33071,33071)` = `GL_CLAMP_TO_EDGE`, min/mag `(9729,9729)` = `GL_LINEAR`, `GL_TEXTURE_BASE_LEVEL=0`, `GL_TEXTURE_MAX_LEVEL=1000`, mip0 `2048×252`, mip1–3 `0×0`, GL error 0. The same state is logged at prior frames too. This rules out a populated mip chain in these checked levels and a mipmap minification filter for this ID46 SDL texture. It does **not** prove the Windows/D3D sampler or exactly which GL state SDL installed at every lower-level draw instruction; the bounded post-flush/query method is stated above.

## Nonzero-alpha edge discrimination

The prior same-state physical-GPU baseline/hide-ID46 BMPs are `port/build/id46-seam-gpu-2026-10-23/{baseline,hide46}.bmp`; both used the identical input hashes and fixed script. Comparing unfiltered minus hide-ID46 gives a valid contribution attribution; `only46` is a separate isolation view. At y640, x895–900 have zero baseline/hide difference. At **x901**, baseline `(31,27,19)` vs hide `(32,28,20)` is a nonzero `(-1,-1,-1)` difference; x902–906 continue with small differences, x910 reaches `(-8,-7,-6)`, and x948 reaches `(-36,-32,-24)`. Across y620–680, x860–889 has 0/1830 changed pixels, x890–899 0/610, x900–909 248/610 (max channel delta 12), x910–919 489/610 (max 31), and x940–955 976/976 (max 44). The instrumented ID46-only frame is pixel-identical to the prior only-ID46 frame; therefore those baseline/hide measurements refer to the same observed draw geometry/state, albeit separate deterministic processes.

At y640, x901 is about 30 px to the right of the measured tile edge, or roughly 45 source texels inside the right tile; U≈0.978, near source column 2003. PNG source rows 131–135 at column 2003 have alpha 4,3,3,3,2 respectively, whereas the outermost columns have zero. This is a **source-backed, low-alpha transition**, not proof of the exact bilinear footprint or pre-sepia alpha at x901. The rendered baseline/hide difference is the stronger evidence that ID46 has begun contributing there. It does not reveal a seam discontinuity at the shared edge; the visible contribution begins only after the alpha guard.

## Limits and next step

The GL query is immediately post-flush and SDL-bound, not a full API call trace; levels above 3 were not queried, though the non-mipmap `GL_LINEAR` min filter makes them irrelevant for this draw. The alpha lookup is approximate because raster interpolation/filtering and sepia are not independently traced. The physical capture is current dirty Linux code only; the original Windows still is unmatched in camera/state and JPEG. Do not claim visual parity, a wrap defect, or an SDL-wide filtering fix. If a visual mismatch survives comparison to a **same-state lossless Windows frame**, inspect the original D3D sampler and the 30–60-source-texel alpha transition around x900–920 (or test a scoped pre-sepia/control texture); avoid changing sampler state solely on this zero-signal boundary.
