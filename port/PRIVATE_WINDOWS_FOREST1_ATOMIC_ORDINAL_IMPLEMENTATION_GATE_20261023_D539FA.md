## Minimal hook and transaction

1. Add an opt-in one-shot `CaptureRequest` and a monotonically incremented `uint64_t renderOrdinal` in the original `Game/src/program.cpp` loop, immediately before `Render()` (`:168-177`). Keep the ordinal local to the rendered frame; do not derive it from wall time, `timeGetTime`, or Linux `frame`. At that point snapshot the just-used effective update delta, `Timing::GetTotalTimeSeconds()`, and **the prior** `GetLastUpdateDelta()`; the latter is updated *after* `Render()` (`:173-176`).
2. When armed, collect draw-only values into an in-memory `CaptureState` during `Game::Draw` (`Game/src/Game.cpp:354-405`): the actual world/view/projection matrices, submitted `shaderTime`, pixel-wobble time and direction immediately after its threshold/reverse branch, and foliage multiplier. Never reconstruct these after `Render()`; the pixel clock is function-static and the camera's stored position may differ from the view matrix during shake (`Camera2D.cpp:120-160`). Collect remaining gameplay/UI snapshots at their draw read points or freeze their values in the same render call. No disk I/O in object draw loops.
3. In `program.cpp::Render()`, directly **after** `UIManager::Instance()->Draw(...)` (`:317`) and before return/`Present()` (`:322`), verify the requested ordinal still matches the in-memory snapshot. Query the actual swap-chain backbuffer texture description and `RSGetViewports` via `Graphics::SwapChain()`/`Device()` (`Core/Graphics.h:24-45`); copy the native backbuffer into a CPU-readable D3D10 staging texture and complete readback **synchronously before `Present`** (`Core/Graphics.cpp:257-281`). Save lossless BMP/PNG without scaling; record row-pitch conversion, format, dimensions, viewport, and post-HUD/pre-Present stage. Source's nominal `DXGI_FORMAT_R8G8B8A8_UNORM` and 1920x1080 globals are defaults, not substitutes for queried values.
4. Serialize sidecar with the **same renderOrdinal** and SHA-256 of the finished image bytes. Write image and JSON to unique temporary names; finalize image first and JSON last. Treat JSON as the packet commit marker: a reader accepts only if both files exist, ordinal in the filename/JSON agrees, byte hash matches, dimensions decode, and `captureStage=post_hud_pre_present`. If any readback/serialization check fails, leave no valid JSON marker and report the failure; never pair a later image with an earlier state. A one-frame stall is acceptable for this opt-in diagnostic.

## Required v1 sidecar, measured not inferred

- Identity: `source_built_original_d3d10` (never label shipped Steam), EXE/source revision and hash, level XML path/hash, visible-asset hashes or a content manifest hash; forest-1 active-level confirmation; image filename/hash; ordinal; update ordinal if distinct; capture stage; backbuffer/viewport dimensions, pixel format/color space, postprocessing enabled, scaling/frame-debugger status.
- Simulation/draw: effective dt, total simulation time, prior `LastUpdateDelta`, full actual world/view/projection matrices, camera stored XYZ/zoom/follow/lag/shake and previous rendered XY; player drawn XY/velocity/facing, grounded/attack/damage, body **and arm** clip/frame/texture/pose; health/max/focus and **drawn** HUD meter/orb count; collected orb IDs; ID117 DojoScrollPickup presence and `kDeflection` unlock; active UI/modal/pause flags.
- Dynamic phases: submitted foliage/noise/vertex-wobble time; pixel-wobble time **and reverse direction**; weather state/foliage multiplier, rain/lightning/particle phase or explicitly documented matched freeze, RNG state/history or input-history recipe. If a field cannot be read in v1, emit `unavailable` with a reason and mark packet **not matched-state eligible**, rather than inventing an XML/default value. ID37/ID15 per-object transform/UV/alpha is diagnostic v2, not necessary for acquiring the first whole frame.
