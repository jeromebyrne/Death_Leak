**Distinct unimplemented draw-state contract.** Original `GameObjectManager::Draw` admits a non-player drawable only when `Alpha()>0` **and the whole object is in the camera view** (`Game/src/GameObjects/GameObjectManager.cpp:302-330`). `Camera2D::IsObjectInView` first tests origin, then rotated/unrotated *object bounds*, with parallax offset (`Game/src/Core/Camera2D.cpp:39-80`); only then does `ParticleSpray::Draw` submit its particle vertex buffer (`Game/src/Particles/ParticleSpray.cpp:128-157`). Linux uses ID47's authored bounds for an approximate **update** zone (`port/game/LevelScene.cpp:857-862`), but its draw merge invokes `spray.Draw` without an emitter-camera predicate (`port/game/LevelScene.cpp:1336-1343`). `ParticleSpray::Draw` instead clips each leaf against the 1280×720 viewport (`port/game/ParticleSpray.h:83-101`). Thus the source-vs-port *admission algorithm* differs: an independently visible warmed/advected leaf can be rendered by Linux after the original has culled ID47's emitter rectangle. This is not the settled ID47 presence, alpha, pre-step/flip, RNG, or size issue (`port/LEAF_PARTICLES_CHECKPOINT.md`; `port/PARTICLE_ALPHA_PARITY_2026-10-22.md`; `port/PRIVATE_POST_ID37_PARTICLE_SPRAY_GATE_20261023T2021Z.md`). Waterfall reports already mention this generic culling approximation for IDs49–51 (`port/WATERFALL_SPLASH_50_51_SOURCE_AUDIT_2026-10-22.md`); this report isolates its *Forest-1 ID47* consequence, not a new general renderer claim.
