## Verdict

**No source-backed visible ID46 seam defect is demonstrated; no production patch.** A new API trace of the actual final-frame `glDrawArrays` batches, plus GL state replay dumped at the first draw instruction, resolves the earlier post-flush uncertainty: forest-1 ID46's two visible tiles draw with texture 215 bound on unit 0, `GL_CLAMP_TO_EDGE` S/T, `GL_LINEAR` min/mag, and local UVs in [0,1]. The adjacent shared edge is U=0 on the left tile and U=1 on the right tile; the reversed phase is the already-implemented whole-quad flip contract, not a request for out-of-range U. Although original `FoliageSway.fx` declares WRAP, this tile path does not exercise wrapping at the edge. The existing same-state composited seam crop has zero attributable ID46 pixels while an interior control contributes, consistent with the transparent PNG edge guard. CLAMP versus WRAP therefore does not, by itself, justify a source edit or claim visual parity.

## Decision and lane release

Original Windows `FoliageSway.fx` WRAP describes its one-quad sampler, whereas Linux deliberately divides repeated content into 0–1 local tile UVs. An API-proven CLAMP state is thus a contract difference but not a demonstrated rendered divergence at this zero-signal boundary. A future source change would require a same-state nonzero-alpha wrap/global-UV A/B and preferably a matched lossless original-Windows frame; neither is supplied by the unmatched Steam JPEG. No production source, XML, art, tests, shared status or checkpoint was edited. No scoped software commit/push is warranted. All build, apitrace, replay and game containers exited; no Death Leak game, FFmpeg, build or replay process remains. **The physical Xorg GPU/build/capture lane is released.** Visual parity and Jerome's review remain open.
