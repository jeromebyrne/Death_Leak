# Physical NVE7 covered-postprocess-clear gate — rejected

Starting HEAD `90b0fc2`. Candidate selected the active-gameplay Sepia pass, which clears the physical output to black then paints an opaque full-viewport quad before HUD. An isolated clean-HEAD build toggled a skip of `glClear(GL_COLOR_BUFFER_BIT)` only where the Sepia viewport exactly covers the output; non-16:9 letterbox output retains the clear. No scene painter order, shader, SDL target, authored asset, main-tree source or raft-mip dirty hunk was changed. This is a framebuffer-clear/target-traffic test, not an atlas or release gate.

Strict physical Xorg `:0`, SDL x11/OpenGL accelerated=1/software=0/vsync=1, nouveau/NVE7, 1280×720, fixed-dt scripted active Forest `B:360`. One candidate binary, serial control/candidate/control, toggled only `DEATHLEAK_TEST_SKIP_COVERED_CLEAR`. All three 360-update final full BMPs matched byte-for-byte, SHA-256 `5436dc189dfa9697d6b4373379bd6c130e96931eba10ec69ba53af0b54895dfd`; all reached Forest player `(2808.99,3118.11)`, 7 orbs, 25 health, 22 fired. This is one synchronized endpoint per arm, not all-frame parity. Pixels were captured without `--profile`, avoiding its dynamic FPS HUD.

Separate serial untraced 360-update A/B/A profiling (120 warmup, 240 samples per arm) yielded p50 **20.222 / 20.135 / 20.0742 ms**, p95 **22.0078 / 21.9726 / 21.9912 ms**, p99 **22.151 / 22.0805 / 22.0875 ms**. Candidate values lie within control spread; no repeatable meaningful frame-time gain. Frame maxima were 22.1767 / 22.1084 / 23.8936 ms; none exceeded 25 ms. GL clear traffic is tested separately with test-only branch counters; see checkpoint/logs. An LD_PRELOAD `glClear` interposer returned zero even on controls and is invalid as a GL call counter, so no driver-level traffic number is claimed from it. No FPS improvement or 60-FPS acceptance is claimed.

**Decision:** reject; the isolated candidate is not shipped. A clear call theoretically touches 1280×720 output, but tile/compression behavior and actual driver memory traffic were not measured. The observed serial latency does not justify changing a pass that still needs a clear for letterboxed displays. Ignored build/log/BMP evidence: `port/build/shader-clear-20261025/` and isolated `/tmp/deathleak-shader-clear-20261025/`. Next distinct task: instrument the Waterfall-top fog/ground-front shader draw span and target bind/copy boundaries with GPU timing queries or apitrace on a repeatable 60-frame active-top route; choose an exact-pixel pass-fusion or target-traffic candidate only where measured cost exceeds control variance.
