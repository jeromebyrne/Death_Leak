A same-frame render-only hide of player XML ID2 changes 2,735 RGB pixels inside its screen bbox `(810,509,893,621)`; removing overlapping foreground ID10 raises median absolute player-versus-hidden-background luma difference from **12.0 to 38.7** (8-bit Rec.709 units, ≈3.2×). No art, XML, renderer source, or tests were changed; no speculative contrast boost is warranted.

## Original-source occlusion/alpha contract

- `Game/XmlFiles/levels/forest_exploration_1.xml:33–47` authors player ID2 at `kPlayer`, alpha 1, `effectlighttexture`, and `fade_when_player_occluded=false`. ID10 is `tree2_blur.png`, `kMiddleForeground`, alpha **0.7**, `fade_when_player_occluded=false`, with a large authored rectangle centered near `(2172,3375)` that contains the tested player world point `(2360.52,3114.74)`. The only Forest-1 `fade_when_player_occluded=true` sprites are IDs5/6 near the earlier route, not ID10; changing ID10 to fade at this point would be an art/gameplay edit without source support.
- Original `Game/src/GameObjects/Character.cpp:1888–1906` draws arm then body via `SolidMovingSprite::Draw`; `Sprite.cpp:626–672` passes object alpha to `BasicLightTexture.fx`, whose pixel shader multiplies sampled texture alpha by that object alpha. `Game/src/Core/Graphics.cpp:392–407` uses source-alpha-over. Its depth contract places `kMiddleForeground` (1000) after `kPlayer` (3000). The port's `LevelScene.cpp:1227–1320` uses the same descending-depth painter ordering, alpha-tinted draw and arm-before-body sequence; ordinary SDL texture draws in `SDLRenderer.cpp:204–267` use `SDL_BLENDMODE_BLEND` and alpha modulation. For this ordinary ID10 draw the authored 0.7 alpha is not a missing fade or an established double-alpha regression.
- The measured lower contrast is therefore explained by an authored translucent dark foreground crossing a dark player, plus the already dark forest composition. It does **not** prove that Windows output has identical pixels, sampler choice, sepia response, or exact silhouette contrast.
