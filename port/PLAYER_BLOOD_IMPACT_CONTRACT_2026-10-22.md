# Player blood impact/inactive contract — source audit (2026-10-22)

Scope: read-only audit of the original Windows blood-FX projectile and the current Linux `Combat` seam. This is an implementation contract, **not** an implementation, build result, or visual acceptance.

## Windows behavior, in execution order

1. `Character::OnDamage` calls `FireBloodSpatter((0,0), m_position)` for a damageable player; projectile direction is copied only for a *non-player* character hit. `FireBloodSpatter` exits when `mEmitsBlood` is false. It creates one `kUnknownProjectile`-owned `kBloodFXProjectile`, `blood_projectile.png`, random impact variant `blood_impact.png`/`blood_impact_2.png`, square size `256*(.5 + (rand()%50)*.01)`, collision dimensions 64×64, speed 3.5, damage 0, inactive maximum 5.5 s. It disables ordinary alpha fade, enables scale fade, spinning and rotate-to-direction are off. [Character.cpp:1580–1614,2235–2272](../Game/src/GameObjects/Character.cpp)
2. Active `Projectile::Update` performs its 0.3 s alpha/size fade-in, applies blood gravity `-0.5*min(2, delta/targetDelta)` to Y velocity, then advances position by velocity times the capped nominal-tick factor and resistance. With zero launch direction, blood initially falls vertically. There is **no source active-flight TTL**. [Projectile.cpp:413–496](../Game/src/GameObjects/Projectile.cpp)
3. `Projectile::OnCollision` ignores debris, foliage, currency orbs and pickups, and filters some other object classes. A solid line is dispatched first to `HandleSolidLineStripCollision`; for any *other* object a blood-FX projectile returns without impact/damage/attachment. Thus do not reuse the knife or player-hit collision path for blood. [Projectile.cpp:64–140](../Game/src/GameObjects/Projectile.cpp)
4. A line impact occurs only if `SolidLineStrip::GetProjectileCollisionData` succeeds: broad-phase `BoxHitCheck` plus an intersection of the line with the ray from **last-frame collision center** to **current collision center + launch direction × 32**. Its reported position is `line.position - projectileRayEnd`; the caller's material-spray origin simplifies to the ray end, *not* the segment intersection. Blood direction is zero, so its ray end is its current center. A strict AABB pair check precedes collision dispatch. [SolidLineStrip.cpp:418–458](../Game/src/GameObjects/SolidLineStrip.cpp), [Projectile.cpp:783–805](../Game/src/GameObjects/Projectile.cpp), [CollisionManager.cpp:20–119](../Game/src/Core/CollisionManager.cpp)
5. On a valid line hit, velocity becomes zero and `m_isActive=false` with a wall-clock inactive timestamp. If material exists, a 10-particle material-directed spray is created even for blood; blood suppresses the line damage sound. The spray reverses projectile direction (thus zero for this blood flight), uses current depth, and has the source parameters in `HandleSolidLineStripCollision`. Pierceable material changes to the preloaded impact texture and calls blood jitter; **nonpierceable** material instead calls `ReboundOffSolidLine` and does *not* switch to impact texture or ground-blood depth. No material also switches texture and jitters, but emits no material spray. [Projectile.cpp:603–711](../Game/src/GameObjects/Projectile.cpp)
6. Blood jitter selects magnitude `(rand()%100)*.01*20` (0–19.8), random ± sign, always adds `kBloodSplashOffsetY=-20` to Y, then changes depth to `kGroundBlood=4000`. On nonpierceable rebound, the source sets an approximate normal/random velocity, marks `mCollidedWithProjectile`, sets inactive max to **0.25 s**, rotation rate .09, and keeps the flight texture/depth; this is a separate branch, not a blood splat. [Projectile.cpp:16,713–772](../Game/src/GameObjects/Projectile.cpp), [GameObject.h:38–45](../Game/src/GameObjects/GameObject.h)
7. Inactive update continues position and `Sprite::Update`. For the blood splat (`DoAlphaFadeOut=false`, `DoScaleFadeOut=true`), the source scale matrix ramps 0→1 over the **first 5%** of the 5.5 s inactive interval (remaining fraction >.95), remains full thereafter, and alpha fades 1→0 in the **last 20%** (remaining fraction <.2). Despite the flag name, final fade changes alpha, not matrix scale. Removal uses `currentTime > inactiveStart + maxInactive`, so equality is still alive. Rebound also adds rotation and `Y -= 1.15*percentDelta` each inactive tick. [Projectile.cpp:499–588](../Game/src/GameObjects/Projectile.cpp)

## Current Linux seam and next implementation

- `Combat::SpawnPlayerBloodFlight` currently stores only `{x,y,vy,size,age}`. `Update` owns active gravity/motion plus a **port-only 10 s collection bound**; `AppendPainterItems` draws `blood_projectile.png` at depth 3000 with active fade. This work is already verified only for active flight by `player_hit_blood_visual_test.cpp`. [Combat.h:87–95,113–122](game/Combat.h), [Combat.cpp:314–341,746–758](game/Combat.cpp), [active-flight checkpoint](PLAYER_HIT_BLOOD_VISUAL_2026-10-22.md)
- Implement a separate blood phase/state in `Combat` (active, impacted splat, rebounding inactive) with impact-variant texture selection and inactive elapsed/duration. Load both impact textures in `SetArt`; draw phase-specific texture, depth, alpha, size/matrix scale and rotation. Preserve existing active fade and independent blood RNG; use deterministic Linux-only draws for size/variant/jitter/rebound without perturbing global RNG. `ClearLevel` must clear all phases. Do not use or mutate `shots_` for blood.
- During the blood update, retain old and new center, then query `scene.Ground()` **for blood independently of the knife's enemy-dependent line skip**. For this port's segment-only geometry, use a center sweep as a documented approximation to the source 64×64 broad phase + last-center→current-center ray; select one deterministic winner, stop active motion at contact, and transition once. Prioritize a valid line over other object types; do not impact on enemy/player/pickup/box merely because a knife would. Feed the chosen segment/material to the impact branch and preserve no-material behavior. Existing `SegmentContact` is available, but its cross-product returns false for collinear/parallel travel; explicit edge tests are needed if parity is claimed. Current `SolidBox` carries no material and must **not** be silently treated as a line/material hit. [Combat.cpp:18–52,583–604](game/Combat.cpp), [LevelScene.h:67–69,192–204](game/LevelScene.h)
- `LevelScene::GroundSegment` retains material name but not `is_pierceable`; `materials.xml` and original `Material::ReadXml` do. Extend the scene's material metadata or a focused accessor from the existing XML parse, preserving authored values; do not guess that every line is pierceable. Reuse `GroundParticleTexture`/`ParticleSpray` only where material and texture actually exist. If the next slice deliberately covers only splat-capable/pierceable lines, explicitly defer rebound and keep nonpierceable flights out of a false splat state. [LevelScene.cpp:248–278](game/LevelScene.cpp), [Material.cpp:77](../Game/src/GameObjects/Material.cpp), [materials.xml](../Game/XmlFiles/materials.xml)
- Replace the 10 s active collection workaround **only when** contact and inactive removal are implemented or retain it explicitly as a port-only orphan bound. The 5.5 s clock starts at impact, never at spawn. Do not claim exact Windows time ordering from `dt`: the original uses `Timing::GetTotalTimeSeconds()` for inactive age.

## Focused CPU cases for the implementation owner

1. Inject one blood flight over a known horizontal/diagonal segment; verify one contact despite a large timestep, no second impact on subsequent ticks, zero post-impact velocity, correct impact variant, signed 0–19.8 jitter plus -20 Y, depth 4000, and no player/enemy health change. Include collision where the active enemy count would make *knife* shots skip lines.
2. Put an enemy, player, pickup and `SolidBox` across the same blood path without a line; verify blood remains active and no damage/attachment/splat. Add a line after them and verify only that line transitions it.
3. For pierceable material, verify the 10-particle spray at the blood **ray-end/current center**, source depth at emission, no line-hit damage sound; for no material, verify splat without spray. For nonpierceable material, verify rebound phase (flight texture/depth retained, 0.25 s inactive window, movement/rotation), never a splat.
4. For the splat's 5.5 s inactive envelope: just after impact scale approaches 0; at 5% scale is full; at 80% remaining? More precisely, at 80% **elapsed** the late alpha fade begins; at 90% elapsed alpha is .5; at exactly 5.5 s the source comparison still allows it, and immediately after it is removed. Verify `ClearLevel` mid-flight and mid-splat.
5. Cover first contact selection with two segments, endpoint/tangent/parallel/collinear cases, a step that crosses an entire thin line, and a 0-dt tick. Assert the chosen port approximation explicitly; do not label it exact Windows parity.

## Ambiguities / fidelity limits

- The original `m_lastPosition` and collision broad phase depend on sprite update/collision-manager order, camera culling and object-list order. The port only has flat segment endpoints and the active-flight update runs before its other combat logic; a nearest-sweep winner is a reasonable deterministic *port policy*, not proof of exact source winner/order. [Game.cpp:205–211](../Game/src/Game.cpp), [CollisionManager.cpp:20–83](../Game/src/Core/CollisionManager.cpp)
- Source nonpierceable rebound is random and line-normal-dependent. `GroundSegment` has no authored normal or strip identity, and `SolidBox` has no material. Exact rebound trajectory/material sound parity requires additional data and is outside a minimal splat slice.
- `Projectile::Update` invokes `Sprite::Update` twice on inactive frames in this source file; effect on attachment/last-position is not established here. The blood line path itself never attaches. Keep inactive visual-envelope tests focused on explicit projectile fields, not asserted attachment parity.
- No GPU/build or visual assessment was performed by this audit.
