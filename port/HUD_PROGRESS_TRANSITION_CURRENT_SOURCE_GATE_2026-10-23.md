## Original contract versus current port

- `Game/XmlFiles/UI/game_hud.xml:76-98` names `9_health_meter` and `91_xp_meter`, their geometry and bar textures. `Game/src/UI/UIMeter.cpp:29-36` loads `meter_bar_middle_back.png`; `:48-85` draws that white backing **before** the colored bar only when `mProgressBeforeMovement > mProgress` and name does not contain `xp_meter`. Edges and overlay follow at `:87-125`.
- `Game/src/UI/UIMeter.cpp:6-16,159-220`: displayed progress starts at 1, prior progress and target at 0, state normal. `SetProgress` starts a move if target differs from **displayed** progress; when already moving it changes only target, preserving the original movement baseline and start time. Moving interpolation is `baseline + (target-baseline) * min(elapsed,0.25)/0.25` for positive elapsed, becoming normal at elapsed >= 0.25. The focus-down branch tests `target - baseline < 0`, immediately sets displayed to target on the next `Update` and returns. In normal state a prior fill above displayed loses exactly 0.005 **per update**, with possible one-step undershoot before the next normal update sets it equal; it is not time-rate decay.
- `Game/src/UI/UIScreen.cpp:131-136` updates child meters first. `Game/src/UI/UIGameHudScreen.cpp:36-49,91-127,129-174` then registers health and focus targets. Thus a change first seen by the HUD registers the new target **after** the meter's update on that tick; that draw still has the old displayed fill. The next HUD update begins interpolation or focus snap. Health/focus cap-change branches can defer target registration and are separate from this slice.
- `Game/src/program.cpp:148-175` caps a delta to target cadence, runs `Update`, **then** increments `Timing::GetTotalTimeSeconds` by modified delta before `Render`. `UIMeter::SetProgress` samples the pre-increment total; the following update samples the next tick's pre-increment total. Do not equate the original render-time total with target-registration time.
- Linux `port/game/Hud.cpp:7-53` has health-length state but no progress state. `:38-39` immediately draws `health/maxHealth`; `:47` immediately draws `focus/100`. `port/linux/main.cpp:458-468` caps `dt` and advances `shaderClock` at loop start; `:1191-1205` draws the HUD after scene postprocess. `port/game/ShaderClock.h:14-21` already holds process-total modified time, including menu/modal updates. Its ordering is earlier than the original's increment, so passing its draw snapshot unadjusted may create a one-tick phase error. No `Hud` or backing asset edits are needed for the already-fixed health outer length/cap (`Hud.cpp:18-33`, HEAD `ec5c509`); leave focus geometry and orb text alone.
