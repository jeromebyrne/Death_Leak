# Post-vocal audio risk gate — read-only source audit, 2026-10-23 21:02Z

## One unowned release-critical risk: full SFX pool prematurely completes Health Devil dialog

At HEAD `410b14622956bdfd42efea307c8de9ea03604d4c` (the committed jump/roll vocal repair), `SDLSoundPlayer::Play` admits ordinary cues, including the new `JumpVocal`, only while `voices_.size() < 16` (`port/linux/SDLSoundPlayer.cpp:56-62`). `PlayDevilVoice` uses that **same** 16-voice pool and returns handle **0** when full, despite the device existing and SFX remaining enabled (`:63-69`). `VoiceFinished(0)` unconditionally returns true (`:71-77`). The live interaction stores this handle in `DevilDialog` (`port/linux/main.cpp:1119-1125`); the next live dialog update uses `VoiceFinished` (`:907-925`) and spawns the reward/pickup once the result is true. Thus 16 overlapping ordinary SFX when the player interacts with a Health Devil can silently skip the authored ~12-second voiceover and release its progression reward on the next eligible update. The newly added vocal cues share this pool, increasing pressure but not being the sole cause. This is an audio-to-gameplay sequencing failure, not a physical-speaker audibility question.

The original `Game/src/GameObjects/HealthDevil.cpp:73-84` waits for its voiceover to finish or for SFX to be disabled before `GiveReward`; pool saturation while SFX is enabled is neither condition. The existing `port/tests/save_bridge_test.py:222-252,542-578` covers deterministic `--simulate-only` dialog duration/cull/reward, not the live SDL handle-zero saturation path. The completed post-vocal CPU event and disk-mix fixtures in `port/PRIVATE_POST_VOCAL_INDEPENDENT_QA_20261023T2057Z.md` cover jump/roll transitions, picker branches, mute and mixed PCM, not Health Devil admission or reward timing. A targeted scan of `port/*.md` found no prior owner/fixture for this 16-slot Health Devil case. No observed user run is claimed to have hit it; it is a source-proven conditional failure with potentially release-critical progression impact.

## Exact CPU-only discriminator proposed for the audio owner

Use a dedicated no-renderer SDL-dummy backend fixture, built against the frozen HEAD's `port/linux/SDLSoundPlayer.cpp` and `port/audio/SoundPlayer.h`. Initialize with `SDL_AUDIODRIVER=dummy`; queue **16 long `Cue::FinalTitle` voices** before callback retirement (for determinism, hold/pause the callback or expose a test-only pool-fill seam), then call `PlayDevilVoice(false)` with SFX enabled. Assert: a nonzero voice handle is returned and `VoiceFinished(handle)` remains false immediately; advance/drain callbacks and assert it becomes true only after voice completion. The current source instead deterministically takes the `voices_.size() == 16` branch, returns 0, and reports finished immediately. Also run an unsaturated control (`PlayDevilVoice(false)` from an empty pool) to distinguish pool rejection from general audio initialization failure, and a separately SFX-muted control where immediate completion is expected. An exact invocation for a fixture implementing that controlled pool-fill seam is `SDL_AUDIODRIVER=dummy ./port/build/health_devil_voice_capacity_cpu_test`; no display, GPU or speaker is needed. A naive rapid-fire public-API-only test is timing-sensitive because callbacks can retire slots asynchronously; do not call such a flaky run a pass or fail.

A fix must reserve/priority-admit the story voice or preserve the authored-duration fallback when admission fails for saturation, while keeping true SFX-disabled behavior immediate; verify both audio admission and the live `main.cpp` reward boundary. This report does **not** implement or validate that fix.
