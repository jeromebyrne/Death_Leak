# Next source-proven forest-1 gameplay visual gap: weather lightning layer (2026-10-22)

## Verdict

The Linux port has no runtime **lightning flash layer**. Windows creates a camera-following `lightning_layer.png` sprite when rain begins and pulses its alpha over 0.4 seconds, including a flash at the start of the first rain session. This is a distinct, potentially screen-wide, **late/conditional** active-gameplay visual, not the already identified particle-alpha, firing-arm, shadow, aim-line, projectile, parallax/fog, or foliage issue. It cannot explain an early forest frame before weather is active. This is a source-semantic omission, not a measured pixel delta against a matched Windows capture.

## Exact source/port evidence

- Forest-1 explicitly allows weather (`Game/XmlFiles/levels/forest_exploration_1.xml:2-7`). Windows parses that flag and passes it to `WeatherManager::AllowWeather` (`Game/src/LevelProperties.cpp:56-58`). The manager starts enabled, with elapsed time zero and no prior weather (`Game/src/GameObjects/WeatherManager.cpp:45-59`); it advances in unpaused gameplay (`Game/src/GameObjects/GameObjectManager.cpp:205-217`). `WeatherManager::Update` advances its clock after updating states (`Game/src/GameObjects/WeatherManager.cpp:191-231`). `UpdateNoWeather` first starts rain only after **180 seconds** of weather-enabled elapsed time (`Game/src/GameObjects/WeatherManager.cpp:9,372-380`). The source comment at :374 says “20 seconds,” but the executable constant is 180; do not follow the comment.
- `StartRaining` creates the rain assets, marks the rain state, and records its start time (`Game/src/GameObjects/WeatherManager.cpp:234-253`). `CreateRainAssets` loads `Media\\lightning_layer.png` as a `ParallaxLayer`, sets `kWeatherForeground`, native 2048 × 2048 dimensions, camera-following X/Y, no UV scroll/parallax, and initial alpha zero (`Game/src/GameObjects/WeatherManager.cpp:114-140`). `ParallaxLayer::Update` actually follows camera X/Y (`Game/src/GameObjects/ParallaxLayer.cpp:26-35`). The shipped texture exists at `Game/Media/lightning_layer.png`.
- In rain, with no flash active, `mTimeUntilNextLightning` starts at zero (`Game/src/GameObjects/WeatherManager.cpp:56-57`), so the first `UpdateRaining` after rain starts calls `DoLightningEffect` when elapsed time is positive (`Game/src/GameObjects/WeatherManager.cpp:314-364`). It schedules subsequent flashes 10–30 seconds apart (`:15-17,256-268`). During an active flash, layer alpha follows `1 - (elapsed - start)/0.4`, then returns to zero (`:346-358`). The Windows drawable loop skips alpha-zero objects but draws visible ones in depth order (`Game/src/GameObjects/GameObjectManager.cpp:302-329`). Rain lasts a randomized 70–120 seconds with a 3-second outro (`Game/src/GameObjects/WeatherManager.cpp:10-13,245-249,314-328`); stop removes the lightning layer (`:270-295`).
- The port loader builds visual objects from XML and special-cases only forest emitter ID47 (`port/game/LevelScene.cpp:155-163,268-292`); its draw loop iterates that loaded sprite list and sprays (`port/game/LevelScene.cpp:760-783,837-848`). Active gameplay invokes that scene draw, combat draw, and postprocess (`port/linux/main.cpp:1099-1112`). No weather state or `lightning_layer.png` load/draw exists in `port/game` or `port/linux` (targeted source search); the renderer itself notes “rain is not ported yet” (`port/linux/SDLRenderer.cpp:304-311`). These are positive control-flow boundaries plus an absence check, not a claim that existing captures reached 180 seconds.

## Bounded fix recommendation

Add a weather-enabled gameplay clock and a **separate `kWeatherForeground` lightning sprite** for forest-1 (or levels whose XML `allow_weather` is true). Load the shipped texture once; keep it camera-following at the source's configured 2048 × 2048 world-unit size, with zero alpha outside flashes. The constructor assigns an initial Y offset, but `ParallaxLayer::Update` replaces Y with camera Y when follow-Cam-Y is true (`Game/src/GameObjects/WeatherManager.cpp:123-135`; `Game/src/GameObjects/ParallaxLayer.cpp:26-35`), so do not preserve that offset as a persistent displacement. Start the first rain session after 180 weather-enabled, unpaused seconds; trigger the first flash on the following rain update, decay alpha over 0.4 seconds, schedule later flashes at the source's 10–30-second interval, and remove/disable the layer when rain ends. Preserve the source's foreground painter order and existing source-alpha/postprocess path. Seed or inject the random intervals for a deterministic validation at pre-rain, onset, mid-flash, after-flash, and rain-stop times. Verify timing/camera before pixel comparison; a matched Windows input, clock, weather RNG, and frame would be needed for image parity.

Do **not** bundle rain-drop particle rendering, weather sound, foliage multiplier, global lighting, or unrelated particle-alpha work into this bounded lightning-layer fix. A fuller weather-system port can follow separately. The source-proven priority here is conditional: early held-fire forest captures may show no effect at all.
