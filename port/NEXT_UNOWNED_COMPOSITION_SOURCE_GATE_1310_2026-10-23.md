## Current checked-in source chain

- `Game/XmlFiles/UI/game_hud.xml:76-98` authors `9_health_meter` (red health) and `91_xp_meter` (cyan focus). Source `UIGameHudScreen::Update` calls `UIScreen::Update` **before** setting current health/focus targets (`Game/src/UI/UIGameHudScreen.cpp:36-49,91-127,129-173`; `Game/src/UI/UIScreen.cpp:131-136`). Thus a changed value is registered after the widgets' update that tick; the first interpolation/update of the new target occurs on the following UI tick.
- `UIMeter::SetProgress` retains separate displayed progress, target, prior fill and transition start; a second target arriving during `kBarMoving` does not reset its origin/start (`Game/src/UI/UIMeter.cpp:6-16,159-170`). `UIMeter::Update` linearly interpolates over `kBarIncreaseTime=0.25f` using `Timing::GetTotalTimeSeconds()`; in `kNormal`, prior fill decreases by `0.005f` per update until it catches displayed progress (`:4,173-220`). The `xp_meter` negative-difference branch snaps a focus decrease (`:193-199`). `UIMeter::Draw` first draws `meter_bar_middle_back.png` when old fill exceeds displayed health, then the colored bar and meter edges/middle (`:33-36,48-125`). The backing is a separate overlaid texture, not an alpha adjustment to the red bar.
- Checked-in Linux `Hud::Load` loads edge/bar/focus/overlay/orb, but no backing (`port/game/Hud.cpp:7-14`). `Hud::Draw` computes red width directly from current `health/maxHealth` and cyan width directly from `focus/100`, without displayed/target/prior-fill state or a clock (`:15-53`; state/header `port/game/Hud.h:6-17`). The live active-play caller is `port/linux/main.cpp:1191-1205`, after scene/postprocess. Therefore 25→20 health immediately submits a 0.8-width red bar and no trailing white bar; source first registers a 0.8 target with the previous 1.0 fill still displayed, then transitions over subsequent ticks and retains the old white backing. Source focus decrease snaps on its next meter update; Linux submits it immediately. Focus increase is also interpolated in source but immediate in Linux.
