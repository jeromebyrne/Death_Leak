# All-four-flip rotation: focused implementation/test plan — 2026-10-22

## Scope and source contract

Read-only CPU/source plan for the renderer owner; no source, build, GPU lane, or shared checkpoint touched. The current `SHADER_ROTATION_VISUAL_AUDIT_2026-10-22.md` establishes that Windows `Sprite.cpp::RecalculateVertices` binds UVs to centered BL/BR/TR/TL vertices, authored horizontal/vertical flips become negative world scales (`Sprite.cpp::Initialise`), and `GameObject.cpp::Update` builds the row-vector rotation/scale/translation world transform. `BasicLightTexture.fx`, `BasicLightTexture_PixelWobble.fx`, and `FoliageSway.fx` all apply World to those source vertices; the latter sways the post-World positions, X then Y. In screen-Y-down coordinates, let `sx = flipX ? -1 : +1`, `sy = authoredFlipY ? -1 : +1`. The UV-labeled Windows point is `F A(-theta) q`, `F=diag(sx,sy)`, whereas SDL's flip-before-rotation copy (and the port's wobble quad) is `A(phi) F q`. Therefore **`phi = -sx*sy*theta`**, in degrees, for all four combinations:

| Authored X | Authored Y | Needed SDL angle |
|---|---|---|
| false | false | `-theta` |
| true | false | `+theta` |
| false | true | `+theta` |
| true | true | `-theta` |

This is an angle/geometry contract, not a claim of pixel-matched Windows images. It applies to the *authored* Y flag, not blindly to `draw.flipY`: `LevelScene::Draw` deliberately inverts Y for ordinary SDL copies and preserves authored Y for custom shader paths.

## Exact current code to change

1. `port/render/OrdinarySpriteRotation.h::OrdinarySpriteRotationDegrees(float radians, bool flipX)` is X-only. Extend its signature to include **authored** `flipY` and implement the sign table above; update its comment. `port/game/LevelScene.cpp::Draw`, around lines 997–1012, has both `object.flipY` and the special `draw.flipY` calculation. Pass `object.flipY` to the angle helper, preserving its current ordinary-vs-custom `draw.flipY` mapping. This one computed `draw.rotationDegrees` feeds all branches and `SpriteMayIntersectViewport`.
2. `port/linux/SDLRenderer.cpp::DrawSprite`, around lines 207–249, sends ordinary `effectlighttexture` sprites to `SDL_RenderCopyExF`; its centered rotation/SDL flip behavior is the reference for the angle helper. Preserve tint, alpha, UV shift, source, repeat, and scale behavior. Do not modify the zero-angle repeat/parallax fast paths as part of this angle fix.
3. `SDLRenderer.cpp::DrawPixelWobble`, around lines 318–380, builds a screen quad and rotates it by `+sprite.rotationDegrees` (line 353). Its UVs come from `port/linux/WobbleUV.h::PixelWobbleVertexUV`, using authored flips; the fragment shader performs V-then-U wobble and final V conversion. The shared all-flip angle should fix its geometry without changing wobble UV/time/scroll/alpha logic. Forest-1 `ScrollingSprite` ID119 (X=false,Y=false) remains `-0.11 rad`; ID122 (X=false,Y=true) changes from `-0.11` to `+0.11 rad` (`forest_exploration_1.xml:1631–1659`).
4. `SDLRenderer.cpp::DrawFoliageSway`, around lines 383–449, already applies authored X/Y reflection to each source vertex but then rotates by **`-sprite.rotationDegrees`** at line 389. After the shared all-flip helper, remove that extra minus: rotate by `+sprite.rotationDegrees`, so the pre-sway world point uses `A(phi)F`. Do not simply feed the new angle into the unchanged minus expression. Keep per-source-corner intensities, `FoliageSwayWorldVertex` X-before-Y displacement, `FoliageScreenV`, repeat tiling, and UV labels untouched. Waterfall-top leaf-shadow IDs 66/67 (`waterfall_top.xml:1148–1176`) are X=true/Y=false, angles `-0.099903/+0.080501 rad`, repeatX=true and nonzero top-corner sway; they currently have the wrong base-rotation sign. A no-flip/nonzero-angle foliage control is also essential because the old implementation fails that parity too.

Run the focused tests and then the project's normal integration gate in the renderer owner's build lane; this report did not run them.

## Other angle consumer to audit, separate from the requested three

`SDLRenderer.cpp::DrawSprite` gives `sprite.rgbGain > 1` priority over pixel-wobble/foliage and dispatches `DrawDamageBurst` (`SDLRenderer.cpp:258–317`). That custom GL branch also rotates by `+sprite.rotationDegrees` (line 290) and maps flip flags into corner UVs. Thus it **does consume the shared angle**, including transient player hit flashes; `port/tests/damage_burst_test.cpp` checks gain lifecycle/alpha, not rotated corner parity. Audit its UV-labeled geometry against the same four-parity contract and add a nonzero-angle four-flip CPU control before claiming every custom shader path covered. `ViewportCull.h` also consumes the angle for conservative admission, but is not a shader branch. The source's `Sepia.fx` postprocess is screen-space and does not consume per-sprite angle.
