# ScrollingSprite prior-world-matrix placement — 2026-10-24 01:33Z

## Source contract and bounded correction

Original `ScrollingSprite::Update` calls `Sprite::Update(delta)` before advancing its scroll lerp (`Game/src/GameObjects/ScrollingSprite.cpp:22-55`). `Sprite::Update` reaches `GameObject::Update`, which builds `m_world` from the then-stored position (`Game/src/GameObjects/GameObject.cpp:160-212`). `GameObjectManager::Draw` later uses that stored matrix; it does not rebuild it after the lerp (`Game/src/GameObjects/GameObjectManager.cpp:302-329`). Thus a scrolling sprite's current alpha but **previous eligible-update XY** is submitted; even the reset/early-return tick refreshes the world matrix from the preceding XY. The port previously advanced `sprite.x/y` and immediately rendered from those new coordinates (`port/game/LevelScene.cpp`), one eligible update ahead. This is distinct from the already-corrected ParallaxLayer follow-X lag, Forest ID37, and Sea-2 AmbientBird.

The correction stores each ScrollingSprite's pre-lerp world XY on eligible updates, initializes those fields from authored XML position, and uses them only for scrolling draw placement. The lerp, fade, update-zone predicate and alpha are unchanged. Forest-1 IDs 119/122 (`forest_exploration_1.xml`, 1000/45 and -750/70 world-units/s) and Waterfall IDs 117/118/119/121 (`waterfall_top.xml:1798-1861`, broad 1988×1290 pixel-wobble fog quads) are active visual witnesses. At 60 Hz the Forest-1 positions can differ by roughly 0.25–0.33 screen pixel; broad transparent quads can alter many sampled pixels.
