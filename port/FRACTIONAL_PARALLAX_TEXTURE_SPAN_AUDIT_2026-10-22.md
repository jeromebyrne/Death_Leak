# Forest fractional-parallax texture-span gate — 2026-10-22

## Verdict and scope

**Direct `GL_REPEAT` on the SDL-owned texture is conditional, not yet cleared for IDs 37/40.** The saved physical-GPU logs identify an OpenGL/nouveau NVE7 renderer, but do not record `SDL_GL_BindTexture`'s returned `texw`/`texh`, the bound GL allocation dimensions, GL version, or texture mip levels for these two assets. In particular, ID40's 2048×677 image is non-power-of-two in Y; its XML and PNG dimensions alone do not establish that SDL's physical allocation has a unit Y span. This was a read-only source/asset/log audit at HEAD `89c9f50`; no build, game, Docker, GPU, ffmpeg, renderer edit, or shared checkpoint edit was made. The concurrent fog GPU/build worker owns the renderer lane.

Original `Game/src/GameObjects/ParallaxLayer.cpp:37-83` writes continuous float U coordinates, and `Game/ShaderFiles/BasicLightTexture.fx:11-17` specifies U/V WRAP with `MIN_LINEAR_MAG_POINT_MIP_LINEAR`.
- `port/game/LevelScene.cpp:1234-1245` hands the SDL-facing positive camera-X phase to `render::Sprite` and disables the ordinary repeat-X path. Current `port/linux/SDLRenderer.cpp:246-261` consumes it through integer `SDL_Rect` segments; `port/linux/UVWrap.h:15-26` floors `fract(shift)*pixels`. Thus a float-UV GL quad would close a real subtexel-phase omission; the existing CPU plan quantifies the held-camera 1000→1000.5 same-cut example (`port/FRACTIONAL_PARALLAX_UV_IMPLEMENTATION_PLAN_2026-10-22.md`). This is not evidence of a broad forest-color defect or matched Windows parity.
- `SDLRenderer.cpp:143-186` creates an opaque SDL texture via `SDL_CreateTextureFromSurface`, deduplicated by path/`TextureId`. The renderer already calls `SDL_GL_BindTexture(texture, &textureWidth, &textureHeight)` in custom paths (`:276-282`, `:335-349`). Those returned floats are the usable image spans of the physical binding; they are not measured or logged for 37/40. Existing `port/build/forest-follow-lag-gpu-2026-10-22/*.log` and `port/build/fog-mip-gpu-gate-2026-10-22/*.log` report `OpenGL device vendor=nouveau renderer=NVE7`, but no spans or level allocation. Hardware identity does not resolve an SDL backend's padding/ownership choice.
- The fog mip code (`SDLRenderer.cpp:335-405,586-683`) deliberately creates a **private** exact-size GL texture and mip chain keyed by `TextureId` only for PixelWobble draws; fallback binds SDL's texture and uses `GL_LINEAR` minification. IDs 37/40 use ordinary full-texture UV-scroll dispatch, not PixelWobble, so they do **not** acquire those private mip names. The private cache is destroyed before SDL textures/renderer (`:42-49`); its existence does not authorize modifying the SDL object's levels or sampler. The source's mip-linear minification remains a separate filter-fidelity question for these ordinary sprites. Setting `GL_LINEAR_MIPMAP_LINEAR` on an SDL-owned texture without a proven complete mip chain could make it incomplete; generating mips or changing base/max level on that shared object could affect later SDL copies and ownership/invalidation. For a first fractional-phase slice, preserve the prior minification class (`GL_LINEAR` when minified), keep `GL_NEAREST` magnification, and do not claim exact D3D mip parity.

## Concrete direct-binding gate

At the later **exclusive** physical-GPU integration, on the same SDL texture objects actually selected for IDs 37 and 40, require: (1) `SDL_GL_BindTexture` succeeds in the current desktop OpenGL renderer/context; (2) both returned spans are finite, positive, and within a small documented float tolerance of **1.0**; (3) the physical allocation and sampler state are compatible with NPOT `GL_REPEAT` for ID40 (desktop GL 2.0+ full NPOT capability or a verified equivalent), with no GL error; (4) `GL_TEXTURE_MIN_FILTER` is selected only from filters backed by complete existing levels—base-level `GL_LINEAR` is safe for this slice, mip-linear only after independently owned/verified levels; and (5) all SDL-object wrap/min/mag state, unit-0 binding/active unit, program, matrices, blend/depth state and SDL bind/unbind pairing are restored after `SDL_RenderFlush`. Log ID/path, `TextureId`, PNG dimensions, `SDL_QueryTexture` dimensions, returned spans, GL version, selected path and any fallback **once** per ID. Do not infer the result from one other texture or from SDL's logical query dimensions.

If either returned span is below unity (especially ID40 Y), **do not** merely multiply modulo-one UVs by that span and turn on `GL_REPEAT`: hardware would repeat the padded allocation, sampling padding at the wrap seam; linear filtering makes that especially visible. Keep the existing integer SDL-copy fallback, with the fractional limitation honestly retained, or create a separately owned exact-size RGBA GL texture per `TextureId` (row orientation matched to the existing SDL-bound custom quad), and gate NPOT repeat/optional mip completeness there. A direct binding should be used only after this runtime gate passes for **both** IDs; the source audit cannot mark either physical span as passed.
