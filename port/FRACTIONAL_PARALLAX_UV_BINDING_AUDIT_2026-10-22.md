# Fractional parallax UV binding — read-only source audit (2026-10-22)

## Finding

The mathematical/CPU command is present, but the live renderer never consumes it. `ParallaxUV.h` computes a modulo-one, one-texture-span TL/TR/BR/BL quad and requires a successful GL binding, unit X/Y texture spans, and supported NPOT repeat before choosing the direct path (`port/linux/ParallaxUV.h:8-19,25-37,40-63`). `ParallaxUVCommand.h` prepares a `FloatQuad` for finite, nonzero, full-texture, unrotated scrolls and otherwise retains the original shifts/flips for the integer path (`port/linux/ParallaxUVCommand.h:9-38`). Yet `SDLRenderer.cpp` does not include or call either helper (`port/linux/SDLRenderer.cpp:1-20`); its scroll branch always calls the integer `ForEachUVWrapSegment` Y-then-X and `SDL_RenderCopyExF` (`port/linux/SDLRenderer.cpp:226-266`). Thus **there is no runtime GL bind/capability/span measurement, repeat-sampler setup, or float-UV draw**. The CPU tests prove intended command behavior, not actual SDL/GL binding (`port/tests/fractional_parallax_binding_cpu_acceptance_test.cpp:1-4,37-79`; `port/tests/fractional_parallax_command_test.cpp:1-3,46-75`).

The loss is specifically fractional phase between source texels: the legacy helper floors `phase * pixels` to an integer cut (`port/linux/UVWrap.h:14-26`), so small camera movement can leave the same source interval until a texel boundary. The authored D3D layer instead writes float UVs directly each draw: X shift from camera/auto-scroll, `repeatsX` forced to exactly 1, and Y shift/one-span in its own branch (`Game/src/GameObjects/ParallaxLayer.cpp:43-90,114-155`). The Linux scene already supplies signed normalized X/Y shifts and uses the whole-quad parallax route rather than ordinary `repeatX` (`port/game/LevelScene.cpp:1242-1256`; `port/render/Renderer.h:46-56`). Do not alter scene state as part of this binding patch. Authored X auto-scroll is not modeled by that scene loader, which currently reads only Y auto-scroll (`Game/src/GameObjects/ParallaxLayer.cpp:50-63`; `port/game/LevelScene.cpp:393-401`); that is a separate parity scope.

## Minimal implementation after GPU lane release

1. Confine live changes to `port/linux/SDLRenderer.cpp` (plus a narrowly scoped CPU adapter/test if needed). Include `ParallaxUVCommand.h`; keep existing branch order: damage burst, pixel wobble, foliage sway, ordinary repeat-X, UV scroll, ordinary copy (`port/linux/SDLRenderer.cpp:226-266`; `port/linux/ParallaxUV.h:51-63`). Only full-texture, zero-rotation, nonzero UV-scroll commands enter this seam. Do not route pixel-wobble or rotated/source-rect sprites through it.
2. In the UV-scroll branch, prepare/measure a `ParallaxUVBinding`: selected backend is actual `opengl` (not merely accelerated; renderer identity is available in initialization at `port/linux/SDLRenderer.cpp:79-110`), `SDL_GL_BindTexture` succeeds, returned X/Y spans are finite unit spans, and NPOT repetition is supported for the queried texture dimensions. Check actual capability before setting `npotRepeatSupported`; do not infer it from SDL's accelerated flag. On any failed/unsafe condition, execute the current nested integer-copy code unchanged (`port/linux/ParallaxUV.h:22-37`; `port/linux/SDLRenderer.cpp:250-261`). If a bind fails, ensure fallback occurs without an unmatched unbind.
3. On eligible bindings, flush queued SDL draws before direct GL, set repeat on S and T, and draw exactly one quad at the existing float destination using `PrepareParallaxUVCommand(...).uv` in TL/TR/BR/BL order. Preserve the SDL-facing signed shift, flip semantics and one-span dimensions; do not reverse phase a second time (`port/linux/ParallaxUV.h:11-19`; `port/game/LevelScene.cpp:1245-1251`). Match current texture tint/alpha, blend and scene min/mag sampling, and restore changed GL program, active texture/binding, matrix, sampler, blend and other state before resuming SDL. Existing direct-GL effects demonstrate flush/bind/state restoration patterns, but are not themselves the parallax binding (`port/linux/SDLRenderer.cpp:270-334,335-405`). Do not assume an SDL texture's GL coordinate orientation without checking a controlled rendered case; CPU corners alone cannot establish it.
4. Keep `ParallaxUVCommandKind::NotApplicable` on the ordinary route, `LegacyInteger` on the exact pre-existing `UVWrap` fallback, and `FloatQuad` on the direct GL route (`port/linux/ParallaxUVCommand.h:16-38`). If factoring a small sink/decision adapter for CPU testing, make it independent of SDL/GL; avoid changing the existing scene command structure or neighboring effect implementations.

Add a decision/sink test that proves one float-quad submission versus legacy nested copies; existing `Sink` is test-local and not evidence of renderer wiring (`port/tests/fractional_parallax_command_test.cpp:32-44,53-57`). Compile it as a standalone CPU target after the lane is released; current Makefile exposes only the basic UV helper target (`port/Makefile:20-26`).

Verify smooth subtexel displacement, seams, orientation, tint/alpha, sampler filtering and post-draw state; separately force an ineligible binding and compare the fallback to the current integer route.
