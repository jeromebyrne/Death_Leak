# Ninja lethal debris — terrain-contact contract (read-only source audit, 2026-10-22)

Baseline: committed `bbc113b`. No source, build, GPU, or integration state changed for this audit. This report proposes one bounded implementation slice; it does not claim the current port has passed a terrain-contact test.

## Source behavior that matters

- `NPC::SpawnLimb` creates each `Debris` at `(NPC.x, NPC.y + 50)` with a **30×30 collision box**, gravity amount `.25`, bounce dampening `.55`, and inter-debris collision disabled (`Game/src/GameObjects/NPC.cpp:569-586`). The `80×80` constructor dimensions are not its collision box; native texture sizing is a separate visual concern.
- `Debris::OnCollision` ignores callbacks before its first `Update`, plus other debris (for these limbs), currency orbs, water blocks, projectiles, and foliage. An `IsSolidLineStrip()` callback changes `kActive` to `kFadingOut` once (`Game/src/GameObjects/Debris.cpp:68-72,110-163`). Character contact can double horizontal velocity but does not initiate fade. Solid boxes alone are not the fade trigger.
- Crucial distinction: this callback is dispatched on **strict collision-AABB overlap**, not necessarily an actual downward intersection with the authored line. `CollisionManager::DetectAndResolve` calls `Debris::OnCollision(strip)` when `IsColliding` finds `debrisRight > stripLeft && debrisLeft < stripRight && debrisTop > stripBottom && debrisBottom < stripTop` (`Game/src/Core/CollisionManager.cpp:19-80,84-109`). `SolidLineStrip::OnCollision` performs its separate bottom sweep against line segments (`Game/src/GameObjects/SolidLineStrip.cpp:126-209`); its result is not a prerequisite for the debris fade callback. The source debris AABB is `[x-15,x+15] × [y-15,y+15]` (zero offset; `Game/src/GameObjects/SolidMovingSprite.h:37-69`). A simple line-crossing-only port would therefore be a different contract.
- Fade countdown starts at **4.0 s on first qualifying contact**, not at spawn: `mTimeUntilFadeOutFully` defaults to `4.0f` (`Game/src/GameObjects/Debris.h:41-47`) and is decremented only in `kFadingOut` (`Game/src/GameObjects/Debris.cpp:80-107`). In the final `.2 s`, both matrix scales become `remaining/.2`; at `remaining <= 0`, removal is requested. This path does **not** animate alpha. `Debris::Update` uses the `mIsOnSolidLine ? .003 : .02` rotation coefficient (`:74-79`), but `SolidLineStrip::OnCollision` deliberately does not set on-line state for debris (`Game/src/GameObjects/SolidLineStrip.cpp:168-173`). Thus terrain contact does not by itself switch debris to the `.003` coefficient.
- `ParticleSpray` is a distinct, non-colliding particle class (`Game/src/Particles/ParticleSpray.cpp:160-342`); its five ninja explosion-line entries are not part of this terrain-contact slice. Do not route them through debris contact/expiry.

## Committed Linux gap

`port/game/Combat.cpp:162-181` creates ten debris and five spray entries, but gives every debris a spawn-relative `4.2f` lifetime. `Combat::Update` advances all entries, never checks terrain contact, and removes them when `age >= lifetime` (`:218-231`). `AppendPainterItems` shrinks **and alpha-fades** debris for the last `.2 s` of that spawn timer (`:571-582`). `port/tests/ninja_death_effect_test.cpp:26-56` checks spawn, movement, and eventual expiry only; it cannot discriminate contact-driven versus unconditional removal. `LevelScene::Ground()` currently retains only per-segment endpoints (`port/game/LevelScene.h:62,111`; `LevelScene.cpp:243-251`), not each strip's collision AABB/dimensions.

## Bounded implementation slice for integration owner

1. In `port/game/LevelScene.h/.cpp`, retain each authored `SolidLineStrip`'s collision AABB (position plus `collisionboxdimensions` and optional offsets), separately from existing `GroundSegment` geometry. Keep the current `Ground()` consumer intact. The relevant XML object already exposes `position`, `dimensions`, and `collisionboxdimensions` in the level-load loop; use the **collision** dimensions (with offsets), not visual dimensions or the segment min/max, for source broadphase parity. A read-only accessor such as `SolidLineStripBoxes()` suffices.
2. In `port/game/Combat.h/.cpp`, give non-spray `DeathEffect` a `fading`/`fadeRemaining` state initialized active/4.0s. After at least one debris movement update, compare its current 30×30 AABB against authored strip AABBs using the four **strict** inequalities above; on first overlap, latch fading. Decrement the fade timer only while latched; remove on `fadeRemaining <= 0`. Preserve existing movement approximation and spray lifetime logic in this slice. As source physics timing is not yet exact, avoid claiming first-contact frame equivalence beyond the AABB contract.
3. In `AppendPainterItems`, set debris width/height scale to `clamp(fadeRemaining/.2,0,1)` only once fading and within the final `.2s`; before contact and during the preceding 3.8s keep size 1.0. Keep debris alpha opaque (source scales matrix, not alpha). Leave spray drawing unchanged. No fallback spawn-age cull: in a level without strip contact, source debris does not start this fade timer. `ClearLevel` remains the lifecycle boundary.
4. Focused CPU-only verification in `port/tests/ninja_death_effect_test.cpp` (or a dedicated adjacent test): (a) kill in a no-strip scene, update past 4.2s, assert ten debris remain; (b) a strip AABB arranged for first contact after spawn, assert exactly ten enter contact-driven expiry and remain through 3.8s after contact, shrink only in final .2s, then disappear after 4.0s; (c) use a strip whose **collision AABB** overlaps the 30×30 debris box while its visible segment does not cross the debris bottom, proving the callback-vs-line-sweep distinction; (d) an ordinary `SolidBox` does not trigger debris fade; (e) five spray entries retain independent expiry. These tests should use deterministic positions/velocities or a narrowly exposed effect diagnostic, not depend on GPU pixels. Run only the focused CPU test and necessary build gate in the owning lane.

Out of scope: accurate Windows `rand()` stream, full debris bounce/position resolution, collision with characters/other solids, collision-manager camera broadphase culling, and matched GPU image comparison. The above is a source-backed lifecycle slice, not complete debris physics parity.
