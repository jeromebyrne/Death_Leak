## Measured recurring traffic and exact-order constraints

The existing strict physical nouveau/NVE7 1280×720 Waterfall-top steady trace has 27 `glDrawArrays`, 204/205 `glBindTexture`, two framebuffer binds, one scene clear, 30 program selections and zero uploads or framebuffer copies per frame. Four serial GPU-query replays of the same active frame measured waterfall-sheet IDs 13/14 at 0.229/0.273 ms median, overlapping fog IDs 117/118/119/121 at 0.107/0.458/0.450/0.449 ms, and the one Sepia quad at 0.890 ms. Earlier independent 180-update physical query runs measured Sepia 1.151–1.173 ms/frame in Waterfall and 1.190–1.219 in Forest, with exactly one scene-target begin, one output switch, one scene-texture bind and zero copies per frame. These are query-on raster durations, not removable work or query-off FPS predictions.

The current `SDLRenderer::DrawPixelWobble` flushes the SDL painter queue, enters private GL, binds the mip texture, sets blend and a 1280×720 orthographic projection, supplies five per-sprite uniforms, draws one quad, and restores program/texture/matrix/blend state. IDs 13/14 are adjacent and share texture/uniform values, but combining them would only avoid one setup/draw submission while retaining both alpha-blended quad fragment workloads (~0.50 ms together in replay). Fog quads have distinct `spriteAlpha` values (0.015, 0.005, 0.005, 0.004166667) and overlap; a one-draw conversion needs a new per-vertex-alpha shader path plus proof that rasterization and blend order are bit-identical. Fourteen intervening draws separate sheets from fog, and nine separate fog from Sepia. Cross-boundary fusion/reordering is not painter preserving.

`ApplyScenePostprocess` already omits the full-output clear at 16:9, binds the completed scene target, switches to output and draws exactly one nonlinear Sepia quad before HUD. Removing the target/sample/draw changes authored colors; moving Sepia into individual sprites changes alpha-composite inputs and the `step` red-excess branch. The scene clear is still needed. A previous five-uniform-location cache eliminated 4,255 CPU/driver queries in 180 updates but left GPU pass traffic unchanged and slightly lost serial native-clock p50/p95/p99. A prior ordered branch batch saved just one draw/bind over 60/180 updates. These negative controls further undercut a small setup-only rewrite as this pass-traffic slice's candidate.

## Disposition

**Reject a new shader/pass-traffic B arm for this bounded gate.** The measured high-cost quads are visible alpha-blended output, and the only source-proven compatible adjacent pair is a one-submission setup optimization, not removal of its measured GPU raster cost. There is no established pixel-preserving recurring pass, copy, clear, or fragment-work removal to implement. No candidate build or strict physical A/B/A was run, so there is no candidate pixel, call, timing or VRAM improvement claim; previous baseline measurements are not repackaged as this run's proof. No software patch is accepted.

Capture ordered command/target state and look for a redundant flush or whole covered region whose removal can be algebraically proved before implementing.
