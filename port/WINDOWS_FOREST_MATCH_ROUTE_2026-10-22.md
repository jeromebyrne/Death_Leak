# Original Windows forest-1 matched-frame route (read-only audit, 2026-10-22)

## Verdict

No existing local **original Windows** forest-1 frame with known camera/state is available for pixel-locked comparison. The only identifiable original forest-1 image is the Steam JPEG `../store_media/screenshots/14.jpg`: the unique ID-117 dojo-scroll pickup, right branch/orb cluster and three raft pieces match forest-1 XML (`port/FOREST_REFERENCE_AUDIT.md`). Its camera, player position, capture resolution before store processing, elapsed frame, animation/weather phases and HUD/pickup state are absent. The ~700 camera-X estimate is only a composition search seed; it cannot recover the original exact frame. Screenshot 13 is less specific; screenshot 19 and the trailer do not provide this frame. Existing `port/build/forest14-linux-match-2026-10-22/linux-r110.png` is a **Linux** composition approximation with different HUD/state, not a paired Windows capture (`port/FOREST14_LINUX_MATCH_CAPTURE_2026-10-22.md`). A repository-wide `find . -type f -iname '*.exe'` returned no executable; the `windows_content` tree supplies assets/XML/shaders/DLLs, not the game EXE. No local Windows capture, PDB or deterministic original replay was found.

## Concrete acquisition route

1. Obtain the **original shipped Windows EXE/depot** (prefer it for release-renderer fidelity) or compile the checked-in `DeathLeak.sln`/`Game/Game.vcxproj` on Windows with its v143/Windows 10 SDK and legacy D3DX10 dependencies. Record EXE SHA-256, source revision if compiled, asset/XML hashes, settings, GPU/driver and runtime. Do not silently call a modified debug build the shipped executable.
2. Run with the game working directory containing `XmlFiles`, `Media`, `ShaderFiles` and DLLs. Load `XmlFiles\\levels\\forest_exploration_1.xml` through the original quick-play/level-select entry (`Game/src/UI/UIQuickPlayScreen.cpp`). Navigate until ID-117 pickup, right branch/orbs and left raft compose similarly to screenshot 14. This yields a **new original-renderer reference**, not the exact historic Steam instant.
3. For a valid paired capture, instrument one frame at the postprocess/backbuffer boundary, before `Graphics::Present` (`Game/src/Game.cpp` `PostDraw`; `Game/src/Core/Graphics.cpp` Present). Save the lossless backbuffer PNG/BMP **and a same-frame metadata sidecar atomically**; do not use a desktop JPEG or a screenshot with an unknown resize. The existing commented debug text in `Game::Draw` reads `Camera2D::Position()` but was disabled; rendering that overlay would contaminate the comparison, so log metadata to file instead. Capture after camera follow/update and distinguish the logical camera position from any shake or view-matrix timing. Disable overlays or document them.
4. Capture the Linux port at the **same output/backbuffer size and explicit camera/player/state**, first compare static geometry/occlusion with dynamic layers controlled, then compare color/pixels on genuinely phase-matched frames. Do not compute a whole-image pixel metric against screenshot 14; use it only to find the scene.

## Minimum per-frame sidecar

- Original EXE/build/content hashes; exact level path; save/session identity and whether the screenshot was from quick-play, save-load or continuous play.
- Rendered frame index, fixed/real delta and total simulation/shader time; backbuffer width/height, fullscreen/window scaling, zoom and effective world-to-screen transform/projection; actual camera X/Y (including any shake offset) and follow/lag state.
- Player X/Y, facing, velocity, animation name/frame/phase, health; currency-orb total and IDs collected, ID-117 pickup present/collected, relevant other object states. Screenshot 14's HUD shows 13 orbs/reduced health whereas the existing Linux R:110 capture has 3/full health.
- Weather mode and transition, rain/fog/particle emitter state/seed/age, foliage and pixel-wobble time/direction, and any temporary damage/slow-motion postprocess state. Record random seed/RNG state or freeze/disable stochastic effects on **both** sides for a static-layer comparison.
- Lossless image hash and pixel dimensions, capture API/stage (pre/post sepia, pre/post HUD), color space/format and the exact metadata-to-image frame association.

Why camera metadata matters: forest-1 XML initializes camera `(0,3400)`, zoom 1, follows X but **not Y**, with X lag 15 and offset 0; player starts near `(-43,3385)` (`Game/XmlFiles/levels/forest_exploration_1.xml`). `GameObjectManager::Initialise` first places camera at player, then follows with lag; `Game::Update` calls follow before draw. Thus player X, frame count or XML's camera Y alone cannot infer the precise rendered camera. Actual camera position is exposed by `Camera2D::Position()` (`Game/src/Core/Camera2D.h`), making same-frame logging practical when a Windows run is available.

**Current blocker:** there is no executable or instrumented original frame locally, and the Steam JPEG cannot reveal its hidden temporal/state variables. The next useful acquisition is one new lossless Windows frame plus sidecar from an original Windows run; exact recreation of Steam screenshot 14 is not supportable from present evidence.
