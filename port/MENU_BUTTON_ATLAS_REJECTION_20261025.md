# Menu-button atlas physical gate — rejected (2026-10-25)

## Scope and isolation

Starting HEAD `664e63a`. The four committed opt-in atlas families are gamepad icons, gameplay HUD, six scene branches, and cart/track props. Rock4/5 are rejected for exact minified/rotated pixels; tree2_blur's combined page fails exact sampling and its tiny solo page has no GL submission gain. This slice selected a **distinct** ten-PNG menu-button family (`Game/Media/UI/buttons/`): play, settings, back, edit and apply_changes normal/focus images. Their call sites are ordinary UI images in mainmenu, options, level-select, pause/death and object-editor XML; no repeat, UV shift, private scene shader or render target is admitted by the exact-path map. Existing virtual-ID dedicated fallback protects any future wrap/private-shader draw; other scene classes remain excluded.

The opt-in `DEATHLEAK_ATLAS_MENU_BUTTONS=on` candidate was built from an isolated detached clean-HEAD worktree; the production working tree's seven dirty tracked paths, especially unstaged raft-mip `port/linux/SDLRenderer.cpp`, were not edited or staged. The candidate used the existing runtime atlas-region path and a test-only `--full-rgba` mode of the deterministic free-rectangle packer. All ten original RGBA rectangles were preserved (including hidden RGB) with two-pixel extrusion. One occupied-bounds page is 2930×516, below the 4096 maximum; 909,554 source pixels / 1,511,880 page pixels = 60.16% full-rectangle occupancy. A second compatible page was not opened. The manifest includes source SHA-256, page/rect, original size and zero trim offsets; verification reconstructed every RGBA source byte. This page is **not** a production artifact.

## Strict physical NVE7 result

All runs used physical Xorg `:0`, SDL `video_driver=x11 name=opengl flags=14 accelerated=1 software=0 vsync=1`, nouveau `NVE7`, actual/logical 1280×720. Serial fixed-dt 60-frame menu A/B/A capture used the same control/candidate binaries and exact menu state. The two controls had identical full BMP SHA-256 `8b9b4a87...14ea94cf4`; the candidate had `cbee9a3b...a0107562`. Decoded RGB differed at **13 pixels / 17 channel bytes**, mostly ±1 in the displayed menu-button area. Alpha was unchanged. This is a strict exact-pixel failure despite byte-identical source reconstruction. Page-offset/filtered sampling precision is a plausible mechanism, not independently proved for every pixel. The candidate is rejected; no production code, manifest or PNG is committed.

Serial physical 60-frame apitrace control/candidate/control counted `glDrawArrays` **840/840/840** and `glBindTexture` **1214/1084/1214** (full traces including startup). Page sharing saved 130 binds, but no real draw submission; it cannot override failed pixels. Serial untraced 360-frame menu runs with a test-only `SDL_RenderPresent` interval interposer (first 120 frames excluded; 240 samples each) yielded p50/p95/p99 milliseconds: **16.6813/17.0704/17.3466 → 16.6829/17.1457/17.5877 → 16.6820/17.0444/17.6799**. Results overlap controls; no FPS gain. The interposer, binaries, traces, captures and manifest remain only in ignored `port/build/atlas-buttons-20261025/`; the isolated worktree was removed after the gate. No production timing or art code changed.

## Remaining exceptions and next gate

Broad 896-PNG classification remains incomplete. Dedicated paths remain for repeat/wrapped ground and raft, UV-shifted backgrounds, private fog/water/foliage shader draws, render targets and untested animation/source-rect variants. Menu-button page rejected on exact pixels, rocks rejected on exact pixels, and tree blur solo rejected on no draw/bind gain. The next in-scope action is a **UV/filter precision discriminator** for nearest UI virtual regions (e.g. page-local integer texel coordinate geometry versus SDL normalized source-copy), then an exact full-frame physical A/B/A retry only if controlled pixels match. Alternatively target a measured consecutive ordinary scene run whose atlas page can actually reduce GL submissions. No 60-FPS, broad atlas, 8K/high-Hz, VRAM/thermal or release acceptance follows from this gate.
