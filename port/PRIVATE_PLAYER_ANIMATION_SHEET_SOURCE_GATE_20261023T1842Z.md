# Private Forest-1 player animation source gate — 2026-10-23 18:42Z

## Verdict

**Concrete source-level pose mismatch: grounded crouch and crouch-release are absent from the Linux player animation path.** This is a conditional active-play mismatch (press/release crouch on traversable Forest-1 ground), not a measured Windows/Linux frame discrepancy or a claim that the existing clip contains crouching. It changes the focal player's entire silhouette and sequence cadence, not just a small effect. The separate ID2/ID10 occlusion, HUD, ID37, and raft/foliage mip lanes are untouched.

## Evidence

- Forest-1's always-updated Player ID2 selects `player_anim_default.xml` (`Game/XmlFiles/levels/forest_exploration_1.xml:33-46`). This XML is **not a packed sprite sheet**: each `Crouch`/`CrouchUp` frame names a separate `duck_default_*.png` (`Game/XmlFiles/animation/player_anim_default.xml:673-724`). The original loader loads every frame filename as a texture (`Game/src/Animation/AnimationSequence.cpp:48-69`); `AnimationPart::CurrentFrame` selects a texture by frame index, clamping a finished nonlooping sequence to its last texture (`Game/src/Animation/AnimationPart.cpp:67-100`). Do not infer an atlas UV/sheet-cell bug from these sources.
- Windows keyboard **S** on grounded, non-melee, non-wall-side, non-rolling player sets crouch and stops X acceleration (`Game/src/InputManager.cpp:649-663`); gamepad down-stick has the analogous gate (`:146-160`). `Character::UpdateAnimations` gives `mIsCrouching` priority over air/run/idle, selects `Crouch`, advances it at its authored 40 fps, and keeps its final frame while held (`Game/src/GameObjects/Character.cpp:905-921`; `Game/XmlFiles/animation/player_anim_default.xml:673`). On release, `SetCrouching(false)` marks `mWasCrouching` (`Character.cpp:2037-2051`); the later `CrouchUp` branch selects and animates its 40-fps sequence until finished (`Character.cpp:1064-1081`; XML `:720`). The source animator advances at most one frame per update and uses its previous update-delta slot (`Game/src/Animation/AnimationPart.cpp:201-229`); exact displayed-frame registration still needs a runtime trace.
- Linux's player loader enumerates only Still/Running/Strafe/Jump/Slide/Roll/Swim/Melee/Intro sequences—neither `Crouch` nor `CrouchUp` (`port/game/LevelScene.cpp:408-440`). `UpdatePlayerVisual` has no crouch argument; its grounded neutral selection is `Still` (`port/game/LevelScene.cpp:1144-1147,1207-1226`), and the active caller passes movement/combat/strafe/aim state only (`port/linux/main.cpp:1240-1245`). Thus even with the authored PNGs present, this active Forest-1 pose/cadence cannot be emitted through the current Linux path. The report does **not** assert that Linux currently binds S to crouch; the missing control/state is part of this parity gap.
