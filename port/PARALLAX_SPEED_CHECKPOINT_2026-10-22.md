# Foreground/background parallax camera-speed correction — 2026-10-22

Windows `ParallaxLayer::Draw` writes **left** U=`xShift+1`, **right** U=`xShift`, with `xShift=-cameraX*multiplierX` for non-horizontally-flipped layers. Therefore a rightward camera change moves texture features **left** by `quadWidth * multiplierX * cameraDelta`, independent of the followed quad's stationary screen position. `GameObject::Update` supplies separate depth-parallax factors for ordinary sprites; the port's `(worldX-cameraX)*factor` already reproduces those magnitudes.

The SDL renderer samples left-to-right before any flip. The port previously passed the D3D phase sign through unchanged, so its unflipped parallax texture moved **right**, opposite the source, while foreground/background depth sprites moved left. `LevelScene::Draw` now reverses the SDL X phase sign, preserving XML multipliers and camera-follow placement. This changes parallax camera/render math only; it does not modify authored horizontal-flip flags, assets or raft/exit objects. Horizontal orientation parity of the full source UV mapping is a separate lane.

Forest-1 XML proves the intended relative speeds: background ID1 is 1985 world units wide with X multiplier .000059, yielding .117115 world px per camera px; foreground IDs37/40 are 2048 wide with .000690, yielding 1.41312 world px per camera px (12.07× background). At 2/3 projection these are .0780767 and .94208 screen px per world camera px. The focused `port/tests/parallax_speed_test.cpp` loads authored forest-1 XML, checks static followed quads and UV increments for camera X 0→100, and passes. The existing source mappings for ordinary depth sprites are unchanged.
