# Independent source review: controller-strafe body (2026-10-22)

Scope: read-only inspection of original Windows gameplay source, Player XML, and the bounded contract `port/STRAFE_BODY_IMPLEMENTATION_CONTRACT_2026-10-22.md`. This report is the sole file written by this reviewer; no source/test/checkpoint changes, build, GPU/display run, or parity capture.

## XInput eligibility and priority — confirmed

- `Game/src/InputManager.cpp:449-459` clears `IsStrafing` before any branch and returns when **neither** `abs(RX)` nor `abs(RY)` is strictly greater than `XINPUT_GAMEPAD_RIGHT_THUMB_DEADZONE`. Equality on either axis is inactive. `:462-472` then rejects rolling, either just-fell flag, and melee. `:474-499` uses the normalized RX **sign**, but compares *raw* LX to the **right-thumb** deadzone: `RX <= 0 && LX > +D` sets `-1`; `RX > 0 && LX < -D` sets `+1`; otherwise no strafe. `GetThumbstickRange` divides by `short` max, 32767 (`:13,751-754`). Thus RX=0, `abs(RY)>D`, LX>D selects aim left/strafe -1; exact LX=+D/-D does not. Same-side LX/RX does not select strafe. The contract captures these comparisons.
- Gamepad dispatch processes melee/crouch/roll, then horizontal movement, then aim/fire, then strafing (`InputManager.cpp:566-591`). Movement itself rejects just-fell, crouch, roll, melee, wall jump, and uses normalized LX magnitude `>0.2` (`:162-185`). This motion gate is **not** the strafe gate; an eligible LX can cause strafing even if motion is prevented by another movement guard (notably crouch or wall jump), though the ordinary moving animation still requires velocity. The port's 8000 binary motion gate remains a separate policy, as the contract says.
- Source has an **aim-only non-strafe horizontal flip** for RX positive/negative (`InputManager.cpp:488-497`), after motion processing. Contract correctly defers it. Further timing nuance for implementer: `Character::AccelerateX` applies its `mIsStrafing` flip after base acceleration (`Character.cpp:1527-1575`), but gamepad dispatch calls horizontal movement before current-tick `ProcessStrafing_gamepad` (`InputManager.cpp:578,589`). A bounded visual pose may use current eligibility, but should not claim exact source flip timing on the entry tick.

## Player body selection and exact XML map

- `Character::UpdateAnimations` puts hard-impact recovery first (`Game/src/GameObjects/Character.cpp:746-766`), then short-impact recovery (`:769-790`), melee (`:792-874`), roll (`:875-904`), crouch (`:905-921`), midair/water (`:922-989`), airborne wall slide (`:990-1005`), and only then ordinary side-clear horizontal motion with strict `abs(source vx)>0.05` (`:1006`). In that branch, active strafe selects `StrafeBack` when `mStrafeDirectionX != m_direction.X`, else `StrafeForward`; no strafe selects `Running` (`:1008-1033`). Comparing against stored direction, not velocity sign, is necessary. This agrees with the contract. Note: wall-side collision while grounded also blocks this ordinary branch (`:1006`), even though the dedicated wall-slide branch only handles airborne state (`:990-991`).
- XML `Game/XmlFiles/animation/player_anim_default.xml:366-387`: `StrafeForward` has 20 frames, index 0→19 mapping `strafe_default_000`→`_019`; footsteps are index 0 (`:367`) and index 10 (`:377`). `:389-522`: `StrafeBack` has 20 frames, index 0→19 mapping `_019`→`_000`; footsteps are index 9 (`_010`, `:445`) and index 19 (`_000`, `:515`). Both declare default 30, min 4, max 60 FPS (`:366,389`). `StrafeBack` includes per-frame `<skeletonparts>` absent from forward frames (`:390-521` vs `:367-386`); a body-texture-only port should not claim skeleton/arm pose parity from these PNGs. These facts support contract fixtures expecting entry `_019`/next `_018` for back and entry `_000`/next `_001` for forward. The reverse sequence reuses the same 20 PNGs, so texture caching may share texture IDs while retaining different ordered frame lists.
- `AnimationPart::SetSequence` itself unconditionally calls `Restart` (`Game/src/Animation/AnimationPart.cpp:142-157`); **the transition-only behavior is from `Character::UpdateAnimations` guarding each call by current sequence name** (`Character.cpp:1012-1029`), not from `SetSequence`. `AnimateLooped` advances at most once per update and carries elapsed excess (`AnimationPart.cpp:169-197`). On transition, test frame zero with a sub-frame `dt`; a sufficiently large first tick may already advance one frame.

## Contract correction / acceptance notes

1. **Correct Player-specific animation multiplier before implementation.** Contract's “dry non-sprint `abs(sourceVx * 1.8 * 3.0)`, sprint/wet `abs(sourceVx * 2.0 * 3.0)`” describes the `Character` constructor default (`Game/src/GameObjects/Character.cpp:55`) but **not Player**: `Player::Initialise` overrides `mRunAnimFramerateMultiplier = 2.65f` (`Game/src/GameObjects/Player.cpp:72-82`). The shared moving branch uses that member for strafe too (`Character.cpp:1033-1050`), so Player strafe dry non-sprint rate is `abs((portVx/60) * 1.8 * 2.65)`; sprint/wet is `abs((portVx/60) * 2.0 * 2.65)`, subject to source slow-motion adjustment and sequence clamp. Do not change the existing Running 2.65 factor; do not add a 3.0-only strafe factor. Source water path passes `overrideMinFramerate=true` (`Character.cpp:1037-1040`, `AnimationSequence.h:15-25`), although water normally takes higher-priority swim selection.
2. Treat input eligibility and body eligibility separately. A valid opposed-stick pair can coexist with a higher-priority pose or blocked movement; only ordinary `abs(vx)>3` with no side collision should select a strafe body (`Character.cpp:1006-1033`; current port `port/game/LevelScene.cpp:1084-1098`). Clear transient strafe each tick and on disconnect. Keep roll/melee/just-fell rejection; if just-fell is unavailable, label the port approximation and fixture it, as the contract directs.
3. Load both names only in the Player body allowlist (`port/game/LevelScene.cpp:403-431`), not the arm allowlist (`:434-440`). Preserve XML order and texture identity; verify footstep metadata if loaded, but leave the port's Running-only material spray branch unchanged (`LevelScene.cpp:1127-1131`). Use aim sign only for a selected strafe body's visual flip; keep movement/combat facing independent as contracted. Verify exits from grounded side collision, stopped movement, neutral aim, roll, melee, and water/air, plus transition reset and one-frame-per-tick progression. XML metadata alone is not proof of emitted strafe spray.

Verdict: threshold/sign and frame-order portions of the implementation contract are source-supported. The Player rate `3.0` assertion and the attribution of transition-only restart to `SetSequence` need correction; neither warrants expanding this bounded body slice into camera, projectile, arm, aim-line, or spray work.
