# Fog pixel-wobble mip-linear minification: bounded implementation plan — 2026-10-22

## Scope and feasibility

Read-only design for the **pixel-wobble draw path** in `port/linux/SDLRenderer.cpp`; no renderer/source edit, build, GL probe, or physical-GPU capture was performed. `HIGH_AREA_SOURCE_PARITY_AUDIT_2026-10-22.md` already establishes the narrow contract gap, so this note covers implementation seams rather than repeating its scene audit. The original `Game/ShaderFiles/BasicLightTexture_PixelWobble.fx:13-19` specifies `MIN_LINEAR_MAG_POINT_MIP_LINEAR`, U/V wrap; its pixel shader perturbs V then U and multiplies sampled alpha by the float opacity (`:56-64`). D3D texture creation uses default `D3DX10CreateShaderResourceViewFromFile` load information (`Game/src/Core/TextureManager.cpp:50-66`). Linux currently sets `GL_LINEAR` min and `GL_NEAREST` mag on the bound SDL texture (`SDLRenderer.cpp:319-374`), with no mip chain. `fog.png` is 1988×1290 and the audited high-area fog draw is 1325×860 logical pixels (~0.667 scale), so the sampler is in its minification regime; curtains 13/14 at ~540×1081 from 512×1024 are slightly magnified and are not the motivating case. This is a source-level sampler mismatch, **not** a demonstrated visible Windows-frame delta.

Feasible with a private GL mip texture cached per static image/`TextureId`. Prefer that to `glGenerateMipmap` on an SDL-owned texture: `SDL_CreateTextureFromSurface` returns an opaque SDL object (`SDLRenderer.cpp:143-171`), and `SDL_GL_BindTexture` exposes its backend GL binding plus `texw`/`texh` scale, not ownership of its levels, allocation dimensions, invalidation, or post-unbind sampler policy. Generating levels or changing `GL_TEXTURE_BASE_LEVEL`/`MAX_LEVEL` there may affect subsequent `SDL_RenderCopyExF` users of the same object; SDL scale mode is also changed per draw (`:195-207`). The private copy isolates the mip chain and sampler state. A direct SDL-texture experiment is possible later only after backend/context behavior and restore/invalidation are verified; it is not the default landing design.

## Proposed narrow implementation seam

1. Keep `textures_` and `paths_` as the existing SDL ownership/cache (`SDLRenderer.cpp:711-713`); add a separate wobble-only cache keyed by `TextureId` holding one owned `GLuint`, source dimensions, complete-chain status, and optional failure status. Retain a `TextureId -> path` mapping or the RGBA pixels **only for on-demand wobble upload**. The current PNG decoder already produces straight RGBA8 (`:143-159`); avoid permanently retaining every PNG's bytes. On first eligible pixel-wobble draw, decode the cached path once (or retain the original bytes just until upload), upload a full-dimension GL texture, generate all levels, and cache it. No ordinary scene/HUD/damage/foliage copy changes. Existing static file-backed textures need no per-frame regeneration; if texture reload/update is added later, invalidate the private cache alongside that update. Delete private GL textures before renderer/context teardown, as the destructor already does for `sepiaTexture_` (`:24-36`). Do not cache or delete an SDL backend texture name as though it were owned here.
2. Preserve orientation. Existing wobble GLSL uses `vec2(uv.x, 1.0-uv.y) * textureSpan` (`:597-609`) to sample SDL's bound texture, whose `SDL_GL_BindTexture` returns possibly non-unit spans (`:329-330`). A private full-size GL upload should vertically reverse the PNG rows before `glTexImage2D` so GL V=0 represents the image bottom; then the existing `1.0-uv.y` samples the image top for authored V=0. Supply `(1,1)` as `textureSpan` for that private texture. Do not merely upload top-first PNG bytes and retain `1-V`: that reverses the artwork. Keep vertex UV shift, flip, rotation, Y-before-X wobble, wrap and float `sprite.opacity` unchanged. Full-size NPOT texture avoids exposing SDL padding in the mip chain; verify complete NPOT repeat/mipmap support in the selected desktop OpenGL context before enabling it.
3. Generate the complete mip chain from level 0 through 1×1 (for 1988×1290, levels 0–10); set `GL_TEXTURE_MIN_FILTER=GL_LINEAR_MIPMAP_LINEAR`, `GL_TEXTURE_MAG_FILTER=GL_NEAREST`, `GL_TEXTURE_WRAP_S/T=GL_REPEAT`, and base/max levels to the generated range if supported/needed. Resolve `glGenerateMipmap` or its supported extension via the actual current-context function pointer/capability path rather than assuming `GL_GLEXT_PROTOTYPES` makes it available. Set/restore `GL_UNPACK_ALIGNMENT` for tightly packed RGBA upload; check allocation/generation errors and texture completeness. On a capability/upload failure, use the *existing* SDL-bound `GL_LINEAR` path for that draw and log a bounded, factual fallback once, never a partially built mip texture. The original D3D default loader's exact mip bytes, sRGB/gamma treatment, and hardware LOD rounding are not proven by source alone: this matches the declared filter/LOD class, not guaranteed byte-exact Windows sampling.
4. Preserve the existing raw-GL/SDL interop boundary: `SDL_RenderFlush(renderer_)` before private binding/draw (`:319-330`); capture old program, matrix mode, active texture unit and **unit-0 `GL_TEXTURE_BINDING_2D`**, plus pixel-store if uploading. Save/restore wrap/min/mag only when mutating the bound object; for the private texture these are owned, fixed properties and need not be reset each draw. Restore bound texture on unit 0, GL program, projection/modelview stacks, matrix mode, active unit, blend/depth/texture enables and other pushed attributes on every normal/error exit. Do not call `SDL_GL_UnbindTexture` unless `SDL_GL_BindTexture` actually succeeded on the SDL fallback; a private texture has no SDL bind pair. Keep the current fallback path's saved SDL sampler parameters (`:333-374`). Refactor the common cleanup into one scoped exit/RAII path so upload errors do not leak GL state into the next SDL copy. Treat SDL renderer/context recreation as cache invalidation; the current class creates one renderer/context (`:43-124`), but a future recreation must not reuse old `GLuint`s.

The likely small patch surface is `SDLRenderer.cpp` only: a private texture record/cache, lazy upload helper, and selection/cleanup in `DrawPixelWobble`. No scene XML, sprite state, shader UV math, or ordinary sampler change is needed. The private-copy cost is about 13.7 MB RGBA8 for a 1988×1290 fog texture including a 4/3-sized mip chain, plus one first-use decode/upload; actual driver memory and timing require later measurement. If the same image is used by multiple fog sprites, key by `TextureId` so all share that chain.

## Deterministic CPU-only verification contract for the later patch

Add a pure-data test target/function with **no SDL window, GL context, Xorg, or GPU**. It should validate decisions and image math, not claim that a GPU driver was exercised:

- Test the mip builder/oracle on a small power-of-two and NPOT synthetic RGBA image with alternating high-frequency colors, non-opaque alpha, and distinct top/bottom marker rows. Define each next level as 2×2 box reduction with explicit odd-edge handling; assert exact dimensions through 1×1, stable pixel values, and the row-flip/upload orientation mapping. This is a deterministic expected-data check; GL driver mip texels can differ by a rounding unit, so keep runtime comparison toleranced separately.
- Implement an independent CPU texture-sampling reference: wrapped bilinear within levels, `lambda = log2(max(sourceWidth/destWidth, sourceHeight/destHeight))` for an unrotated, unwarped full-UV quad, trilinear interpolation between floor/ceil levels for positive lambda, and nearest magnification for negative lambda. At the audited 1988×1290 → 1325×860 mapping, expect lambda ≈ log2(1.5) ≈ 0.585 and a blend of levels 0/1, **not** base-only bilinear. Check exact non-boundary texel centers, fractional UV wrap, both flips, alpha interpolation, and a magnified case where the mip chain is ignored. For wobble/rotation, do not use destination-ratio lambda as a pixel-exact oracle: implicit derivatives vary across the warped quad; only verify existing UV-order/flip functions separately.
- Extract/test a pure cache-policy decision (load once for repeated fog `TextureId`, reuse across IDs sharing the same path, invalidate on texture replacement/context recreation, fallback on simulated generation failure) and a fake-GL call/state ledger for balanced bind/restore on success, failed upload, and failed SDL fallback bind. This ledger can assert intended state transitions but cannot prove SDL backend interoperability.

CPU gate: all deterministic image/cache/state tests pass and the patch changes only the wobble path. **Separate GPU/build owner** then verifies actual extension availability, GL errors, cached texture completeness, state after a following SDL copy, fog-only minification A/B, magnified curtain control, and a matched Windows frame/clock if visual parity is claimed. No CPU oracle should be reported as a rendered visual match.
