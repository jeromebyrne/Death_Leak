## New scene-local source discriminator

An authored XML/depth-order inventory found `first_ninja_arena.xml` kGround IDs 29–34 as a six-ordinal ordinary run: `structural_post, raft, structural_post, raft, structural_post, structural_post`. IDs 22–24 are an earlier raft/raft/post run. These are genuinely alternating textures in authored painter order, unlike already-tested same-texture particle coalescing and the previously tested Waterfall branch triple (which saved only one GL draw/bind over 60 or 180 updates). They share `effectlighttexture`, no repeat X/Y, no animation, authored alpha=1, and use ordinary SDL sprites at these sites. The same raft asset also has private pixel-wobble uses elsewhere; the existing virtual-region path would require dedicated fallback there. The arena family is **source-plausible**, not proven same-frame visible or steady-state GL-switch reuse: XML alone cannot establish camera clipping, SDL flushes, or what the physical GPU receives.

Both arena sources are strongly minified and rotated: raft PNG 1024×280 is drawn around 490–557×161–194 world units with rotations including -0.01973 and +0.45027; post PNG 190×891 is drawn around 53–56×248–264 with rotations including -0.16967 and +2.91018. Current `DrawSprite` selects linear scale mode for minification, calls `SDL_SetTextureScaleMode` per draw, and preserves rotation/source mapping. Atlas-only identity is **not** a proven bind/submission saving; prior physical traces showed per-draw sampler setter traffic and an equality-guard prototype removed many binds without repeatable frame-time gain. A geometry batch of these rotated/minified draws would need independent exact UV, sampler, blend/tint, rotation-center and painter-order proof. The rock and tree-blur full-RGBA atlas probes previously failed physical exact pixels by 1-LSB samples on minified/rotated sprites, so their result cannot be presumed safe here.

## Deterministic pack and memory gate

Using the existing `port/tools/atlas_pack.py --full-rgba`, the two-source full-RGBA page and manifest verified exact RGBA reconstruction and 2-pixel extrusion. It is cropped to occupied bounds at 1222×895, below the 4096 ceiling, but source occupancy is only 456,010/1,093,690 = 41.69%. Raw RGBA allocation proxy is 4,374,760 bytes versus 1,824,040 bytes for separate source rectangles: +2,550,720 bytes if both are resident. Adding the adjacent `muckpile` yields a 1544×1179 cropped page and only 39.45% source occupancy. Adding same-scene dirt-patch and cart-track instead yields 2250×895 and 45.44% occupancy, +4,394,688 raw bytes beyond four dedicated source rectangles. These are allocation proxies, not calibrated live VRAM. The packer is deterministic and density-prioritized within its free-rectangle algorithm, but none of these **scene-local groupings is a densely filled page** under the requested standard. Packing unrelated fillers solely to inflate occupancy would lose scene-residency rationale and does not establish recurring calls.

## Disposition and next distinct discriminator
