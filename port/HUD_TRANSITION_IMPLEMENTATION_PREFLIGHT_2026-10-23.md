## Resolved Windows behavior

- `Game/src/UI/UIMeter.cpp:6-16,159-220`: each meter starts displayed=1, target=0, previous-fill=0, normal. `SetProgress` compares the incoming target to **displayed**, not the stored target. On a new move it snapshots displayed and pre-increment process total; while moving, repeated calls replace target without resetting baseline/time. A target equal to current displayed during motion does nothing, leaving the earlier target active.
- On moving `Update`, focus (`xp_meter`) snaps down if `target - movementBaseline < 0`, even if the target is above the currently displayed value. Otherwise positive elapsed interpolates from the original baseline toward the latest target over 0.25 s; elapsed <= 0 leaves displayed unchanged. Completion sets normal at >=0.25 s. Health decreases interpolate too. In normal state previous-fill decreases by **0.005 per update** while greater than displayed; a one-step undershoot is possible, then next normal update equalizes it.
- `Game/src/UI/UIScreen.cpp:131-136` updates child meters before `UIGameHudScreen::Update` registers targets (`Game/src/UI/UIGameHudScreen.cpp:36-49,91-174`). A changed target first seen on tick T therefore draws old fill on T; movement begins on the following update. Cap-change branches at `:96-117,144-164` can additionally defer registration; fixture should first stabilize unchanged caps and not conflate that behavior with transition timing.
- `Game/src/program.cpp:148-175`: `SetProgress` and meter `Update` see total time **before** the frame's modified delta is committed; render happens after commit. `Game/XmlFiles/UI/game_hud.xml:76-98` names `9_health_meter` and `91_xp_meter`. `UIMeter.cpp:29-36,62-85` loads `meter_bar_middle_back.png` for both and draws the white previous-fill **only for health** when previous > displayed, at the same bar origin before the colored fill. Existing XML meter alpha applies to its draw path. `UIMeter.cpp:87-125` draws edge/middle afterward; the port's existing overlay/edge ordering is a separate issue and is not in this slice.
