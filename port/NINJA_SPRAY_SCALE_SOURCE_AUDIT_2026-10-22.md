# Ninja material spray — source-backbuffer and painter audit (2026-10-22)

Read-only source audit; no source edits, build, Docker, GPU, or capture. This addresses only the scale/painter questions left open by `NINJA_MATERIAL_SPRAY_SOURCE_QA_2026-10-22.md` and does not revisit its already-fixed first-frame alpha finding.

## Backbuffer finding

The checked-in Windows entry point initializes **a 1920×1080 backbuffer** (`Game/src/program.cpp:15-18,277`); its Steam Deck branch changes only `gWindowWidth/gWindowHeight` to 1280×720, not those backbuffer variables (`program.cpp:101-109`). `Graphics::Initialise` retains the passed backbuffer dimensions (`Game/src/Core/Graphics.cpp:53-63`), `Game` sets `GameScale = backbuffer/(1920,1080)` (`Game/src/Game.cpp:142-143`), and the camera uses that backbuffer for its orthographic projection (`Game/src/Game.cpp:92`; `Game/src/Core/Camera2D.cpp:10-30`). Therefore the *source-code default* spray has `GameScale.X=1`. A 1280×720 window alone is **not evidence** of a native 1280×720 Windows backbuffer. This is a source-code conclusion, not proof of a particular shipped binary or captured runtime mode.

At that default scale, the runtime factory's extra multipliers leave sampled size/speed and `scaleTo=8` unchanged (`Game/src/Particles/ParticleEmitterManager.cpp:422,478-499,515-525`). The port keeps 1920-authored spray geometry and projects it once at 2/3 into 1280×720 (`port/game/Combat.cpp:188-220`; `port/game/ParticleSpray.h:83-99`). Thus a **1920 Windows frame downsampled to 1280**, not a hypothetical native-1280 Windows frame, is the source-grounded scale comparator. Do not change the port's `scaleTo=8` merely because the factory references `GameScale.X`.

If a *native* 1280 Windows backbuffer is independently established, parity changes: Windows samples initial size and speed at 2/3, then also passes `8×2/3` as the lifetime scale target (`ParticleEmitterManager.cpp:478-499,515-525`; `Game/src/Particles/ParticleSpray.cpp:269-283`). Port initial size/speed project at 2/3, but its lifetime target remains 8 (`port/game/Combat.cpp:200-220`; `port/game/ParticleSpray.h:55-59,83-92`). At the end-of-life size target (just before removal), port size would approach **1.5×** native-1280 Windows size for the same base sample. Also, Windows adds the literal `+30` after `Bottom()` on a backbuffer-scaled ninja, while port projects that `+30` to 20 pixels (`Game/src/GameObjects/Character.cpp:1648-1659`; `Game/src/GameObjects/GameObjectManager.cpp:453-463`; `port/game/Combat.cpp:190-193`; `port/game/ParticleSpray.h:87-92`). These are conditional distinctions, not proven mismatches in the default source mode.

## Painter integration finding

Windows runtime emission appends the spray to `m_gameObjects` and sorts by depth (`Game/src/Particles/ParticleEmitterManager.cpp:543-546`; `Game/src/GameObjects/GameObjectManager.cpp:961-989,1022-1025`); its draw loop traverses that list (`GameObjectManager.cpp:297-329`). The port appends the material spray as a depth-3000 dynamic painter callback (`port/game/Combat.cpp:603-611`) and `LevelScene::Draw` stable-sorts dynamic items descending, then draws them after static objects of equal depth (`port/game/LevelScene.cpp:1012-1020,1038-1048,1118-1122`). This is compatible with a later-inserted runtime spray at equal depth in the original list (C++ `list::sort` is stable). The focused CPU test bypasses the unified scene painter (`port/tests/ninja_death_effect_test.cpp:67-75`), so it does not prove on-screen integration. There is no authored `ParticleSpray` element in `Game/XmlFiles/levels/first_ninja_arena.xml`, removing the previously noted authored-spray equal-depth tie from this particular arena; no GPU/pixel sign-off is implied.

## Highest-value bounded discriminator

For the next visual comparison, record the **actual Windows backbuffer dimensions** alongside one lethal arena frame, then compare at the same output resolution: if 1920×1080, downsample the Windows frame to 1280×720 and retain the port's current spray scale; only if a native 1280×720 backbuffer is demonstrated should the conditional lifetime-size/`+30` offset differences above become correction candidates. The source default strongly predicts the former. Leave painter code unchanged until an actual arena capture shows an occlusion/order error.
