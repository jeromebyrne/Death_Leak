## Exact-raster/UV certification decision

The offline tool is deliberately an **eligibility oracle, not an exact NVE7 raster oracle**. Source-zero certification is firm for guarded texels, but cannot establish exact output for a segmented/cropped quad: SDL/OpenGL's implementation-specific subpixel edge snapping, top-left triangle ownership, float32 vertex and UV rounding, varying interpolation, and the new interior/crop edges have not been compared against the original on the real NVE7. The recovered blobs cover only one pose and the original triangles; they do not contain a segmented draw or per-fragment interpolants. Mathematically affine UV agreement is insufficient to prove byte-exact sampling around retained colored boundaries after changing triangle diagonals/coordinates. A CPU top-left raster approximation would only emulate a chosen precision and cannot certify this driver's output. No universal exact pixel equivalence across camera, zoom, and shake is therefore proved, despite the attractive source-space area. **Do not implement physical candidate B under the task's exact-safe-only condition.** No B binary, pixel A/B/A, p50/p95/p99, GL-call/bind, or memory gain is claimed. The prior production baseline still applies because this commit has no runtime change; this gate did not run a new physical A/B/A without a certified B.
