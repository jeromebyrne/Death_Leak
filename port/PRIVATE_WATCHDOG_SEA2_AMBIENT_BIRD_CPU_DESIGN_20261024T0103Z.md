## Source-equivalent contract

- `Game/XmlFiles/levels/sea_2.xml:286-343` has two `AmbientBird`s, IDs 15/16, at (-8137.453125,-704.309814) and (-4654.958496,-1021.309814); both have `travel_offset=+5000`, `always_update=true`, `updateable=true`, `kFarBackground`, alpha 0.4, X acceleration rate 0.5, max X velocity 2.5, X resistance 0.99, gravity off, and `XmlFiles\bird_anim.xml`. Source `Game/src/GameObjects/AmbientBird.cpp:12-46,189-193` defaults travel to 1000 for other XML, reads the authored value, normalizes `(travel_offset, direction.Y)` on initialization, and captures the authored start position. For these two positive offsets the intended horizontal direction is +1; avoid assuming arbitrary nonzero Y direction without checking inherited initialization.
- Per active tick, `AmbientBird::Update` calls `NPC::Update(delta)` **first** (`:101-108`). The inherited `Character`/`MovingSprite` chain calls `Sprite::Update`, which calls bird `UpdateAnimations` before movement integration (`Game/src/GameObjects/Sprite.cpp:358-368`, `MovingSprite.cpp:53-65`). In normal gameplay, inherited movement integrates the acceleration set on the *previous* tick: `nextVelocity = velocity + acceleration*direction`, clamps to authored max X, advances X by `velocity*(delta/targetDelta)`, then multiplies X velocity by current resistance and zeros magnitude <0.1 (`MovingSprite.cpp:78-95,147-159,199-214`). `AmbientBird::Update` then calls `AccelerateX(direction.X)`, setting rate `mAccelXRate=0.5` for the **next** update (`Character.cpp:1527-1549`, `MovingSprite.cpp:276-300`). Thus a fresh, zero-velocity bird need not move on its first update; at target delta, unobstructed second tick starts the positive X displacement. Model inherited collision/stun/slow-motion only if needed for this visual path; don't replace this with `x += speed*dt` or claim exact Windows pixel parity from the simplified path.
- After acceleration, reset check uses strict travel crossing: for positive direction, `x > startX + travelOffset`; for nonpositive direction, `x < startX + travelOffset` (`AmbientBird.cpp:112-163`). Reset only if **both** current object and authored start are outside the camera view and a player exists with `abs(playerX-currentX)>1000`. The authored-start visibility test uses start parallax offsets `(camera-start)*(multiplier-1)` in X/Y; `kFarBackground` multiplier is `(0.25,0.95)` (`GameObject.cpp:879-898`). `Camera2D.cpp:39-104` uses parallax-adjusted object bounds for current visibility and strict point-in-frustum for start visibility. Reset assigns `position=startPosition` only: no velocity, acceleration, direction, flap timer, frame or alpha reset. This can permit an immediate continued flight. Level-editor mode returns after inherited NPC update but before acceleration/reset/flap logic.
- Animation is two-state, independent of travel (`AmbientBird.cpp:52-83,165-187`). Initial `isGliding=false`, both timers 0. Each `UpdateAnimations` (inside inherited update) selects `Running` when not gliding (9 FPS) or `Still` when gliding (1 FPS), changing sequence only if name differs, then `AnimateLooped` and sets body texture. `SetSequence` restarts frame/elapsed clock (`AnimationPart.cpp:142-158`); `AnimateLooped` adds `Timing::LastUpdateDelta` and advances **at most one frame per update**, subtracting one frame interval (`:160-192`). `Game/XmlFiles/bird_anim.xml:5-15`: Still is `ambient/2.png`; Running cycles `ambient/1.png`, `2.png`, `3.png`. The XML FrameRate 45 is overridden to 9/1 upon state switch, not a persistent 45-FPS contract. After inherited update, flap logic decrements the active timer: initial flapping timer 0 causes `isGliding=true` and samples flap duration `2.00..3.39` seconds in 0.01 increments; later gliding timer expiry sets `isGliding=false` and samples wait `0.90..1.89` seconds. Sampling is exactly `rand()%unsigned((max-min)*100) + min*100`, then `*0.01`; C++ float conversion/PRNG global sequence means exact phase is not derivable from XML. The texture/state switch is visible on the **next** inherited animation update, not the tick that flips the flag. No flap timer is reset on travel reset. `OnCollision` always returns false; `OnDamage` is empty (`AmbientBird.cpp:31-33,86-99`).

- Fresh state: initial flapping, direction +1, velocity/latched acceleration zero, start=current. With a controlled 0.01-sample and target-delta tick, first tick does **not** translate X, latches +0.5 acceleration, flips to gliding and loads the 2.00..3.39 timer; second eligible tick translates X positively using the prior acceleration, then selects Still (with restart). Assert the one-tick switch delay. (Account for inherited initialization if test fixture establishes a different initial acceleration.)
- While Running, controlled animation elapsed at 1/9 sec advances 1→2→3→1, with a large elapsed delta still advancing only one frame/tick. On state change, clock/frame restart; Still remains texture 2. At the flap duration boundary, transition to Running is selected by the following animation update and the wait timer is in 0.90..1.89 sec range. Use injected sample values, not live `rand()`.
- At `x == startX+5000`, no reset. At `x >` threshold, each failed conjunct (current in view, start in view, no player, player distance <=1000) independently blocks reset. With both out of view and distance >1000, X/Y return to authored start but velocity/flap/frame persist. Mirror negative-offset threshold in a synthetic fixture. Check far-background parallax `(0.25,0.95)` in the start-point visibility calculation, not raw world X/Y.
- A bird frozen by updateability gate has no motion, animation-clock or flap-timer advance. Other generic sprite/orb animation remains unchanged.
