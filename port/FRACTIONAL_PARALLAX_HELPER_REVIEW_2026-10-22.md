## Concrete integration/contract risks

1. **The dispatch helper is advisory, not wired.** `SelectParallaxUVPath` matches current branch order only if the caller constructs `damageBurst` as `rgbGain > 1 && damageBurstProgram_`, `pixelWobble` as `enabled && pixelWobbleProgram_`, `foliageSway` as `enabled`, `uvScroll` as either nonzero shift, and derives source-rect/rotation exactly as `DrawSprite` does (`SDLRenderer.cpp:226-261`; `ParallaxUV.h:40-63`). A call site must preserve that order; calling the eligibility gate before higher-priority effects would incorrectly route them through the new quad.
2. **Eligibility needs measured GL facts, not assumed texture dimensions.** `ParallaxUVDirectEligible` correctly rejects failed binding, nonunit/nonfinite spans, non-GL and unsupported NPOT repeat (`ParallaxUV.h:25-38`), but the current renderer neither measures the UV-scroll binding nor determines NPOT-repeat support for it. In particular ID40 is 2048×677, so a hard-coded `npotRepeatSupported=true` or an assumed unit span would defeat the guard. If binding succeeds but fails the guard, unbind before using the existing SDL-copy fallback; do not draw direct GL and SDL copies together.
3. **Sampler and state transaction remain an integration obligation.** Current ordinary UV scroll inherits SDL texture color/alpha mods and per-pixel alpha, and the direct quad will bypass SDL copies. Save/restore bound texture, active unit, program, matrices, wrap S/T, min/mag, blend and prior GL state around a flushed draw, using the existing custom-quad orientation (`SDLRenderer.cpp:310-324,335-405`). Apply `sprite.tint` and `sprite.opacity` once in the direct path; do not assume the preceding `SDL_SetTexture*Mod` calls automatically modulate immediate-mode GL vertices. Preserve the current destination and GL V=0-at-screen-top convention.
4. **The CPU test is not a renderer integration test.** Its destination equality uses two identical synthetic arrays (`fractional_parallax_uv_test.cpp:72-75`), and its source-order check uses a nearest-center model only at exact-aligned cuts (`:103-114`). Those assertions do not verify actual `DrawSprite` destination, GL filtering, seam color, alpha, or state restoration. Test assertions also require a build without `NDEBUG`; the present default `CXXFLAGS` meets that condition, but a release-flag override could produce a false PASS.

No defect found in the helper's signed corner formula or its test's exact-cut comparison on this source review. No renderer, test, Makefile, GPU, Docker or existing status/report file was changed by this lane.
