## Deadline and mechanism

Forest frame 120 starts the existing cave decode worker. The candidate uses that **same thread**, after cave decode, to decode `Game/Media/waterfall_4.png` (512×1024, exactly 2,097,152 RGBA bytes) into one bounded CPU buffer. The default enables it; `DEATHLEAK_WATERFALL4_DECODE=off` gives a same-binary control. At `LoadDedicatedTexture`, a release/acquire completion flag guards moving the completed buffer to the unchanged `SDL_CreateRGBSurfaceWithFormatFrom` → `SDL_CreateTextureFromSurface` path; if incomplete/invalid, synchronous PNG decode remains. No GPU upload is moved, no texture ID or SDL_Texture identity changes, and no speculative partial texture can be drawn.

Waterfall-top scene entry is frame 411 of the fixed-dt `R:800,L:1200` Forest route. The scene requests `waterfall_4.png` **after** cave background upload, at scene-load elapsed 44.879–66.341 ms in the no-readback A/B/A runs. The first top draw follows synchronous `LevelScene::Load`; frame 415 is first-reveal under loading fade and frame 424 the first postfade draw. All required waterfall pixels therefore must be ready before first entry draw, not merely before frame 415. B consumed the complete worker buffer before the original SDL upload. Its worker duration was 14.451 ms in the no-readback B run; controls decoded cold on the main thread for 12.731 and 15.379 ms. B main-thread decode was zero, while SDL upload remained 1.000 ms (A 1.055/1.126 ms).

## GL, memory and limits

The changed branch only supplies RGBA bytes to the **same** SDL surface/texture creation and GL upload; source-level GL submission, texture ID, painter order, renderer filtering, and target topology are unchanged. The serial gate did not acquire a new apitrace or calibrated GPU time/VRAM counter; equal GL call counts and GPU time are inferred, not directly measured. Extra bounded CPU payload is 2,097,152 bytes while queued (plus vector overhead); no additional GPU texture is allocated. Direct RSS/VRAM and thermal telemetry were not measured. First-entry total latency still 82–93 ms; cave SDL allocation/upload and other scene-load work remain the next distinct tail bottlenecks. The previously rejected unconditional cave preallocation is not revived; next evaluate **the next independently cold, source-safe top-entry decode asset**, or measure a genuinely low-stall SDL-compatible cave upload primitive before altering residency. No 60-FPS, 8K/high-Hz, sustained, thermal, or release acceptance is claimed.
