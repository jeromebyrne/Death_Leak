## Exact spawn transform

`GameObject::Bottom()` is **visual-object bottom**, `m_position.Y - m_dimensions.Y * 0.5f` (`Game/src/GameObjects/GameObject.h:128-135`), not collision bottom. The lethal gruesome branch copies `m_position`, replaces Y with `Bottom()`, and passes `(pos.X, pos.Y + 30)` to `CreateDirectedSpray` (`Game/src/GameObjects/Character.cpp:1643-1660`). `CollisionBottom()` instead uses `m_collisionBoxDimensions.Y` plus offset (`Game/src/GameObjects/SolidMovingSprite.h:46-55`) and is used in the *non-gruesome* branch (`Character.cpp:1713-1719`), not this one.

The ninja spawner sets visual dimensions **183.142853 × 231.714279**, collision dimensions **100 × 200**, offset **(0,0)** (`Game/src/GameObjects/NinjaSpawner.cpp:32-43,96-100`). Thus at an ordinary lethal hit the common spray's nominal center is `(ninja.X, ninja.Y - 231.714279/2 + 30) = (X, Y - 85.8571395)` in the spawner's source world geometry. It is **15.8571395 units below collision bottom** (`Y-100`), and **135.8571395 units below** the existing debris center `Y+50` (`port/game/Combat.cpp:169-173`). Do not use `Y-100+30`, `Y+50`, or a texture's native pixel height. The port stores enemy centers as `Enemy{x,y}` and uses the same 100×200 collision half-extents in movement (`port/game/Combat.h:11-32`, `port/game/Combat.cpp:56-61,90-101`); its ninja draw hardcodes approximately 183×231 visual size (`Combat.cpp:553-567`). Use the source's more precise 231.714279 height for the emitter's world origin, independent of the rounded draw height. Projectile kickback is applied to `enemy.x` before the lethal branch (`Combat.cpp:184-205`), mirroring the source's pre-spray kickback (`Character.cpp:1592-1609,1648-1659`); spawning from post-kickback `enemy.x` is correct.

Windows scales authored world/object geometry via `GameObject::Scale` (`Game/src/GameObjects/GameObject.cpp:454-463`) and defines `GameScale = backbuffer/(1920,1080)` (`Game/src/Game.cpp:142-143`). Runtime `CreateDirectedSpray` also multiplies **size and speed** by `GameScale.X`, and passes `scaleTo * GameScale.X` (`Game/src/Particles/ParticleEmitterManager.cpp:422-423,478-499,515-525`). Linux's current world coordinates remain 1920×1080-authored, with a **single** 2/3 projection into the 1280×720 destination (`port/game/Combat.cpp:553-567`, `port/game/ParticleSpray.h:83-92`). Keep spawn at `(X,Y-85.8571395)` in Linux world units and let the existing renderer projection apply 2/3 once; do not pre-scale the origin by 2/3. The Windows runtime-size/lifetime-scale behavior at an actual 1280×720 Windows backbuffer remains a parity question, not a reason to scale the port's world origin twice.

For this **runtime** factory, direction is `(0.2 + r, 0.8 - r)` where `r` is sampled in `.01` increments from `[0,.29]`; lifetimes are deterministic by index, `1.5 - (.7/20)*i`, so the last is `.835s` (`Game/src/Particles/ParticleEmitterManager.cpp:426-440`). Spawn offsets are signed integer magnitudes up to 50 X and 100 Y, not merely ±5/±10 (`:442-476`). The *load-time* factory is different (`:550-647`); do not copy the authored XML path's fixed direction (`port/game/LevelScene.cpp:314-335`) for this runtime spray.
