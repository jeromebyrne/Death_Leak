# Raft GL wrap: bounded source contract (2026-10-23, 08:38)

## Verdict

The **opt-in** Linux raft-mip draw has a concrete, source-backed **sampler-addressing bug**: it changes both axes to `GL_CLAMP_TO_EDGE` immediately before sampling, whereas the original Windows raft effect explicitly requests `WRAP` on U and V. This is a state/translation defect in the experimental branch, **not evidence of a visible pixel discrepancy or an accepted mip-fidelity improvement**. The default Linux SDL path is unaffected while `DEATHLEAK_RAFT_MIP_EXPERIMENT` is unset. Prior `RAFT_MIP_CURRENT_SOURCE_DISPOSITION_2026-10-23.md` already identified the discrepancy and cautioned against pixel claims; this report pins down the UV/sampler contract and minimal correction only.

## Original Windows contract

- Forest-1 IDs 11, 57, 58 are nonanimated `Media/objects/raft.png` sprites with `effectlighttexture` and `repeatX=false`, `repeatY=false`; IDs 11/57 are horizontally flipped, 58 is not (`Game/XmlFiles/levels/forest_exploration_1.xml:191-203,928-955`). No-repeat here means the **mesh UVs are not extended** for tiling; it does not change the effect sampler's address mode.
- `Sprite.cpp:19-22` defines the ordinary corners as `(0,0),(1,0),(1,1),(0,1)`. `Sprite::RecalculateVertices` uses those corners and changes U only when `mRepeatTextureX && !m_drawAtNativeDimensions` (`Game/src/GameObjects/Sprite.cpp:215-234`); the raft's false repeat flag therefore leaves its nominal UV domain at `[0,1]` on both axes. The shader passes input Tex through unchanged (`Game/ShaderFiles/BasicLightTexture.fx:37-46`). Horizontal flip changes orientation, not the address-mode requirement.
- The nonanimated sprite loads its SRV via `TextureManager::LoadTexture` (`Sprite.cpp:162-170`; `Game/src/Core/TextureManager.cpp:50-79`), selects `Draw_effectLightTexture` (`Sprite.cpp:369-379`), and assigns the SRV to the effect diffuse variable (`Sprite.cpp:626-635`; `Game/src/Effects/EffectLightTexture.cpp:51-57`). `BasicLightTexture.fx:10-16` explicitly declares `Texture2D txDiffuse` with `Filter = MIN_LINEAR_MAG_POINT_MIP_LINEAR`, `AddressU = WRAP`, `AddressV = WRAP`; its pixel shader samples `txDiffuse.Sample(samLinear, input.Tex)` (`:53-59`). This is the **authored D3D10 sampler contract**, subject to actual effect binding at runtime. It is not a claim that a specific Windows pixel accessed outside `[0,1]`.

## Current Linux working-tree branch

- `port/linux/SDLRenderer.cpp:228-230,274-289` gates the private GL path on the exact env value `on`, scene sampling phase, raft-path suffix, current GL context, and absence of source rect/repeat/UV shift/special effects. It is path-based, not restricted to the three Forest-1 IDs; a failed private draw falls through to SDL copy (`:228-270,290-298`). The ordinary path uses SDL linear while minified and nearest otherwise (`:213-225`), with no ordinary mip selection (`:266-270`).
- The private uploader creates mip levels and configures `GL_LINEAR_MIPMAP_LINEAR` minification, `GL_NEAREST` magnification, and **`GL_REPEAT` on S/T** (`SDLRenderer.cpp:793-881`, especially `:875-880`). This is the matching addressing choice at allocation. But each enabled raft draw binds that same texture and overwrites S/T with **`GL_CLAMP_TO_EDGE`** (`:297-308`). The GL quad supplies nominal endpoint UVs 0/1 (reversed for flips), with V inverted to account for PNG-row flip (`:320-335`). Thus the draw-time GL state directly conflicts with the original U/V WRAP contract and defeats the uploader's REPEAT state.
- `glPushAttrib(GL_ALL_ATTRIB_BITS)`/`glPopAttrib()` around the draw (`:303,342`) should not be treated as proof that mutation of the **texture object's** wrap parameters is undone; the private texture is cached per TextureId (`:789-796`). The safe correction sets the intended parameters at the draw point, independent of previous cached-object state.

## Minimal safe fix and gate

In the private `DrawRaftMipExperiment` branch only, replace its two `glTexParameteri(... GL_CLAMP_TO_EDGE)` calls (`SDLRenderer.cpp:307-308`) with `GL_REPEAT` for both `GL_TEXTURE_WRAP_S` and `GL_TEXTURE_WRAP_T`; leave the uploader, env gate, UVs, flips, transform, alpha/blend, painter slot, fallback, and ordinary SDL rendering unchanged. Explicit draw-time REPEAT is preferable to relying solely on upload-time defaults for a cached texture. No general renderer-addressing change is justified by this audit.

After renderer ownership/GPU lane is clear: (1) source diff/syntax check; (2) with opt-in **on**, assert/log the bound private texture's S/T wrap parameters at an actual ID11/57/58 draw; (3) frozen-state, lossless native-resolution Linux off/on capture, including raft alpha boundaries and non-raft control, to measure local impact; (4) only with a matched Windows D3D10 draw/crop and effective bound SRV/sampler evidence, judge visible parity. If desired, a controlled GL CLAMP-vs-REPEAT edge crop can isolate addressing sensitivity, but it cannot itself prove Windows parity. The prior `RAFT_MIP_WINDOWS_BINDING_GATE_2026-10-23.md` establishes that Windows bound SRV/resource mip descriptors and matched lossless same-state frame are unavailable locally; `RAFT_MIP_SOURCE_GATE_2026-10-23.md` and `RAFT_MIP_CURRENT_TREE_PREFLIGHT_2026-10-23.md` cover mip and scale questions separately. No build, GPU run, capture, or runtime sampler query was done here; pixel impact and selected Windows mip/LOD remain unverified.
