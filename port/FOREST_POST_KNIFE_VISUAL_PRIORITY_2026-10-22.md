# Forest-1 post-knife visual priority — CPU/source handoff (2026-10-22)

## Single priority and evidence grade

At HEAD `4661632` (dry knife solid-line material spray implemented with a CPU fixture), the highest-*coverage* remaining **source-demonstrable forest-1 active-play visual-contract difference** is the one-update draw-destination lag of the two camera-following foreground ParallaxLayers, especially ID37 (`shrubbery.png`, the lower band) and the same rule for ID40 (`trees_top.png`, upper edge). The layer texture phase uses the current camera in both engines, but Windows' world matrix uses the position before the current follow update while Linux places the quad from current camera X. During ordinary moving-camera play this shifts these broad foreground layers horizontally; at held camera it converges. This is a priority among proven, repeatedly exercised *scene-area* contracts, **not** a claim that it is the most conspicuous perceived defect, a broad darkness/brightness explanation, or a measured Windows/Linux image delta.

The prior physical-GPU *within-port diagnostic*, not repeated here, already bounded practical ID37 impact at one moving forest frame: previous/current camera X 761.040/769.036, predicted and observed destination shift −5.331 backbuffer px, 49,532 changed pixels in an ID37-only lower crop, mean RGB absolute delta 0.394/255 and maximum channel delta 6/255; the held-camera control was byte-identical (`port/FOREST_FOLLOW_LAG_GPU_DISCRIMINATOR_2026-10-22.md`). That is real but low-contrast. It establishes an active 10-second route visual opportunity (camera movement and the visible lower foreground), not original-Windows parity or sufficient reason to alter the current renderer. ID40 has the same authored/state contract but lacks a separate practical-effect measurement.

- Windows `Game/src/GameObjects/ParallaxLayer.cpp:26-35` calls `Sprite::Update` and **then** stores current camera X in `m_position`. `Game/src/GameObjects/GameObject.cpp:202-212` builds `m_world` during that base update; `Game/src/GameObjects/Sprite.cpp:626-637` uploads it on draw. `ParallaxLayer::Draw` independently computes X UVs from current camera X (`ParallaxLayer.cpp:37-83`). The code remains that way at HEAD 4661632.
