# Current-HEAD visual discriminator — camera-follow foreground translation (2026-10-22)

## Single finding

At pushed HEAD `c1725ee`, the highest-confidence *remaining source/port visual-contract difference* identified in the reviewed active forest-1 route is the one-update **destination-position lag** of the two broad camera-follow foreground ParallaxLayers, XML IDs **37** (`shrubbery.png`, lower band) and **40** (`trees_top.png`, upper edge). Windows source builds each layer's draw matrix from the position before its `followcamx` assignment, while Linux builds the draw destination directly from the current camera X. Both calculate texture UV phase using current camera X. Thus a moving-camera Windows frame places the layer quad one camera increment left of Linux while keeping its UV phase current; a stationary camera converges after the next update. This is a deterministic code-path difference, not an observed Windows-versus-Linux pixel delta or an explanation for the persistent darkness of ID37.

This is a **narrow next GPU discriminator**, not a new broad audit: `port/PARALLAX_FOLLOW_TEMPORAL_TRACE_2026-10-22.md`, `port/FOREST_FOLLOW_LAG_QUANTIFICATION_2026-10-22.md`, and `port/NEXT_FOREST_VISUAL_DISCRIMINATOR_2026-10-22.md` already established the source semantics and CPU prediction.
