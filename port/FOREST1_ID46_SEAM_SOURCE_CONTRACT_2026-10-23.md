# Forest-1 ID46 seam: source contract and CPU gate — 2026-10-23

## Checkpoint / verdict

Read-only source/asset/reference inspection is complete. **There is a source-backed CPU-side UV-interpolation mismatch independent of GPU sampler state:** Windows draws ID46 as **one** 10000-wide, two-triangle quad; Linux subdivides the deformed quad into 2048-world-unit repeat tiles, each with its own two-triangle diagonal. For a non-parallelogram deformed quad, these triangulations interpolate U/V differently inside the shape even if their tile-edge UVs and GL address/filter modes are perfect. This is a geometry/UV contract finding, **not** proof of a visible ID46 seam or Windows-image mismatch. No game, build, display/GPU, or capture was run. The existing `ID46_WRAP_REFERENCE_FEASIBILITY_2026-10-23.md` establishes that no same-state Windows frame is available and the texture's base-level outer alpha columns are transparent; neither fact removes this interior interpolation distinction.

## Exact Windows contract

- `Game/XmlFiles/levels/forest_exploration_1.xml:765-778`: ID46 is centered at world (2086.573242, 2976), `kGround`, width 10000, height 252, `repeatX=true`, `repeatY=false`, alpha .5, zero rotation, `horizontalflip=true`, `verticalflip=false`, `effectfoliagesway`, and `Media/levels/forest_exploration_1/leaves_shadow.png`. Only the top source corners sway: TL intensity (7,6), TR (8,9); BL/BR (0,0); time multiplier 1. The texture is 2048x252 RGBA per the prior feasibility report's asset inspection.
- `Game/src/GameObjects/Sprite.cpp:19-22,194-234`: source corner order is BL/BR/TR/TL, source U is 0 at left and **10000/2048 = 4.8828125** at right, V is 0 at world-bottom and 1 at world-top. The repeated U belongs to the **whole original quad**, not separate sprite objects. `Sprite.cpp:73-98` applies the authored horizontal flip by negative world X scale after reading XML; `Sprite.cpp:432-477` reads flip/repeat and four named sway intensities. Thus in world/screen order after flip, the right edge has U=0 and the left edge has U=4.8828125; the leftmost partial repeat has phase .8828125. `Sprite.cpp:181-191,829-862` draws four vertices with index sequence `2,1,3,0` as one D3D10 triangle strip: triangles (2,1,3) and (3,1,0), with a single full-width diagonal between source BR and TL.
- `Game/ShaderFiles/FoliageSway.fx:14-20,41-65`: the D3D sampler contract is `MIN_LINEAR_MAG_POINT_MIP_LINEAR`, U and V **WRAP**. The vertex shader first transforms to world, then moves X by `sin(worldY*.1 + Time*TimeMultiplier*GlobalTimeMultiplier)*Norm.x`, then moves Y by `sin(updatedWorldX*.1 + samePhase)*Norm.y`, then applies View/Projection; UV is passed unchanged. The pixel shader samples that UV and multiplies sample alpha by the object's alpha. `Game/src/GameObjects/Sprite.cpp:207-212,832-840` supplies the per-corner Norm.xy and time multiplier. `Game/src/Game.cpp:377` sets the weather-controlled global time multiplier. `Game/src/Core/TextureManager.cpp:50-79` loads the PNG with D3DX's default SRV-from-file parameters; actual mip contents/LOD remain a GPU/runtime question, not established by this source read.

## Linux source path and CPU comparison

- `port/game/LevelScene.cpp:527-539,547-548,1252-1261,1273-1294`: the XML effect/intensities/time multiplier, flip, dimensions, alpha and repeat route into the render sprite. ID46's `kGround` has the default layer factor 1. The custom foliage path preserves authored flipY and supplies shader-clock time and weather multiplier; `port/linux/FoliageSway.h:14-22` implements the same **X-before-Y** sine formula. `port/linux/EffectQuadGeometry.h:23-40` computes the source-labeled, flipped world corners, applies that sway, then projects to screen.
- `port/linux/SDLRenderer.cpp:209-233,532-563`: `DrawSprite` chooses `DrawFoliageSway` before the ordinary repeat-copy path, maps all four source intensities to their original source labels, and reorders the corners for the authored X flip. `port/linux/SDLRenderer.cpp:564-592` then linearly splits both deformed top and bottom edges at every visible repeat interval, writes tile UVs (`flipX ? sourceWidth/textureWidth : 0` at left; reversed at right), and calls `SDL_RenderGeometry` **once per tile** with indices `0,1,3,1,2,3`. `port/linux/RepeatX.h:16-40` anchors flipped full tiles at the quad's right edge and leaves the partial tile at its left; its `sourceWidth` is rounded from each tile's physical width. `port/linux/SDLRenderer.cpp:217-225` selects SDL linear scale mode for repeat/minification, but does not establish actual GL wrap, min/mag, mip or queued draw-time state. That remains the separate reserved GPU gate.
- CPU distinction: on the original, UV interpolation uses just the full-width source diagonal. In the port, every repeat boundary creates new vertices and a new local diagonal. Splitting a single *affine parallelogram* would be UV-equivalent; ID46 is generally **not** one because its bottom displacement is zero while top-left and top-right displacement intensities differ (7,6 versus 8,9) and their Y-sine phases depend on different updated world X. Both paths can have correct edge positions and U repeat phase yet produce different interior UVs. The difference may be small or invisible after transparent edges, alpha .5, occlusion, filtering and sepia. It must not be conflated with clamp-versus-wrap, and this source review does not quantify pixels at R:98.
