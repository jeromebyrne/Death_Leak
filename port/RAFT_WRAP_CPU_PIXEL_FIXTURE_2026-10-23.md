# Forest-1 raft WRAP/CLAMP: CPU pixel fixture specification (2026-10-23)

## Verdict and scope

A **source-backed sampler-state mismatch** exists only in the opt-in private GL raft-mip draw: the original `BasicLightTexture.fx` sampler requests `AddressU = WRAP`, `AddressV = WRAP`, while `DrawRaftMipExperiment` binds the private texture and immediately sets S/T to `GL_CLAMP_TO_EDGE` (`Game/ShaderFiles/BasicLightTexture.fx:10-16,53-59`; `port/linux/SDLRenderer.cpp:297-308`). Its uploader initially sets S/T to `GL_REPEAT` (`SDLRenderer.cpp:875-880`), which the draw overrides. The default SDL copy path is unchanged unless `DEATHLEAK_RAFT_MIP_EXPERIMENT=on` and the eligibility predicate succeeds (`SDLRenderer.cpp:225-230,274-289`). A two-axis draw-site `GL_REPEAT` correction would match the **authored address contract**; it is not yet a proven visible improvement or Windows framebuffer match.

The relevant Forest-1 sprites are XML IDs **11, 57, 58**: each uses `Media/objects/raft.png`, `effectlighttexture`, `repeatX=false`, `repeatY=false`, dimensions 458.298584×125.316017, alpha 1; IDs 11/57 are X-flipped, ID58 is not (`Game/XmlFiles/levels/forest_exploration_1.xml:191-203,928-955`). The nearby *light-shaft* sprite ID14 instead uses `Media/sun_shaft_2.png` (`:241-253`): do **not** conflate it with the raft texture. The private branch is selected by raft path suffix, not XML ID; a CPU XML check identifies intended Forest-1 objects but cannot attest to a runtime ID draw hit. Original sprite UV corners are (0,0),(1,0),(1,1),(0,1); X UV expands only for repeat-X (`Game/src/GameObjects/Sprite.cpp:19-22,215-234`). The effect vertex shader passes UV unchanged (`BasicLightTexture.fx:37-46`). The private GL quad likewise uses endpoint U/V 0/1, swaps U for X flip, and inverts V for PNG-row orientation (`SDLRenderer.cpp:320-335`). Thus all nominal UVs are in `[0,1]`, yet linear filtering can still cross an edge.

## Exact CPU-only A/B fixture to add later

Create one independent test, e.g. `port/tests/raft_wrap_cpu_pixel_test.py`, **without** importing SDL/GL or launching the game. Load the tracked `Game/Media/objects/raft.png` (1024×280 RGBA; SHA-256 `d319f5d1cc292565df20111a67529feb8b4ff3434ff2176fa3d7ddf5f420d031`) with Pillow. Parse the Forest XML and assert IDs/path/effect/repeat/flip above. Read `SDLRenderer.cpp` and isolate `DrawRaftMipExperiment` between its signature and `DrawFractionalParallax`; within the span between `glBindTexture(GL_TEXTURE_2D, name)` and `glBegin(GL_QUADS)`, assert exactly one S and one T draw-site wrap assignment, both `GL_REPEAT`, and reject any `GL_CLAMP_TO_EDGE` there. This deliberately **fails on the present dirty tree** and passes after only the two draw-site tokens change; uploader-only `GL_REPEAT` must not falsely pass it. Keep the source assertion separate from the pixel oracle so the latter can be run against either state.

For the pixel oracle, implement explicit normalized-coordinate nearest/linear texel addressing in Python floats (no GL): for a mip of width W/height H, `x=u*W-0.5`, `y=v*H-0.5`, bilinear neighbors floor/ceil, weights from fractional parts; WRAP indexes modulo W/H; CLAMP bounds each index to `[0,W-1]`/`[0,H-1]`. Sample the **same** RGBA mip and UV twice, changing only address mode. Use a deterministic CPU **BOX** pyramid (`Pillow Image.Resampling.BOX`, halve each dimension with floor, at least 1) as a fixture oracle, expressly **not** a claim that `glGenerateMipmap` or D3DX10 produces these texels. Assert the image hash before using numerical pixels. Test both axes and both endpoints/near-endpoint bands, plus interior controls, at base and mip levels 1–4. For any selected mip, U address modes can diverge inside `[0,1]` only for `u < 1/(2W)` or `u > 1-1/(2W)` (including endpoints); V analogously uses H. At exact `u=0`, linear WRAP averages last and first columns while CLAMP takes first; at `u=1`, WRAP averages them while CLAMP takes last. For IDs 11/57, X flip exchanges which screen edge corresponds to `u=0` versus `u=1`; ID58 uses the opposite mapping. Test V independently with an interior U. Check a synthetic 2×2 opaque, unequal-edge texture too, so the address-mode oracle has a visible positive control independent of the raft's transparent guard.

Concrete tracked-asset oracle values from the deterministic BOX pyramid (RGBA byte source values; bilinear outputs are floats, **do not round before asserting**):

| Probe | UV and selected BOX mip | CLAMP raw RGBA | WRAP raw RGBA | Expected result |
|---|---|---|---|---|
| Positive raft edge | level 3 = 128×35, `u=0`, `v=4.5/35` | `(25,25,25,10)` | `(12.5,12.5,12.5,5)` | alpha differs by 5; at `u=1`, CLAMP `(0,0,0,0)`, WRAP same 50/50 result |
| Stronger edge | level 4 = 64×17, `u=0`, `v=2.5/17` | `(8,8,8,62)` | `(4,4,4,31)` | alpha differs by 31; at `u=1`, CLAMP zero, WRAP `(4,4,4,31)` |
| Interior control | same mip/row, `u=0.5/W` (first texel center) | first-column texel | identical first-column texel | no cross-edge footprint |
| Nominal-mip alpha guard | levels 0, 1, 2, `u=0`/`1`, any `v` at row center | edge alpha 0 | edge alpha 0 | no source-alpha compositing delta from U edge alone |

The level-3/4 numbers were read from a local read-only Pillow BOX reduction of this exact asset; for level 3 row 4, first/last texels are `(25,25,25,10)` / `(0,0,0,0)`, and for level 4 row 2 they are `(8,8,8,62)` / `(0,0,0,0)`. At base level, outermost rows and columns have alpha 0; BOX levels 1 and 2 retain zero-alpha outermost texels on all edges. Raw transparent RGB may differ at low levels, so separately composite each sampled result using straight-alpha source-over on a fixed opaque contrasting background and assert **no composited difference when both alpha are zero**. For level-3/4 probes assert a nonzero composited difference; do not hard-code GPU byte rounding. This distinction prevents a raw-RGB delta from being misreported as visible raft pixels.

Minimal verification command **after the proposed test file exists**: `python3 -m unittest port/tests/raft_wrap_cpu_pixel_test.py` from repository root (Pillow required). Run the pixel-oracle subtests separately if checking the current tree; the draw-site source subtest is expected to fail until the two-line correction. No build, game binary, display, GPU, or Windows capture is needed for this fixture. A passing test establishes source state plus mathematical/asset sensitivity **only**, not actual rasterized fragment coverage, GPU mip texels/LOD, SDL backend state, sepia/overdraw, or original Windows parity.

## Likely on-screen pixel impact

At the authored 2/3 scale, a 458.298584×125.316017 raft projects to roughly 305.532×83.544 logical pixels; the 1024×280 texture is ~3.352 texels/output pixel on both axes, suggesting LOD `log2(3.352) ≈ 1.745` for an axis-aligned sample (`port/game/LevelScene.cpp:1195,1269-1271`). This is a **nominal estimate**, not a measured GL fragment LOD; rotation (IDs 57/58), viewport transforms and derivative selection can alter it. If only levels 1/2 contribute, their fully transparent BOX-pyramid boundary texels make a **visible alpha-over WRAP/CLAMP difference unlikely**, even though raw RGB might differ. The level-3/4 CPU probes prove that this asset can yield an alpha and composited-pixel difference under stronger minification, not that those levels are selected in Forest-1. The current source-backed correction is real; **framebuffer pixel impact is unverified and probably small/zero at nominal raft scale**. A CPU oracle must never be presented as Windows or Linux framebuffer A/B evidence.
