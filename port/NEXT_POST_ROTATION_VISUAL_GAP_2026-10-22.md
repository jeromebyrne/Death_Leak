# Next post-rotation composition discriminator — camera-follow foreground geometry (2026-10-22)

## Decision

After the all-four-flip rotation correction, the highest-priority **non-overlapping, source-backed composition candidate** in the reviewed active forest-1 route is a one-update **camera-follow geometry/UV phase split** for foreground `ParallaxLayer` IDs 37 and 40. It concerns broad, recurrent foreground layers, not the rotated ordinary sprites, foliage quads, or damage-burst quad owned by the rotation worker. This is a deterministic difference between the source and port *code paths*, but its visible magnitude and Windows runtime behavior are not yet proven. Treat it as the next discriminator, **not an authorized speculative rendering fix**.

In Windows, each layer's world matrix is made from its position before its follow-camera position is assigned; its draw-time UV phase uses the current camera. Linux uses the current camera for both its destination center and UV phase in one draw. On a camera-moving frame this can change a layer's screen-space quad position while its sampled texture phase is already current. It should disappear after a held camera has received another update. At the forest-1 1280×720 projection, a 100-world-unit camera step corresponds to about 66.7 logical pixels of possible first-frame X displacement if the Windows matrix retains the preceding followed position; this is a **test-vector upper contrast**, not a measured game-frame error. Normal frame-to-frame camera steps should be smaller.
