# Forest ID37 mip discriminator — 2026-10-23

## Decision

**The current Linux ID37 GL texture has no level-1 mip.** A source-requested `MIN_LINEAR_MAG_POINT_MIP_LINEAR` versus current `GL_LINEAR` image comparison is therefore **not valid on this binding**: selecting `GL_LINEAR_MIPMAP_LINEAR` without first building a mip chain would sample an incomplete mipmapped texture, not the Windows filtering contract. No sampler or renderer change was made. The existing gross lower dark silhouette remains authored ID37 coverage, not a demonstrated filtering fault; a valid mip chain could at most leave an unquantified local edge/seam difference until separately measured. This experiment does **not** establish the original Windows SRV's runtime mip count.

## Boundary

`SDLRenderer.cpp` creates ID37 through single-image `SDL_CreateTextureFromSurface` and the fractional path explicitly sets `GL_LINEAR` minification. The original `BasicLightTexture.fx` requests `MIN_LINEAR_MAG_POINT_MIP_LINEAR`, but the original Windows bound view/resource level count and sampled LOD are unmeasured (`ID37_WINDOWS_MIP_RUNTIME_FEASIBILITY_2026-10-23.md`). A future apples-to-apples test needs a verified mip chain on the isolated Linux binding and, for a parity claim, the matched original Windows SRV/frame packet. Neither is established by this bounded lane, so no speculative `GL_LINEAR_MIPMAP_LINEAR` toggle or source correction was attempted.
