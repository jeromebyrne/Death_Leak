# Current raft-mip experiment: source disposition (2026-10-23)

## Verdict

**No concrete Forest-1 pixel mismatch against the original Windows game is proved by the current dirty experiment.** The switch is opt-in (`DEATHLEAK_RAFT_MIP_EXPERIMENT=on`); unset, it cannot affect the delivered default gameplay. If the delivered clip was captured with the switch on, that fact and the exact branch hits must be established from its run record before attributing visible raft pixels to this diff. Keep this code classified as an unaccepted local A/B experiment, not a fidelity correction or demonstrated regression.

There *is* a concrete **source-state discrepancy** in the enabled branch: it forces `GL_CLAMP_TO_EDGE` on both raft axes (`port/linux/SDLRenderer.cpp:307-308`), whereas the original `BasicLightTexture.fx:10-16` declares `AddressU = WRAP` and `AddressV = WRAP`. The original pixel shader samples `txDiffuse` through that sampler (`BasicLightTexture.fx:53-59`), and the XML assigns the ordinary `effectlighttexture` to raft IDs 11, 57 and 58 (`forest_exploration_1.xml:191-203,928-955`). Thus the enabled GL draw is **not an exact translation of the authored sampler state** for these rafts. A visible edge difference is only a candidate: at in-range UVs with no filter footprint crossing the image boundary, WRAP and CLAMP may return the same result. Neither this state discrepancy nor the conditional mip change demonstrates an actual pixel difference from Windows in the delivered frame.

Its exact `on`, scene-phase, raft-path, no-source/no-repeat/no-UV-shift/no-special-effect predicate makes IDs 11/57/58 eligible when visible, but is not object-ID or Forest-level scoped. ID 11/57 are horizontally flipped; ID 58 is not (`forest_exploration_1.xml:191-203,928-955`). The branch preserves the painter call site and draws a separate PNG-backed GL quad; failed texture creation falls through to the old SDL path. These facts establish possible footprint, not a draw hit in the delivered clip.
- The GL uploader uses generated mips and `GL_LINEAR_MIPMAP_LINEAR`/`GL_NEAREST` (`SDLRenderer.cpp:793-880`). The original shader requests `MIN_LINEAR_MAG_POINT_MIP_LINEAR` (`BasicLightTexture.fx:10-16`) and `TextureManager.cpp:50-79` loads with null D3DX10 load info. That predicts, but does not prove, a multi-mip Windows resource or view at the actual raft draw. The source does not provide the bound SRV `MostDetailedMip`/`MipLevels`, resource `MipLevels`, selected LOD, or a matched lossless Windows frame. GL mip generation and D3DX10 mip generation are not thereby proved equivalent.
- The prior `SDL_RENDERER_DIRTY_DIFF_FIDELITY_GATE_2026-10-23.md` establishes that the previous SDL copy remains the default and identifies the same conditional footprint; `RAFT_MIP_WINDOWS_BINDING_GATE_2026-10-23.md` records the missing bound Windows descriptor and reference frame. The local original-runtime recovery report finds no runnable original EXE or matched frame in the accessible tree. No claim of observed pixel disparity, relative sharpness, or Windows parity follows from the present source-only audit.
