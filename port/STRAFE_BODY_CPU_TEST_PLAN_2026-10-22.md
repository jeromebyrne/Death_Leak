## Frame-clock discriminators

Use a fresh scene and fixed `vx=600`: dry Player dynamic rate is `clamp(abs((600/60)*1.8*2.65),4,60)=47.7 FPS`, frame period ≈0.02096436 s, but the first strafe advance uses XML **30 FPS** (period 1/30), then stores 47.7. Suggested robust sequence: enter with `dt=0.030` and assert frame `_000` (would be `_001` if dynamic rate were wrongly applied before advance); continue `dt=0.001` and assert `_001` (the 0.030 excess is retained and now evaluated at 47.7); continue `dt=0.001` and assert still `_001` (remaining clock ≈0.01004). For a separate fresh scene, enter with `dt=0.034` and assert `_001`, proving long first tick can advance at default 30. For a separate large-dt case, enter with `dt=0.100` and assert only one step, then use a very short next tick to show retained excess advances only one additional step per tick. The runtime main clamps dt to 0.05 (`port/linux/main.cpp:457-460`), but direct scene fixture may supply 0.100 to test `AnimateLooped` contract. Use inequalities/epsilon around timing math, not exact float equality.

To prove transition-only restart, continue same `StrafeBack` for several ticks and assert monotonic frame progression/no return to `_019`; switch to Running/Still and back and assert frame cursor restarts at index zero while the per-sequence rate **persists**. Example: after a first strafe visit has stored 47.7, exit for one short tick; re-enter that same sequence with `dt=0.021` and assert index 1 immediately (47.7 period is below 0.021; XML 30 period is above it). Distinguish this from clock reset: re-entry begins elapsed=0 and advances once, rather than carrying the prior sequence's elapsed. Source `SetSequence` restart and one-step/excess behavior: `Game/src/Animation/AnimationPart.cpp:142-197`; source advance-before-rate assignment and Player multiplier: `Game/src/GameObjects/Character.cpp:1033-1050`, `Game/src/GameObjects/Player.cpp:72-82`; current port sequence clock/rate implementation: `port/game/LevelScene.cpp:1108-1137`, `port/game/LevelScene.h:195`. Dry sprint, wet-last-frame (no min clamp), and slow-motion multiplier need separate fixtures only if those states become represented in the port; do not silently pretend this dry fixture covers them, and do not alter Running's existing rate for this test.
