# Autoscroll pre-cull source gate — read-only audit (2026-10-24 03:35Z)

## Verdict

**There is a source-proven conditional future command-UV divergence, separate from the scene-local versus process render-clock bug.** Original Windows advances an autoscroll layer's stored V only after the manager admits it to `ParallaxLayer::Draw`; the Linux port advances stored `autoScrollYPhase` before its viewport rejection. Consequently every Linux draw pass while a layer is offscreen can add a step that Windows would not, and the accumulated excess becomes a different submitted V when that layer subsequently enters view. No saved original-Windows same-state UV/pixel packet proves an observed pixel discrepancy or its magnitude in a recorded frame. A current Linux-only packet cannot establish Windows phase.

## Exact eligibility and order

* Windows `GameObjectManager::Draw` iterates objects, skips null/non-drawable, then requires `Alpha() > 0` **and** (`Camera2D::IsObjectInView(drawObj)` or `IsPlayer()`) before optional `ApplyChange` and `Draw` (`Game/src/GameObjects/GameObjectManager.cpp:302-330`). `Camera2D::IsObjectInView` first tests the object's origin against strict camera bounds, then tests its unrotated/rotated bounds with parallax offsets (`Game/src/Core/Camera2D.cpp:39-81`); debug level-edit mode forces in-view. An admitted `ParallaxLayer::Draw` adds prior-process-render delta × scaled authored speed × .001 to stored vertex V, then calls `Sprite::Draw` (`Game/src/GameObjects/ParallaxLayer.cpp:39-161`). Culling or nonpositive alpha means **no phase mutation**. Eligibility is independent of whether pixels ultimately survive clipping/occlusion.
* Linux `LevelScene::Draw` first skips collected/shadow/aim-line/diagnostic-filter cases, then builds a `render::Sprite`, sets opacity, and for every remaining authored Y-autoscroll layer mutates `object.autoScrollYPhase` and assigns `draw.uvShiftY`; **only afterward** calls `SpriteMayIntersectViewport(draw)` and may `continue` (`port/game/LevelScene.cpp:1380-1455`). That conservative rotated screen-quad AABB uses inclusive viewport edges (`port/render/ViewportCull.h:10-24`), not Windows' origin/bounds algorithm. There is no equivalent `alpha > 0` check before the Linux mutation. All currently enabled authored Y layers have positive alpha, so the alpha distinction is latent for these XML defaults, but may matter if runtime alpha reaches zero. Diagnostic filtering is port-only and should be disabled for a parity oracle. `previousRenderedModifiedDelta_` is scene-local; the independent clock correction in `PRIVATE_WATCHDOG_AUTOSCROLL_CROSS_SCENE_CLOCK_DESIGN_20261024T0332Z.md` should be composed with, not substituted for, this gate.

## Authored exposure and saved packets

XML inventory (`Game/XmlFiles/levels/*.xml`): the *only enabled* Y-autoscroll is waterfall-top IDs **6, 7, 10, 13, 14, 15, 16, 31** and waterfall-bottom IDs **10, 13, 14, 15, 16, 17, 18, 25, 26, 27, 28**. None of the Forest levels has enabled Y autoscroll, despite containing disabled autoscroll properties; Forest frame packets therefore are **not affected by this pre-cull phase mechanism**. All enabled layers have `cameraparallaxmultipliery=0`, `followcamy=false`, positive alpha, and positive speeds; their geographically separated extents make offscreen passes natural. This affects an individual waterfall layer only if Windows would reject it on at least one draw that Linux processes and it is later admitted to draw, or if the two different cull predicates disagree at an edge.

A concrete, source-derivable example: waterfall-top ID15 is centered at authored Y≈1318 with height≈2240, so its top≈2438. At a 1080-high camera centered Y=3400 its top is below camera bottom=2860; with zero Y parallax and alpha=.2, Windows rejects it and retains its initial V. Linux at the corresponding 720-high mapped camera also builds an entirely offscreen quad, **adds** one prior-delta step, then rejects it. At a later camera centered near Y=2000, the same layer intersects the view and its command phase can differ by that step. With preceding modified delta 1/60 and 720/1080 scale, one excess ID15 step is `11 × 2/3 × .001 = .007333333` cycles modulo one. This is a constructive conditional divergence, not evidence that a saved route actually visited those exact states.

The saved Linux bottom frame-826 packet (`port/build/private-bottom-fog-packet-20261024t0320z/packet.json`) has camera Y≈1445.684 and submitted Y-scroll waterfall commands including bottom ID25 at draw ordinal 24, `uvShiftY=.384000212`, destination `[31.40,-513.61,888.76,1777.52]`. Its submitted ID25 cannot itself demonstrate pre-cull mutation at frame 826; its phase history may include entry-clock divergence and/or offscreen draws, and the packet lacks a per-layer eligibility/draw history or Windows equivalent. At that same camera, the much lower authored bottom ID16/17/18/26/28 are offscreen candidates whose Linux phases can advance without a command; the packet records **submitted** commands, not culled sprite state. Top active-frame packets likewise do not establish an original phase, and none of the saved Forest packets is a Y-autoscroll counterexample. Do not infer pixel mismatch or assign a numeric cumulative offset from any of these packets.

## Minimal correction and CPU command oracle

For a narrow fix in `port/game/LevelScene.cpp`, do not mutate a Y-scroll phase until an authored sprite has passed the port's draw-admission checks. Construct its destination/rotation/opacity first; reject positive-alpha failure and viewport failure; then increment phase with the **process prior-render delta** from the separate clock fix, assign `draw.uvShiftY`, and submit. `SpriteMayIntersectViewport` does not depend on UV, so moving the increment after that predicate is behaviorally local for admitted commands. To emulate Windows more exactly, use an object-space eligibility predicate matching `Camera2D::IsObjectInView` (including its strict inequalities/parallax-offset/rotation rules) rather than presuming the port's conservative screen-quad AABB is identical. The minimal order repair prevents definite offscreen phase drift; it does not alone prove all border-case cull parity. No change to shader, texture, speed, or per-sprite phase ownership is warranted here.

A CPU command-capture test should create/load a top scene with ID15, hold camera Y=3400 for N completed 1/60 renders, then move to Y=2000 and capture ID15's **first admitted** command. Expected Windows-order phase is one eligible draw step ≈.007333333, not `(N+1)` steps; no command should exist on the offscreen frames. Repeat for bottom ID26 (or another separated bottom layer) with a camera path through its extent, including a zero-alpha and boundary-cull case, and assert only admitted draws advance stored phase. Log object ID, camera, alpha, original-style and port cull predicates, process prior delta, eligible-draw count, and submitted V; compare modulo one with float tolerance. A same-state original Windows command trace is needed to decide residual predicate/packet parity, and matched original pixels are needed before a visible-pixel claim.
