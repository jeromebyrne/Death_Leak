## Source equation and exact loss point

- Windows `Game/src/GameObjects/ParallaxLayer.cpp:37-83`: `repeatsX=1`; for camera-driven X, `xShift = camX * (horizontalFlip ? +mX : -mX)`; then original vertex U `[xShift+1, xShift, xShift, xShift+1]`. With Y scroll (`:114-155`), `yShift = -camY*mY` for camera drive or prior V plus `autoScrollYSpeed*.001*percentDelta` for auto-scroll; original vertex V `[yShift,yShift,yShift+1,yShift+1]`. If Y scroll is off, V resets to `[0,0,1,1]` (`:87-109`). `BasicLightTexture.fx:11-17,37-55` samples continuous U/V with WRAP, min-linear/mag-point/mip-linear, multiplying sampled RGB by `lightColor` and sampled alpha by `alpha`.
- Linux `port/game/LevelScene.cpp:1204-1249`: destination uses the existing follow-camera/world projection and `scale`; `uvShiftX = cameraX*mX*(flipX?-1:+1)`, `uvShiftY = autoScrollY?phase:-cameraY*mY`; camera-X ParallaxLayer suppresses ordinary `repeatX`. The X sign is intentionally opposite the original D3D vertex label because the SDL screen-leading convention differs. Do **not** negate this already SDL-facing shift again, move the destination, or alter follow-camera update timing. The renderer-facing Y/flip convention is already encoded in the sprite and should be checked against the current SDL-bound quad, not inferred from PNG row order.
- `port/linux/SDLRenderer.cpp:246-261` currently reduces each shift via `ForEachUVWrapSegment` in `UVWrap.h:15-26`: `p=s-floor(s)`, `cut=floor(p*texturePixels)` (clamped), followed by integer source rectangles. This destroys sub-cut motion. For the direct quad, `ParallaxUV.h:12-21` provides screen corners `TL=(px,py), TR=(px+sx,py), BR=(px+sx,py+sy), BL=(px,py+sy)`, where `p=shift-floor(shift)` and `sx/sy=flip?-1:+1`. Keep those **float** coordinates through `glTexCoord2f`; no `cut/pixels` or span scaling on the eligible direct path. The existing custom SDL-bound quad maps V=0 to screen top (`SDLRenderer.cpp:310-324,382-390`).

Require SDL driver `opengl`/a valid desktop context, successful `SDL_GL_BindTexture`, finite positive returned `texw/texh` within `1e-6f` of 1 on **both** axes, and NPOT repeat support for an NPOT logical size (desktop GL 2.0+ or verified equivalent). Draw with the sampled PNG alpha, RGB tint, and alpha factor `tint.a/255 * sprite.opacity` applied **once**; prior `SDL_SetTextureColorMod`/`AlphaMod` does not by itself prove immediate-mode GL modulation, and current ordinary SDL copies do not explicitly use `Sprite::opacity`. Verify the final alpha contract against source and a controlled GPU draw, especially forest authored `.95`, rather than double-applying either modifier. Keep source-over blending.
5. Treat the GL interop as a state transaction: snapshot current active texture unit, unit-0 2D binding, current program, matrix mode/stacks, relevant GL enable/blend/color state; after binding snapshot the SDL texture object's wrap S/T and min/mag parameters. Restore object parameters **before** `SDL_GL_UnbindTexture`, then restore prior unit-0 binding, program/matrices/attrib state and active unit on every success/failure exit. Existing `DrawPixelWobble` (`:335-405`) is a useful pattern, but its private `WobbleMipTexture` (`:586-683`) is neither an eligibility shortcut nor a shared cache for parallax.
