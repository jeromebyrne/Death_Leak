# Ordered particle-spray batch discriminator — rejected (2026-10-25)

## Candidate and source isolation

At HEAD `46a3a47`, seven unrelated tracked paths were dirty, including an unstaged raft-mip change in `port/linux/SDLRenderer.cpp`. No competing game, apitrace, compiler or FFmpeg process occupied physical Xorg `:0` at preflight. This experiment used only an ignored clean-HEAD source copy in `port/build/particle-batch-20261025/src`; no production source or artwork changed.

`ParticleSpray::Draw` is a distinct scene/effect painter-order run: one emitter draws consecutive visible particles using one dedicated texture, with per-particle brightness/alpha, horizontal flip, and varying destination sizes. A test-only `DEATHLEAK_BATCH_PARTICLES=on` collected each emitter's original-order sprites and submitted compatible same-texture/same-sampling-class ordinary copies as one `SDL_RenderGeometry` call, with per-vertex color. Unsupported states or mixed min/mag sampling fell back to original `DrawSprite` calls. The initial magnification-only gate was too narrow: physical active Forest samples had 15-particle runs drawn at 39.619→9.905 logical pixels from a 64×64 texture and 3-particle runs from a 256×256 texture; it submitted no batch and changed neither GL call count. The second isolated prototype allowed all-linear minified runs, without crossing sampler-class boundaries. This is an experiment, not shipping code.

## Physical A/B/A

Serial runs used physical Xorg `:0`, SDL x11/OpenGL accelerated=1/software=0/vsync=1, nouveau NVE7, 1280×720, Forest-1 `--frames 180 --fixed-dt 0.0166666667 --script B:180`, with the same binary and the opt-in environment switch off/on/off. All arms ended at `(1368.99,3107.3)`, 5 orbs, 25 health, 11 shots fired. Ignored logs/traces/BMPs are under `port/build/particle-batch-20261025/`.

- Apitrace A/B/A: real `glDrawArrays` **7,780 / 7,780 / 7,780**; `glBindTexture` **27,080 / 23,139 / 27,080**. Thus the geometry path removed 3,941 bind calls over 180 frames but **zero GL draw submissions**. SDL already coalesces these same-texture sprite copies into the same number of driver draws; the opt-in geometry does not advance the draw-call goal.
- Untraced 60 sampled frames after 120 warmup: p50 **21.5589 / 21.4681 / 21.4860 ms**, p95 **21.8590 / 21.8376 / 21.8404 ms**, p99 **21.9351 / 21.9015 / 22.1606 ms**. These overlap; no frame-latency gain is demonstrated. The opt-in diagnostic printed its first 30 batch attempts before the sampled window, which limits any fine-grained timing inference.
- The serial traced frame-179 full BMP hashes matched across all three arms (`c1a87411...7dfce`). Additional active frame-29/59/89 serial A/B/A captures showed the candidate matching at least one control at each ordinal, while another control differed due to the known uptime-driven full-screen film. These are useful negative-discriminator pixels, **not** an exact synchronized full post-HUD parity gate across all controls. A production acceptance would require a deterministic film-clock capture or synchronized pre-HUD pixel gate.

## Disposition and next distinct step

**Reject for production.** Despite fewer binds, the measured effect run already coalesces to the same real GL draw count, and latency overlaps controls. A broader implementation would add per-emitter vector allocation and geometry/sampler state complexity without evidence of net performance benefit. No prototype source or assets are staged, committed, or shipped.

Still unatlased/unbatched: ordinary rock4/rock5 and tree2_blur mappings rejected on pixel precision or unchanged GL calls; scene tree/blur/raft/cart/shaft runs remain dedicated; repeating/UV-shift ground, fog/water, pixel-wobble/foliage/private shaders, render targets and source-rect/filter-sensitive sprites need separate classification and exactness proofs. Existing opt-in icon and HUD atlas families remain limited and are not broad 4K coverage. The next useful scene/effect candidate should be a measured **alternating texture/state** painter interval with actual GL draw boundaries (for example Waterfall-top's 3000–1001 interval), not another same-texture particle run or page-only atlas. Trace its exact ordered commands, choose only a parity-safe coalescing boundary, then perform synchronized exact pixels and serial physical A/B/A submissions plus latency. No 60-FPS, 8K/high-Hz, VRAM/thermal or release acceptance is inferred here.
