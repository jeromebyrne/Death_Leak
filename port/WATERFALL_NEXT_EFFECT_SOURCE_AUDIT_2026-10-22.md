# Waterfall-top next effect: weather-driven foliage-sway phase (2026-10-22)

**Finding (source audit only):** The port draws authored foliage sway, but hard-codes its global weather multiplier to **2.5**. Windows supplies a live `WeatherManager` value: **1.0 on a fresh manager before the first rain**, **2.625 during rain**, then **2.5 after rain stops**. This is a time/phase mismatch, not an amplitude or texture omission. It is the strongest distinct, source-backed unported waterfall-top effect found beyond the already-owned IDs 13/14 flow, IDs 49–51 spray, and orb hover: twelve authored sway sprites span ropes, foreground tree canopies, and shadows. Visual magnitude has not been measured against matched Windows frames.

## Evidence and boundary

- `Game/XmlFiles/levels/waterfall_top.xml:2-7` enables weather. IDs **36–39** are `effectfoliagesway` rope ends with nonzero bottom-corner X intensities 10/5 and per-object time multiplier 6 (`:667-726`); IDs **60–65** are tree tops with bottom X intensity 20, and IDs **66–67** leaf shadows with nonzero top X/Y intensities (`:1058-1177`). These are not sheet-scroll or splash objects.
- `Game/ShaderFiles/FoliageSway.fx:9-10,43-50` places `GlobalTimeMultiplier` *inside* both sine phases as `Time * TimeMultiplier * GlobalTimeMultiplier`; changing it changes position at the same clock time, not the displacement envelope. `Game/src/Game.cpp:370-377` sets shader time and reads `WeatherManager::GetFoliageSwayMultiplier()` each draw setup. The manager constructor initializes 1.0 (`Game/src/GameObjects/WeatherManager.cpp:45-59`), `StartRaining` assigns 2.5×1.05 = 2.625 (`:27-28,234-236`), and `StopRaining` assigns 2.5 (`:270-272`). Its first rain is triggered only after elapsed weather time exceeds 180 s (`:9,372-380`); the comment there saying 20 s is stale. A manager carried across levels can already be in a later state, so 1.0 is specifically the fresh-manager case.
- Linux parses each sprite's four corner intensities and authored `time_multiplier` (`port/game/LevelScene.cpp:490-502`), passes `visualTime_` into the draw contract (`:1007-1009`), and evaluates foliage vertices with literal **2.5f** (`port/linux/SDLRenderer.cpp:384-420`). Its separate `WeatherLightning` and `WeatherRain` state updates in `port/linux/main.cpp:1064-1069` and weather painter items at `:1133-1153` do not feed the foliage path. Thus rain/flash rendering being present does not close this gap. The renderer comment saying rain is unported is stale; do not use it as evidence of a missing rain effect.

**Implementation boundary:** Expose the active weather multiplier through the existing renderer-neutral foliage draw contract (or a narrow renderer state setter) and supply it from the gameplay weather state. Model fresh 1.0, raining 2.625, post-rain 2.5 without resetting the foliage shader/scene clock on transitions; preserve the XML corner amplitudes, per-object time multipliers, texture UVs, alpha, flips, depth, and current rain/lightning painter order. Do not edit `LevelScene.cpp` concurrently with the orb-hover owner. The source uses process-total `Timing` time while the port uses `visualTime_`; that pre-existing clock-origin difference must be controlled or separately scoped in pixel comparisons, not hidden by this multiplier change.

**Focused discriminator, not run:** A CPU unit around the foliage phase function should hold world vertex, authored intensity, `Time`, and `TimeMultiplier` fixed (e.g. rope ID36, multiplier 6; tree ID60, multiplier 1) and independently calculate expected X/Y at global factors 1.0, 2.625, and 2.5. Assert the three phase outputs differ at a nondegenerate time while amplitudes/UVs stay unchanged. Exercise the weather state transition just before 180 s, at first rain, and after rain stop, including a fresh-load case. When the exclusive GPU lane is free, isolate ID36 and ID60 at identical camera and shader time with only the global factor changed; compare vertex-edge displacement, then a matched Windows frame with controlled weather state and clock. No build, test, game, GPU/display run, or parity claim was made here. Only this report was written; pre-existing workspace modifications were left untouched.
