# Running-frame material footstep spray — independent source QA (2026-10-22)

Scope: read-only review of the current uncommitted `LevelScene.cpp/.h`, `PlayerMotion.cpp`, and focused CPU test against `Game/src/GameObjects/Character.cpp`, `Material.cpp`, and shipped animation/material XML. No build, Docker, GPU, display, or source/test edit was performed. `git diff --check` on the three modified implementation files passed. This report is the only file written.

## Findings, in priority order

1. **Running re-entry can emit an extra frame-0 spray.** The source's `Character::DoAnimationEffectIfApplicable` checks `mLastRunFramePlayed != bodyPart->FrameNumber()` (Character.cpp:1121), and `mLastRunFramePlayed` is initialized to 99999 then updated only in the Running branch (Character.cpp:75, 1062). Switching from Running frame 0 to Still and immediately back to Running frame 0 therefore does **not** emit a second spray. The port treats any sequence entry as a fresh frame (`LevelScene.cpp:1028-1036,1048`) and emits again. The focused test validates first entry and repeat suppression within one sequence, but does not cover this re-entry. **Fix:** preserve the source's last-running-frame-number gate across non-Running sequences; add a frame-0 → Still → Running frame-0 discriminator, plus a distinct-frame re-entry case.

2. **Material water gating is broader than source and can suppress valid particle material.** Source `Material::Material` marks only the exact name `water` as `IsWater()` (`Material.cpp:8-10`). `Character.cpp:1136-1142` gates *audio* on `WasInWaterLastFrame()` but gates the *particle spray* only on `!material->IsWater()`. The port excludes both `water` and `shallow_water` during texture load and emission (`LevelScene.cpp:263,945`), although `materials.xml:62-65` gives `shallow_water` an active `large_splash.png` texture. Port `UpdatePlayerVisual` additionally requires `!inWater` (`LevelScene.cpp:1048`), which is not a source spray condition. The focused test explicitly expects the latter suppression (`footstep_material_spray_test.cpp:69-72`), so it locks in the divergence. **Fix:** use the source's material predicate (exact `water`) for spray eligibility; remove the blanket `inWater` particle gate, while retaining any separate audio behavior. Add a focused shallow-water material and submerged-on-dry-line source-contract case. Note: no `shallow_water` solid-line use was found in the current shipped levels, so that subcase is presently latent; the `inWater` gate is a live semantic difference wherever a dry solid line overlaps a water volume.

## Confirmed aligned within this review

- Running body XML marks frames 0 and 10 with `sfx_type="footstep"` (`player_anim_default.xml:188-189,277`); the port stores flags aligned with successfully loaded frames.
- The emitted count, player-depth value, facing-relative horizontal origin, collision-bottom +17 vertical origin, spread, size/speed/lifetime bounds, gravity, brightness, scale, and fades correspond to the source `CreateDirectedSpray` call (`Character.cpp:1148-1170`). `PlayerMotion` reports the winning floor segment and invalidates contact for box/airborne support.
- The focused test has not been executed in this QA. Its use of direct `SetPlayerFootstepContact` is useful for emission parameters but cannot itself establish end-to-end material selection or draw parity. No visual parity conclusion is made.
