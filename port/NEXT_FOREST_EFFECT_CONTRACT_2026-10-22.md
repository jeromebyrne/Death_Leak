# Next forest/waterfall effect contract: tracking-orb particle trail (2026-10-22)

**Read-only finding at HEAD `bbc113b`.** The highest-impact *new implementation slice* found in this audit is the missing **attached, looping `orb_shatter.png` trail** when an authored small CurrencyOrb starts tracking the player. Both forest-1 and waterfall-top contain 22 `CurrencyOrb` XML elements (static count); this is a repeated, bright, player-proximate event, unlike a one-off background edge. Impact is ranked by recurrence and source behavior, **not** by a measured Windows/Linux pixel delta. This is separate from the already audited ninja explosion/debris and from orb hover/tracking motion; no parity claim follows.

## Source and current-port evidence

- The source assigns small orbs `flame_orb` material and `kOrb` depth in `Game/src/GameObjects/CurrencyOrb.cpp:38-73`; the material's sole particle texture is `Media\\orb_shatter.png` (`Game/XmlFiles/materials.xml:657-661`). Forest and waterfall each author small orbs (examples `Game/XmlFiles/levels/forest_exploration_1.xml:1098-1124`, `Game/XmlFiles/levels/waterfall_top.xml:1270-1293`).
- On strict squared distance `<130²`, `CurrencyOrb::Update` changes idle to tracking and calls `AddTrailParticles()` once (`Game/src/GameObjects/CurrencyOrb.cpp:149-178`). That routine creates a **15-particle radial spray** at the orb, at orb depth, with draw bounds 3200×1200, speed 1.5–3.4, lifetimes .1–.35 s, size 40–80, gravity .5, brightness .8–1, loop=true/loopTime=-1, life-scale target .1, fade-in .15, fade-out .8, and spawn spread 3×3; it attaches to the orb with orientation tracking (`:326-390`). `CreateRadialSpray` samples per-particle values and registers the spray (`Game/src/Particles/ParticleEmitterManager.cpp:212-371`). Its negative loop time does **not** auto-stop (`Game/src/Particles/ParticleSpray.cpp:319-328`).
- On collection, source detaches that spray and changes it to non-looping, letting live particles expire (`Game/src/GameObjects/CurrencyOrb.cpp:75-130`; `Game/src/Particles/ParticleSpray.cpp:287-335`). This is **not** the large-orb collection burst in `CurrencyOrb.cpp:285-324`.
- Current port implements small-orb proximity tracking at `port/game/LevelScene.cpp:683-732` and collection at `:581-593`; `port/linux/main.cpp:690-694` calls both. Neither `port/game` nor `port/linux` has an orb-trail emitter or `orb_shatter.png` reference (targeted source search). The authored level-spray path is distinct, so the existing waterfall splash/forest leaf sprays do not supply this effect.

## Exact bounded implementation/test recommendation

Add **only the small authored-orb tracking trail**: on the existing false→true `orbTracking` transition, create one scene-owned 15-particle `orb_shatter.png` emitter at the orb's current XY and `kOrb` painter depth. Preserve the source parameters above, seeded deterministic sampling for tests without claiming Windows RNG identity, and the existing orb motion/animation/collection rules. Preserve the source attachment flag; recycled particles restart at the orb's current XY while already-live particles retain their trajectories (`Game/src/Particles/ParticleSpray.cpp:279-304,479-514`). On collection detach, stop respawning, render residual particles to natural expiry, and prevent duplicate emitters across subsequent tracking ticks or saved/reloaded collected orbs. Do not add the large-orb burst, ninja effects, unrelated authored sprays, SFX, or XML/art changes in this slice.

Focused CPU test: hold an orb outside 130, cross the strict threshold, assert exactly one emitter/15 particles and correct asset/depth/parameters; keep tracking for >.35 s to show continuing loop and attachment to moved orb; collect once, assert no respawns, residual decay and expiry, then saved reload produces no trail. Check `130` equality and repeat tracking ticks for no false trigger. When the exclusive GPU lane is available, an isolated same-camera tracking-orb crop can establish visible coverage; Windows comparison additionally needs matched camera/orb/player state, RNG, and effect time.

**Scope:** original C++/XML, current port, and prior reports inspected. No source/test/build/game/GPU/display work; only this new report was written. Existing worktree changes were preserved.
