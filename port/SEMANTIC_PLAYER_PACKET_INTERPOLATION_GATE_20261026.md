## Semantic ownership discriminator

The relevant draw is not one contiguous transformable packet:

- `LevelScene::Draw` visits authored sprites in painter order and interleaves dynamic items and level-authored sprays by depth/order. Shadow is an authored `playerShadow` object at ground depth and disappears when `!playerGrounded_`. Aim is an authored `playerAimLine` at player depth and disappears at zero `aimLineAlpha_`; its position, rotation, alpha and flip have independent aim state. Body and optional arm are two draws at the body ordinal; arm is conditional on sequence/frame. The child X prompt is emitted after the body and four independent footstep/jump/landing/sword-pull spray vectors, before the next same-depth object. This order is not preserved by grouping the actor into a single late overlay or shifting a contiguous command range.
- Each attached spray has zero-or-more live particles and its own world coordinates, alpha/lifetime/size. The vectors are created, updated, erased and culled at different steps. A previous/current command-index pairing can therefore match a new particle with an unrelated old particle or jump across a birth/death. Shadow/aim/prompt/arm also change command cardinality at normal gameplay transitions. A semantic tag on a draw *family* is insufficient; stable per-object/per-particle identities and a birth/death policy are needed.
- Body, shadow, aim, prompt and sprays project through `worldX/worldY` and `drawCameraX/drawCameraY`, but other scenery uses depth-specific layer multipliers and parallax UV/camera-follow state. Camera shake is prepared once per update. Moving only the actor against current-camera scenery creates an inconsistent previous/current camera sample; shifting the entire sealed command packet by a common screen delta breaks parallax, shader UVs, painter coverage and HUD/postprocess. Camera ownership must be represented before interpolation, with separate scene projection and actor transforms at the same presentation alpha.
- `PresentationRecordingRenderer::BeginFrame` clears the sole packet; `EndFrame` seals it. The prior packet is not retained, commands have no object/scene epoch or semantic identity, and `Replay()` accepts no alpha. Ordinary active draws currently present current state; repeats use that same current packet. A repeat-only previous→current lerp would jump backward after each ordinary present. A correct one-step-latency design must render **both ordinary and refresh-only** presents from the same previous/current snapshot at a bounded alpha, reset history at level loads, teleports, pause and camera discontinuities, and keep simulation/shader/audio state on fixed 60-Hz updates only.

These are concrete, independent topology/clock blockers. Adding a no-op tag API would not produce a safe visible vertical slice; rendering a body-only B would be a knowingly detached visual regression. No speculative runtime code was committed.
